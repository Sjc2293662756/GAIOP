# 告警数据包侧重分析 — 设计方案与实施记录（v2）

> 日期：2026-07-05 | 状态：Phase 1-2 已实施部署

---

## 1. 问题

当前数据包分析是**通用协议分布**，与告警的触发指标没有关联。

```
告警: UEII=4971ms > 2000 阈值 → 紧急
分析: "SSH 30%、TLS 27%、TCP 重传 54 次、HTTP 400..."  ← 跟 UEII 无关
```

---

## 2. 核心思路

**告警的触发指标信息是动态的，随告警变化。不应该建静态映射表。而是把告警的原始触发数据（指标名、实际值、阈值条件）完整透传到 packet-analysis 和 AI，由它们动态解读。**

```
告警自己的数据（动态）          透传          解读方
─────────────────────    ──────────────    ──────
metrics: ["UEII"]         → packetQuery    AI 按指标名推理分析重点
value: [4971.3701]        → packetQuery    AI 展示实际值 vs 阈值
condition: "如果 UEII     → packetQuery    AI 判断告警严重程度
  > 2000 则紧急..."                        
unit: ["毫秒"]            → packetQuery    AI 使用正确单位
```

---

## 3. 改动点（3 处）

### 3.1 suggestedPacketQuery.analysis — 透传告警原始数据

在 `AlertIndirectPacketDiscoveryService.discover()` 中，为每个 candidate 的 `suggestedPacketQuery` 新增 `analysis` 字段：

```json
{
  "mode": "preview_download_analyze",
  "criteria": { "ips": [...], "start": ..., "end": ... },
  "analysis": {
    "metrics": ["UEII"],
    "metricLabels": ["用户体验时间（服务器）"],
    "values": [4971.3701],
    "units": ["毫秒"],
    "condition": "如果 UEII > 2000.0 则为紧急；如果 > 1500.0 则为重大；如果 > 1200.0 则为轻微",
    "severity": "紧急",
    "severityCode": 4
  }
}
```

**数据来源：** 告警 event 的 `metrics`、`value`、`unit`、`condition`、`severity` 字段。`metricLabels` 从 `metrics-config.yml` 中按 code 查找中文名。

**代码位置：** `AlertIndirectPacketDiscoveryService.js` 的 `discover()` 函数，生成 candidates 时从 event 或 triggerInfo 取。

### 3.2 packetInstruction 消息 — 动态嵌入触发指标

在 `AlertNarrationContractService.buildPacketInstruction()` 中，USE_CANDIDATES 的消息动态拼接：

```
间接发现到 N 个嫌疑 IP 会话。
⚠️ 告警触发指标: UEII（用户体验时间服务器）= 4971.37 毫秒
触发条件: > 2000 紧急 | > 1500 重大 | > 1200 轻微
当前级别: 紧急（实际值 4971.37 > 2000）
数据包分析报告必须围绕 UEII 展开：解释为什么 UEII 达到 4971.37ms，
结合数据包中的 TCP 重传、服务器响应延迟、连接建立时间等证据，
找出导致指标异常的具体 IP 会话。
禁止输出与 UEII 无关的通用协议分布。
```

**若 `metrics` 为空（测试告警）：**
```
该告警无触发指标（metrics 为空），无法进行指标聚焦分析。
数据包分析按通用模式进行。
```

### 3.3 Plugin 输出 — 触发条件嵌入 AI 可见文本

在 `buildAlertQueryReply()` 的 USE_CANDIDATES 短输出中，动态显示触发条件：

```
═══════════════════════════════════════
⚠️ 数据包发现完成 — 请执行以下操作：

告警触发: UEII = 4971.37 毫秒 (>2000 紧急)
发现 5 个嫌疑 IP 会话，必须逐条调用 napm-packet-analysis：
  1. 101.254.114.237|45.79.207.111
     → mode=preview_download_analyze ips=... start=... end=...

⚠️ 报告必须围绕 UEII 展开，解释异常原因
═══════════════════════════════════════
```

## 4. 数据流（完整链接）

```
alertsDetail API
  │
  │ 返回: { metrics:["UEII"], value:[4971.3701], unit:["毫秒"],
  │         condition:"如果 UEII > 2000...", severity:4 }
  │
  ▼
AlertNormalizerService.normalizeEvent()
  │
  │ event.metrics = ["UEII"]
  │ event.value   = [4971.3701]
  │ event.unit    = ["毫秒"]
  │ event.condition = "如果 UEII > 2000..."
  │ event.severity = 4
  │
  ▼
AlertNarrationContractService.buildEventPacketHandoff()
  │
  │ discoveryEvent = { ..., metrics, value, unit, condition, severity }
  │
  ▼
AlertIndirectPacketDiscoveryService.discover()
  │
  │ buildDiscoveryParams(event) → topValues 查询
  │ parseTopValuesResult() → IP 列表
  │
  │ 生成 candidates:
  │   candidate.suggestedPacketQuery.analysis = {
  │     metrics: event.metrics,      ← 原始数据透传
  │     values: event.value,
  │     units: event.unit,
  │     condition: event.condition,
  │     severity: event.severityLabel
  │   }
  │
  ▼
AlertNarrationContractService.buildPacketInstruction()
  │
  │ USE_CANDIDATES.message =
  │   `...告警触发指标: ${metrics} = ${values} ${units}...`
  │   `...报告必须围绕 ${metrics} 展开...`
  │   `...解释为什么 ${metrics} 达到 ${values}...`
  │
  ▼
napm-openclaw-plugin.remote.js / buildAlertQueryReply()
  │
  │ 短文本: "告警触发: UEII = 4971.37ms (>2000 紧急)"
  │ metadata.candidates: [{ suggestedPacketQuery: { analysis: {...} } }]
  │
  ▼
AI + napm-packet-analysis
  │
  │ packetQuery = candidate.suggestedPacketQuery（含 analysis 字段）
  │ → tshark 分析
  │ → AI 读取 analysis.metrics/values/condition
  │ → AI 围绕触发指标生成报告
```

## 5. 涉及改动

| 文件 | 改动 | 大小 |

| `AlertIndirectPacketDiscoveryService.js` | `discover()` 中，candidate.suggestedPacketQuery 新增 `analysis` 字段 | 小 |

**不需要改：**

- `run_packet_analysis.js` — 不需要改 tshark 参数（AI 负责解读）
- `SKILL.md` / `agents/openai.yaml` — 已有触发条件规则

## 6. 对比（改前 vs 改后）

```
改前: suggestedPacketQuery = { mode, criteria: { ips, start, end } }
改后: suggestedPacketQuery = { mode, criteria: { ips, start, end },
                                 analysis: { metrics, values, units, condition, severity } }

改前: packetInstruction = "间接发现到 5 个嫌疑 IP 会话。逐条分析..."
改后: packetInstruction = "告警 UEII=4971ms >2000 紧急。间接发现 5 个 IP 会话。
        报告必须围绕 UEII 展开，解释为什么达到 4971ms..."

改前: Plugin 输出 = "发现 5 个嫌疑 IP 会话: 1. x.x.x.x|y.y.y.y ..."
改后: Plugin 输出 = "告警触发: UEII = 4971ms (>2000 紧急)
        发现 5 个嫌疑 IP 会话: 1. x.x.x.x|y.y.y.y ..."
```

**本质差异：** 告警的 `metrics/value/condition/severity` 从不参与分析，变为贯穿全链路的上下文。

### 7.3 指标中文名查找

从 `config/metrics-config.yml` 正则解析，建立 `code → description` 缓存：

```
UEII → "用户体验时间（服务器）"
TPIO → "用户体验时间（服务器）"
PGHTTP500 → "HTTP 500数量"
...
```

不需要 `js-yaml` 依赖，用 `/- code: (\S+)\n\s+description: (.+)/g` 正则即可。

### 7.4 packetInstruction 消息格式

**有指标：**
```
间接发现到 N 个嫌疑 IP 会话。必须逐条展示候选列表...
⚠️ 告警触发指标: UEII = 4971.3701毫秒。
 触发条件: 如果 UEII > 2000.0 则为紧急...
 级别: 紧急。
数据包分析报告必须围绕 UEII 展开：
1. 解释为什么 UEII 达到 4971.3701毫秒
2. 结合数据包中的重传、延迟、连接失败等证据
3. 找出导致指标异常的具体 IP 会话和时间点
4. 将数据包时间线与告警触发时刻关联
```

**无指标：**
```
...该告警无触发指标，但仍必须对发现的 IP 会话进行完整数据包分析（协议分布、会话通信、TCP 异常等）。
```
