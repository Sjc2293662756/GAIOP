# 2026-04-29 PKIO指标映射补充说明

## 本次补充内容

将以下问法稳定映射到指标：

- `数据包数量`
- `数据包个数`
- `包数量`
- `包流量`
- `packet count`
- `packet traffic`
- `pps`

统一收敛为：

- `PKIO`

## 本次修改位置

1. `skills/openclaw-napm-query/scripts/run_napm_query.js`
2. `skills/openclaw-napm-query/services/MetricMappingService.js`
3. `skills/openclaw-napm-query/scripts/reference-runtime.js`

## 作用

### 1. 本地语义识别

当用户直接问：

- `数据包数量最多的前5个应用分别是谁`

skill 不再误落到：

- `PGTME`
- `TPIO`

而是直接构造：

- `topValues`
- `metric=PKIO`
- `topMetric=PKIO`

### 2. 指标合法性补齐

即使当前 `metrics-config.yml` 未显式注册 `PKIO`，运行时也会补充注册该指标，避免因为“别名识别到了，但指标不合法”而再次回退。

### 3. 参考语义增强

参考运行时中，`数据包` / `包流量` / `PKIO` 也会被归入流量域，减少被错误归入时延域的概率。

## 本地验证结果

问句：

`数据包数量最多的前5个应用分别是谁`

本地实际构造结果：

- `metrics=PKIO`
- `topMetric=PKIO`

返回结果中也已确认上游指标为：

- `PKIO`

## 当前结论

现在这类“数据包数量 / 包流量 / 包个数”问法，skill 已经能稳定按 `PKIO` 去查。
