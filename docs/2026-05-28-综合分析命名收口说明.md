# 综合分析命名收口说明

日期：2026-05-28

## 1. 背景

功能一实际语义是“综合分析 / 聚焦分析 / 先发现再分析”，不是普通“概览分析”。

历史代码中使用 `service=overview`、`overviewScene`、`overview_with_discovery`，容易让 OpenClaw 把复杂分析理解成“概览/总览”，从而在意图构造时漂移。

## 2. 命名原则

本次不重命名底层 `service=overview`，因为它已经是现有执行协议和 overview-module 的兼容入口。

新的分层命名如下：

| 层级 | 保留/新增 | 说明 |
|---|---|---|
| 执行 service | `service=overview` | 兼容执行名，不对用户表达 |
| 执行 scene | `overviewScene` | 兼容 overview-module |
| 语义类型 | `analysisType=comprehensive_analysis` | 用户语义是综合分析 |
| 语义模式 | `analysisMode=focused_analysis/discover_then_analyze/system_analysis` | 区分聚焦分析、先发现再分析、系统分析 |
| 语义场景 | `analysisScene` | 与 `overviewScene` 对齐，后续逐步替代 |
| 输出类型 | `comprehensive_analysis` / `comprehensive_analysis_with_discovery` | narration 面向 OpenClaw 的语义类型 |
| 旧输出兼容 | `legacyResponseType=overview_with_discovery` | 兼容旧判断 |

## 3. 构造示例

### 3.1 聚焦综合分析

```json
{
  "service": "overview",
  "queryModeKey": "overview",
  "analysisType": "comprehensive_analysis",
  "analysisMode": "focused_analysis",
  "analysisScene": "business",
  "overviewScene": "business",
  "groups": [
    { "type": "WebApplication", "argument": "可观测239web" }
  ],
  "start": "<from napm-resolve-time-range>",
  "end": "<from napm-resolve-time-range>"
}
```

### 3.2 先发现再分析

```json
{
  "service": "overview",
  "queryModeKey": "overview",
  "analysisType": "comprehensive_analysis",
  "analysisMode": "discover_then_analyze",
  "analysisScene": "network",
  "overviewScene": "network",
  "analysisPipeline": {
    "targetObjectType": "IPAddress",
    "selection": {
      "rank": 1
    },
    "discoveryQuery": {
      "service": "topValues",
      "queryModeKey": "topn",
      "groups": [
        { "type": "IPAddress" }
      ],
      "metrics": ["RFCI"],
      "topMetric": "RFCI",
      "topCount": 1
    }
  },
  "start": "<from napm-resolve-time-range>",
  "end": "<from napm-resolve-time-range>"
}
```

## 4. 本次代码改动

修改文件：

- `skills/openclaw-napm-query/scripts/run_napm_query.js`
- `skills/openclaw-napm-query/services/OpenClawNarrationContractService.js`
- `skills/openclaw-napm-query/SKILL.md`
- `config/napm-resolution-spec.v1.json`
- `napm-openclaw-plugin.remote.js`

关键变化：

- focused query 自动补 `analysisType/analysisMode/analysisScene`。
- discover-then-analyze 成功结果输出 `responseType=comprehensive_analysis_with_discovery`。
- 旧 `overview_with_discovery` 保留在 `legacyResponseType`。
- narration 文案从“概览结果”改成“综合分析结果”。
- OpenClaw prompt 明确：`service=overview` 是兼容执行名，不要把用户语义称为“概览分析”。

## 5. 后续建议

后续可以逐步把内部文件名如 `overview-module.js`、`OverviewPlanner` 改成 `ComprehensiveAnalysisModule` 一类命名。

但这一步风险较高，会影响大量 require 和测试文件，建议等 P0 功能稳定后再做物理重命名。
