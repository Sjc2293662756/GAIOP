# 业务页面 URL 数据包预览路由偏移修复复盘

## 背景

用户在企业微信中先查询：

```text
在其他web应用中，有哪些页面出现400错误？
```

系统返回了页面族：

```text
http://101.254.114.238/SDK/webLanguage
pageFamilyId=8574581
```

随后用户继续问：

```text
http://101.254.114.238/SDK/webLanguage 分析这个的数据包预览
```

正确语义应是：对这个业务页面族做数据包预览，先调用 `pageViews` 获取可选页面访问明细，让用户选择对端 IP 或访问行，再基于 `pageFamilyDetailId` 构造 `DownServlet` 下载链接。

## 错误现象

OpenClaw 把页面 URL 中的 `101.254.114.238` 提取成普通 IP，转而调用普通 IP 数据包预览链路。

错误链路：

```text
用户页面 URL 请求
  -> OpenClaw 抽取 URL 中的 IP
  -> napm-packet-analysis
  -> packetsPreview(ips=101.254.114.238)
  -> 返回 100 个 IP 会话、约 30MB 流量
```

这条链路查的是 IP 维度的数据包预览，不是页面族 `http://101.254.114.238/SDK/webLanguage` 的业务访问明细，因此语义错误。

## 正确链路

正确链路应为：

```text
用户页面 URL 请求
  -> napm-packet-analysis
  -> downloadType=DownServlet
  -> mode=preview_only
  -> criteria.page/pageUrl=http://101.254.114.238/SDK/webLanguage
  -> 若已有上下文，带上 pageFamilyId=8574581
  -> NetInside pageViews(json=true, pageFamilyId=8574581)
  -> 返回 pageViewsPreview.rows
  -> 用户选择 clientIp 或 pageViewIndex
  -> DownServlet(instanceId=PATH1/{pageFamilyDetailId})
```

关键接口：

```text
https://101.254.114.238/webservice/NetInside?type=pageViews&start=1781488800&end=1781492400&json=true&pageFamilyId=8574581&maxLimit=undefined
```

## 根因

### 1. OpenClaw 入口契约不够硬

`napm-packet-analysis` tool 的 schema 原来强调 `ips/ipRanges/id/top/instanceId`，没有把以下业务页面字段显式暴露为一等输入：

```text
businessName
page
pageUrl
pageFamilyId
pageFamilyDetailId
clientIp
pageViewIndex
```

模型看到 URL 中有 IP，就容易把页面 URL 误拆为普通 IP 查询。

### 2. 系统提示没有区分两类“预览”

数据包链路存在两类预览：

| 类型 | 接口 | 含义 |
|---|---|---|
| 普通包预览 | `packetsPreview` | 按 IP/IP 段/事件 ID 查看是否有可下载包，以及包大小/包数量 |
| 业务页面预览 | `pageViews` | 按页面族列出页面访问实例，供用户选择对端 IP 或页面访问行 |

“页面 URL + 数据包预览”必须走第二类，不应降级到普通 `packetsPreview`。

### 3. 插件注入的 TLS 环境变量与脚本实际读取不一致

插件原来注入：

```text
NETINSIDE_TLS_INSECURE=true
```

但 packet 脚本实际读取的是：

```text
NETINSIDE_TLS_REJECT_UNAUTHORIZED=false
```

导致即使构造了正确的 `pageViews` 链路，也可能因为自签证书失败。

## 本次修改

### 1. 插件入口增加业务页面预览归一化保护

文件：

```text
napm-openclaw-plugin.remote.js
.codex-temp/napm-openclaw-plugin.remote.js
```

新增逻辑：

```text
normalizePacketBusinessPagePayload()
looksLikeBusinessPagePacketPreviewPrompt()
extractFirstHttpPageUrl()
```

规则：

- 如果 payload 中已有 `page/pageUrl/pageFamilyId/pageFamilyDetailId/businessName`，强制使用 `downloadType=DownServlet`。
- 如果 prompt 是“页面 URL + 数据包预览/分析”，提取完整页面 URL 放入 `criteria.page/pageUrl`。
- 如果是预览语义，强制 `mode=preview_only` 并设置 `criteria.businessPageViewsPreviewOnly=true`。
- 普通 IP-only 请求保持 `packetsDown/packetsPreview` 链路，不受影响。

### 2. 插件 tool schema 暴露业务页面字段

`napm-packet-analysis` 的 `criteria` schema 新增：

```text
businessName
page
pageUrl
pageFamilyId
pageFamilyDetailId
clientIp
serverIp
pageViewIndex
```

并在 tool description 中明确：

```text
如果用户提供 Web 页面 URL/path 并要求数据包预览/分析，
必须使用 DownServlet 业务页面预览，
不要把 URL 中的 IP 转成普通 IP packetsPreview。
```

### 3. 系统上下文增加业务页面预览契约

新增约束：

```text
Business page packet preview contract:
Web page URL/path + 数据包预览/分析
  -> napm-packet-analysis
  -> downloadType="DownServlet"
  -> mode="preview_only"
  -> criteria.page/pageUrl
  -> pageViews candidate rows
```

同时明确：

```text
Never downgrade a business page packet preview to IP-based packetsPreview merely because the URL contains an IP address.
```

### 4. packet skill 增加优先路由说明

文件：

```text
skills/openclaw-napm-packet-analysis/SKILL.md
```

新增 Priority routing rules，明确：

- 业务页面 URL 的数据包预览是 `DownServlet/pageViews` 链路。
- 不应抽取 URL 中 IP 走普通 `packetsPreview`。
- `pageViews` 返回的是可选择的页面访问明细，不是 pcap 大小预估。

### 5. 修正 TLS 注入变量

插件调用 packet skill 时同时注入：

```text
NETINSIDE_TLS_REJECT_UNAUTHORIZED=false
```

避免 `pageViews` 请求被自签证书阻断。

## 后续注意事项

- 如果没有上一轮 `pageFamilyId` 上下文，packet skill 会尝试通过 `businessName + page` 先查页面族 Top，再进入 `pageViews`。
- 如果用户明确说“按 IP 预览 101.254.114.238 的数据包”，才允许使用普通 `packetsPreview`。
- 如果用户选择某个 `clientIp` 或 `pageViewIndex`，下一轮应调用同一 skill，传入该选择，继续构造 `DownServlet` 链接或下载分析。
