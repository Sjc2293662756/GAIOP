# 企微入口规划回退与空结果话术修复说明

## 1. 问题现象

真实问句：

- `访问其他web应用次数最多的客户端是谁？`

现网原始表现存在两类问题：

1. 企微入口未稳定命中可执行查询，容易回复“还需要补充一点信息”。
2. 即使查询已经真正执行，空结果场景的话术仍然偏机械，只会返回“本次未查到数据”。

这两个问题都发生在 OpenClaw 企微入口侧，而不是本地网关执行器侧。

---

## 2. 根因定位

本次排查确认了三件事：

1. 本地网关职责没有变化，仍然只负责执行 `resolvedQuerySeed`。
2. 企微真实入口使用的是远端 `wecom-openclaw-plugin` 的独立规划链路，不完全依赖仓库内 `skills/openclaw-napm-query/agents/openai.yaml`。
3. 企微插件的规划回退启发式存在两个缺口：
   - 未稳定覆盖“访问其他web应用次数最多的客户端”这一类问法。
   - 空结果时仍走固定机械文案。

---

## 3. 本次修复内容

### 3.1 修复企微规划回退规则

远端企微插件补齐了以下识别能力：

- `访问量 / 访问次数 / 页面访问`
- `客户端 / 客户端IP`
- `其他web应用 / 其它web应用 / 未注册web应用 / Other Web Application`

命中后优先收敛为：

- `service=topValues`
- `metric=PGNPGE`
- `topMetric=PGNPGE`
- `topCount=1`
- `groups=[{type:"WebApplication",argument:"Other Web Application"},{type:"ClientIPs"}]`

同时保留最近 24 小时时间范围兜底，避免上游因为缺少 `start/end` 报错。

### 3.2 修复空结果话术

企微入口空结果文案从简单的：

- `本次未查到数据。`

调整为更明确的完成态表达，保留指标与对象范围，避免用户误以为系统没有执行查询。

## 5. 验证结论

针对问句：

- `访问其他web应用次数最多的客户端是谁？`

已确认企微入口规划回退可以生成正确 seed，至少不会再停留在“还需要补充一点信息”的旧路径。

同时，直接按该 seed 调用网关时，链路已经可以正常执行到 NAPM 查询层；若结果为空，也会按新的完成态口径返回，而不是把“未查到数据”误表现成“没理解到问题”。

---

## 6. 补充说明

本次修复依然遵守当前项目边界：

- OpenClaw / 企微入口负责理解、规划、回退兜底、结果表达。
- 本地网关只负责按结构化 seed 执行查询。

因此这次没有把该问法继续做成网关本地的“主判定规则”，而是修在真正应该承担理解职责的上游入口侧。
