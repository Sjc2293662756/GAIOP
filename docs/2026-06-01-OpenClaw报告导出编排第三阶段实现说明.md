# OpenClaw 报告导出编排第三阶段实现说明

日期：2026-06-01

## 背景

第一阶段已经实现 `openclaw-napm-report`，可以将结构化 `reportData` 生成 `.docx`。

第二阶段已经让 `openclaw-napm-query` 在真实查询结果中输出 `reportData`。

第三阶段需要在 plugin/OpenClaw 编排层增加报告导出入口，让用户明确说“生成报告”“导出 Word”“将以上以 Word 形式导出”时，可以调用报告生成 skill。

## 已实现内容

### 1. 新增生产工具

新增工具：

```text
napm-report-export
```

该工具与 `napm-skill-query` 一起作为生产 NAPM 工具注册。

生产默认工具现在是：

```text
napm-skill-query
napm-report-export
```

诊断工具 `napm-resolve-query` 和 `napm-mainflow-query` 仍然只在 `NAPM_ENABLE_DEV_RESOLVER_TOOLS=true` 时注册。

### 2. 新增报告执行器配置

新增环境变量：

```text
NAPM_REPORT_EXECUTOR
```

默认路径：

```text
/home/netinside/.openclaw/skills/openclaw-napm-report/scripts/generate_napm_report.js
```

报告下载基础路径：

```text
NAPM_REPORT_DOWNLOAD_BASE_URL
```

默认：

```text
/reports
```

### 3. 导出链路

`napm-report-export` 的执行顺序：

```text
接收 reportData 或导出追问
  -> 优先使用 args.reportData
  -> 如果没有 reportData，则读取最近一次 fresh NAPM skill 结果中的 reportData
  -> 校验导出格式
  -> 调用 openclaw-napm-report/scripts/generate_napm_report.js
  -> 返回报告路径和下载链接
```

### 4. 支持追问式导出

以下问法应走 `napm-report-export`：

```text
将以上以 Word 形式导出
把刚才结果导出成 Word
生成报告
导出 docx
```

如果用户在同一句话里提出新查询和报告请求，例如：

```text
生成最近一天丢包最严重 IP 的分析报告
```

正确编排是：

```text
napm-skill-query
  -> 返回 reportData
napm-report-export
  -> 使用 reportData 生成 docx
```

### 5. PDF 处理

当前 PDF 仍未启用。

如果用户要求：

```text
将以上以 PDF 形式导出
```

`napm-report-export` 会返回：

```text
REPORT_PDF_EXPORT_UNAVAILABLE
```

不会静默降级为 Word。

## 当前边界

已经支持：

- 工具级报告导出。
- 显式 `reportData` 导出。
- 最近一次查询结果追问导出。
- Word/docx 生成。
- PDF 明确拒绝。

尚未支持：

- PDF 实际生成。
- 自动把报告文件挂到 HTTP 静态下载服务。
- 用户自定义模板。
- 长期跨会话报告数据缓存。

## 验收方式

### 方式一：显式传 reportData

OpenClaw 调用：

```text
napm-report-export({
  "prompt": "将以上以 Word 形式导出",
  "format": "word",
  "reportData": { ... }
})
```

预期：

```text
ok=true
format=docx
filePath 存在
downloadUrl 存在
```

### 方式二：追问导出

第一轮：

```text
最近一天丢包最严重的前10个IP
```

OpenClaw 调用 `napm-skill-query`，结果中必须含 `reportData`。

第二轮：

```text
将以上以 Word 形式导出
```

OpenClaw 调用 `napm-report-export`，不重新查询 NAPM，直接使用最近一次 fresh `reportData`。

## 后续建议

下一阶段建议做两件事：

1. 部署远端，确认 OpenClaw 真实模型会按系统提示调用 `napm-report-export`。
2. 若真实模型仍不调用，需要增加更强的 prompt/hook 约束，但不要让 plugin 私自补查 NAPM。

报告导出必须保持这个边界：

```text
没有 reportData -> 不生成报告
有 reportData -> 只负责导出
PDF 不可用 -> 明确失败
```
