# 深入分析指令 — 指标附加设计

> 日期：2026-07-03

## 1. 问题

当前"深入分析"指令只包含事件 ID 和时间窗口：

```
分析这个告警数据包 700420 1783049940 1783050180
```

AI 拿到后只能知道"查哪个事件"，但不知道该分析**什么指标**，需要用户手动补充。

## 2. 方案

采用**方案 A — 末尾追加指标名**，格式固定、参数顺序固定：

```
分析这个告警数据包 <EventID> <start> <end> <指标1> [指标2 ...]
```

### 示例

单指标：
```
分析这个告警数据包 700420 1783049940 1783050180 用户体验时间（服务器）
```

多指标（Syslog 有时会有 metric1、metric2 等）：
```
分析这个告警数据包 700420 1783049940 1783050180 用户体验时间（服务器） 吞吐量（流入和流出）
```

## 3. 选择理由

| 对比项 | 方案 A（追加指标） | 方案 B（key=value） | 方案 C（自然语言） |
|---|---|---|---|
| 长度 | 中等 | 最长 | 最长 |
| AI 解析难度 | 低（按位置） | 低（按 key） | 中（NLP） |
| 多指标支持 | 空格分隔 | 重复 key | 需要组织语句 |
| 复制给 @机器人 | ✅ 简洁 | ⚠️ 冗长 | ⚠️ 易截断 |

方案 A 最均衡：信息完整且足够紧凑，AI 拿到 EventID + 时间 + 指标名就能拉 NAPM 时序数据做深入分析。

## 4. 实现位置

`WeComPushService.js` → `_buildMarkdownMessage()` → 代码块指令生成逻辑。

修改：将 `alert.metrics` 中的所有指标名追加到指令末尾，空格分隔。

## 5. 处理边缘情况

| 场景 | 行为 |
|---|---|
| 无指标 | 不追加，保持原有指令 |
| 单个指标 | 追加一个指标名 |
| 多个指标 | 空格分隔全部追加 |
| 指标名为空 | 跳过空指标名 |
