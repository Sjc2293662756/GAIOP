# openclaw-napm-query 问题 6：日志脱敏整改说明

日期：2026-07-30  
状态：本地整改和回归已完成。

## 问题与影响

原日志可能记录用户名、内部 URL、对象名称、完整请求参数、API 响应片段或错误响应体，扩大日志读取权限时会暴露认证标识和业务数据。

## 日志原则

- 普通日志采用允许列表，只记录服务名、状态码、耗时、参数名、数量和类型。
- 用户名、密码、token、内部地址、IP、对象参数和响应体不得原样记录。
- 审计 URL 必须通过统一脱敏函数构造。
- 错误消息和嵌套 metadata 在写入前递归清洗。

## 修改内容

- `NapmClient` 初始化日志只保留传输协议和 TLS 状态。
- 请求日志只记录 service 与非认证参数名；响应只记录状态和长度。
- 失败日志不再写入上游响应体。
- `MetricExecutionKernel` 移除响应前 200 字符样本，只记录类型和长度。
- `GroupBuilder` 只记录 group 类型，不记录 argument。
- `QueryValidator` 只记录安全查询摘要。
- `auditLogger` 扩展敏感键、URL、IP、用户名、对象名和响应体的递归脱敏。

## 回归验证

- `test/query-log-safety.test.js` 验证 URL、认证字段、对象参数、响应内容和错误消息不会泄漏。
- 静态扫描确认不存在响应体样本日志和原始用户名/base URL 初始化日志。
- 全量 Jest：73 个 suite、496 个测试全部通过。

## 验收结论

查询链普通日志和审计日志均改为最小必要信息，不再依赖调用方自行避免敏感字段。
