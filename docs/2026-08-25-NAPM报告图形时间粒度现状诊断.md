# NAPM 报告图形时间粒度现状诊断

日期：2026-08-25  
范围：`openclaw-napm-inspection`、`openclaw-napm-summary`、`openclaw-napm-report`、`echarts-chart-skill` 以及时间范围配置。  
阶段：诊断已完成；巡检阶段修复已实施并完成对应回归验证。未连接服务器，未制作部署包，未部署。

## 1. 结论

诊断时发现巡检的时间窗口和时间粒度都是固定的；本次修复将粒度改为按窗口时长和点数预算动态选择：

| 巡检窗口 | 修复前 | 当前选择结果（默认最多 120 点） |
|---|---:|---:|
| 最近 1 小时 | `60s` | `60s` |
| 最近 1 天 | `3600s` | `3600s` |

实现位于 `skills/openclaw-napm-inspection/services/InspectionTrafficAnalysisService.js` 的 `selectGranularity()` 和 `collect()`：

- `traffic-last-hour` 使用 `durationSeconds=3600`，按预算选择 `60s`。
- `traffic-last-day` 使用 `durationSeconds=86400`，按预算选择 `3600s`。

巡检业务窗口仍然是固定的最近 1 小时和最近 1 天，但查询粒度不再由 `collect()` 写死；`queryWindow()` 对任意正时长按预算从 `60/300/3600/86400s` 中向上选择。

本次已采用“固定业务窗口 + 动态粒度”：窗口仍保持最近 1 小时、最近 1 天，粒度由窗口时长和默认最多 120 个点的预算共同决定。

## 2. 当前报告链路

```text
napm-inspection / napm-summary
  -> timeValues 查询
  -> 时间序列标准化
  -> reportData
  -> chart-specs.v1.json
  -> openclaw-napm-report 内部 ECharts SSR
  -> PNG 嵌入 Word
```

报告服务实际在 `InspectionFixedTemplateService` 中直接 `require('echarts')` 并生成 PNG；当前未发现对独立 `echarts-chart-skill` CLI/core 的调用。`TOOLS.md` 和 `PROJECT.md` 中“由 report skill 内部调用 echarts-chart-skill”的描述与实现不一致。

## 3. 报告类型与粒度矩阵

| 报告类型/范围 | 当前粒度决定方式 | 当前结果 |
|---|---|---|
| 巡检 | 窗口固定，粒度按点数预算选择 | 最近 1 小时 `60s`，最近 1 天 `3600s` |
| 综述 global/network/webApplication/application/businessGroup | 按 `end-start` 自动选择 | `<=86400: 60s`；`86400< span <=604800: 3600s`；更长 `86400s` |
| 综述 alert | 不调用 `timeValues` | 告警时间桶由后端返回，报告侧没有明确粒度字段 |
| 故障分析 fault | 外层时间范围计算一次 | fault 与 baseline 共用同一粒度，即使两个窗口长度不同 |
| diagnostic 固定模板 | 图表规格为空 | 当前没有图形输出 |

综述的自动计算同时存在于 `SummaryService` 和 `SummaryClient`。两处规则一致，但都与配置推荐不完全一致。

配置推荐为：

- `last1hour -> 60`
- `last24hours/today/yesterday -> 3600`
- `last7days/last30days -> 86400`

实际服务按跨度计算，因此本地复现为：

```text
span=86400   -> 60
span=86401   -> 3600
span=604800  -> 3600
span=604801  -> 86400
```

这意味着 `last24hours` 实际为 `60s`，`last7days` 实际为 `3600s`，均与配置推荐不一致。

## 4. 已复现问题

### 4.1 请求粒度和响应/图形粒度不一致

巡检请求证据记录请求粒度，标准化优先使用 API 响应中的 `raw.granularity` 生成点时间、统计缺点和图表横轴；两者同时保存在数据契约中。

mock 结果：请求 `60s`、响应 `3600s` 时：

```text
queryEvidence.granularity = 60
queryEvidence.actualGranularity = 3600
图表点间距 = 3600 秒
dataset.stats.missingPointCount = 0
```

修复后同一份数据按响应的小时粒度绘制和统计，并通过 `granularityMismatch=true` 保留请求/响应不一致证据。

### 4.2 多指标长度不一致

Summary 标准化以第一指标数组长度生成横轴；Inspection 标准化以最长指标数组生成点。指标数组长度不一致时，可能出现横轴截断、指标缺点或后续渲染补零。

修复前巡检报告图表构造中的 `Number(value) || 0` 会把缺失值、`null` 或非法值静默绘制为 `0`；当前巡检图表保留 `null` 并关闭跨空值连接。

### 4.3 缺少起始时间

修复前当响应没有 `interval.start` 时，巡检标准化回退到 `0`，可生成：

```text
第一点时间："1"
后续时间：1970-01-01 08:01:00
```

### 4.4 时区处理分裂

时间序列标准化显式使用 `Asia/Shanghai`，但报告图表对 Unix 数值时间戳使用 Node 进程本地时区。相同时间戳在 `TZ=UTC` 和 `TZ=Asia/Shanghai` 下相差 8 小时。

当前标准图表大多使用已经格式化的 `time` 字符串；巡检图表对数值 Unix 时间戳已固定使用 `Asia/Shanghai`。

### 4.5 空数据处理不一致

- Summary 无数据时跳过 PNG，最终使用图表槽位占位表。
- 修复前 Inspection 无数据时仍构造并渲染空图，可能得到空白 PNG；当前无数据时跳过 PNG，沿用图表槽位占位表。

### 4.6 诊断报告图表缺口

`skills/openclaw-napm-report/templates/diagnostic/chart-specs.v1.json` 当前为 `"charts": []`。故障分析数据中虽然可能有 fault trend 和 baseline trend，但固定模板不会生成图表。

## 5. 根因判断

### 已证实

1. 粒度策略存在配置、Summary、Inspection 多个实现，缺少唯一真源。
2. 诊断时 `requestedGranularity` 与 `actualGranularity` 没有作为统一数据契约保存和校验；当前巡检数据已补齐这两个字段及 `granularityMismatch`。
3. 各标准化器对数组长度、缺失值和时间轴的处理不一致。
4. 图表层把缺失值静默转换为 `0`。
5. 缺少 `interval.start`、进程时区变化和空数据时会产生不同结果。

### 潜在风险

1. 告警时间线的 bucket 粒度由后端返回，报告侧没有可审计的粒度元数据。
2. fault 和 baseline 共用外层粒度，两个窗口长度差异较大时可能不合适。
3. 规范文档声称使用 `echarts-chart-skill`，实际报告服务使用了重复的本地 ECharts 实现。

## 6. 动态粒度实现

本次巡检阶段采用以下 resolver：

```text
窗口时长/语义 key
  -> 计算目标点数
  -> 从 60/300/3600/86400 中选择
  -> 保存 requestedGranularity 和 actualGranularity
  -> 图表、统计使用 actualGranularity，证据同时保留请求/实际粒度
```

当前巡检规则为：

- 最近 1 小时：`60s`。
- 最近 24 小时：`3600s`。
- 最近 7 天：`86400s`。
- 任意自定义范围：按最大点数预算选择支持的粒度，并向上取整。

默认点数预算为 120；请求粒度来自 resolver，响应若返回合法支持值则以响应值为实际粒度，否则回退到请求值。

## 7. 建议回归测试

- 精确覆盖 `86400`、`86401`、`604800`、`604801` 边界。
- 覆盖 `last24hours`、`today`、`yesterday`、`last7days`、`last30days`。
- 覆盖巡检、综述各 scope、fault/baseline 不同窗口长度。
- 覆盖请求粒度与响应粒度相同、不同、缺失、非法值。
- 覆盖 `interval.start/end` 缺失、非分钟对齐、跨小时/天边界。
- 覆盖多指标长度不一致及 `null/undefined/NaN/0`。
- 断言 `xData.length === 每条 series.data.length`，且缺失值不会变成 `0`。
- 在 `TZ=UTC` 与 `TZ=Asia/Shanghai` 下验证横轴显示一致。
- 统一验证 Summary 和 Inspection 的空数据占位行为。
- 若诊断报告需要图表，增加 chart spec、数据契约和 PNG 回归测试。
