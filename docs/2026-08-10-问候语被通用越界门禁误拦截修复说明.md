# 问候语被通用越界门禁误拦截修复说明

日期：2026-08-10
适用范围：OpenClaw 企业微信通道、NAPM OpenClaw 插件、观枢AI 平台身份与简短交互

## 1. 问题现象

用户执行 `/new` 后发送：

```text
你好？
```

OpenClaw 已正常创建新会话，但观枢AI没有返回问候或身份介绍，而是返回通用域外文案：

```text
我当前只处理系统监控、性能分析、NAPM 查询和结果解读相关问题。
像天气、闲聊、泛问答这类内容不在当前技能范围内。
如果你是想看系统情况，可以直接问我：239web最近异常吗、某系统今天比昨天差吗、这个监控结果怎么理解。
```

同类风险包括“您好”“嗨”“哈喽”“早上好”“下午好”“晚上好”和“在吗”等纯问候或平台在线确认。

## 2. 诊断结论

线上日志已经确认该轮状态为：

```text
generalOutOfScope=true
outOfScopeBoundary=false
platformIdentity=false
napmRelated=false
```

随后 `before_message_write` 记录：

```text
rewriting assistant message for general out-of-scope request
```

因此故障不在 `/new`、企业微信消息接收或模型回答，而在 JavaScript 门禁的输入分类和输出重写链路。

## 3. 根因

### 3.1 通用域外规则采用过宽的负向判定

插件使用以下公式：

```js
generalOutOfScopeRequested = Boolean(prompt)
  && !domainRelated
  && !platformIdentityPrompt;
```

“你好？”不包含 NAPM、系统、应用、告警、性能等领域关键词，同时旧版 `isPlatformIdentityPrompt()` 只识别“你是谁”“你能做什么”等明确身份问题，没有识别问候语。因此该消息被归入通用域外请求。

### 3.2 输出层会强制覆盖模型回答

`message_sending` 和 `before_message_write` 都会读取 `generalOutOfScopeRequested`。一旦该值为 `true`，即使模型已经生成正常问候，插件也会用统一域外文案覆盖它。

### 3.3 原有回归测试缺少问候场景

旧测试覆盖了身份问题放行和天气问题拦截，但没有覆盖：

1. 纯问候的分类与输出放行；
2. `/new` 后立即发送问候；
3. 带问候前缀的天气、娱乐或 NAPM 请求不能绕过原有分类。

## 4. 业务分类决策

根据项目口径，纯问候归入现有“平台身份/交互”类型，与“你是谁？”共享放行链路：

```text
platformIdentityPrompt=true
generalOutOfScopeRequested=false
napmRelated=false
```

该分类只改变门禁状态，不把用户原文改写成“你是谁”。模型仍根据原始问候自然回答，并依据 OpenClaw workspace 的 `IDENTITY.md` 和 `SOUL.md` 保持观枢AI身份一致。

## 5. 精确边界

### 5.1 放行的纯问候

当前覆盖：

- 你好、您好、嗨、哈喽、哈啰；
- Hello、Hi；
- 早、早上好、上午好、中午好、下午好、晚上好；
- 早安、午安、晚安；
- 在吗、在不在；
- 上述文本允许“观枢AI/助手”称呼、常见语气词和结尾标点。

### 5.2 不因问候前缀放行的请求

问候规则采用整句锚定，以下消息不会被误归为身份/交互类：

```text
你好，今天天气怎么样？
您好，讲个笑话。
你好，帮我查一下现在系统情况。
```

它们会继续根据实际正文分类：天气和娱乐仍走通用域外门禁，系统情况仍走 NAPM 查询链路。

## 6. 当前 JavaScript 门禁及本次影响

| 门禁 | 当前规则 | 本次是否改变 |
| --- | --- | --- |
| OpenClaw 原生命令 | `/new`、`/reset` 等 `/xxx` 命令由 OpenClaw 处理 | 否 |
| 平台身份/交互 | 身份、能力、运行平台和纯问候 | 是，增加纯问候 |
| NAPM 业务分类 | 系统、应用、告警、性能、流量、丢包等领域规则 | 否 |
| 通用域外分类 | 非 NAPM 且非身份/交互的普通请求 | 否，仅排除纯问候 |
| 运维操作边界 | NAPM 相关且包含重启、部署、SQL、Docker、代码等操作词 | 否 |
| 工具路由门禁 | 告警、报告、数据包、故障诊断使用各自专用 Skill | 否 |
| 查询契约门禁 | 校验 `resolvedQuery`、对象路径、服务和查询模式 | 否 |
| 结果证据门禁 | NAPM 回答必须有本轮可验证 Skill 结果 | 否 |
| 报告文件门禁 | 报告文件必须来自本轮 `napm-report-export` | 否 |

## 7. 本地代码修改

### 7.1 分类器

在 `napm-openclaw-plugin.remote.js` 的 `isPlatformIdentityPrompt()` 中增加纯问候正则。规则使用 `^` 和 `$` 锚定整句，防止“你好，查天气”等复合请求利用问候前缀绕过边界。

### 7.2 路由上下文

平台身份路由说明扩展为身份、能力和问候三类。纯问候要求简短、自然地回应并说明自己是观枢AI；该分支不得调用 NAPM Skill 或其他工具。

### 7.3 回归测试

`test/napm-openclaw-plugin-out-of-scope-guard.test.js` 新增：

1. 九种代表性问候的分类测试；
2. 问候在 `message_sending` 和 `before_message_write` 中均不被改写；
3. `/new -> 你好？` 完整轮次测试；
4. 问候前缀不能绕过天气、娱乐和 NAPM 正文分类的反向测试。

## 9. 验收标准

1. `/new` 后发送“你好？”能够收到观枢AI的自然问候；
2. 问候不调用或要求 NAPM Skill；
3. 问候回答不被两个输出钩子覆盖；
4. “你好，今天天气怎么样？”仍返回通用域外文案；
5. “你好，帮我查一下现在系统情况。”仍进入 NAPM 查询链路；
6. 原生命令、身份问答、NAPM 查询、报告、告警和时间契约无回归。
