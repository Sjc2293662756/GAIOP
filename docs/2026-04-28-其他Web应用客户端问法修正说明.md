# 其他Web应用客户端问法修正说明

## 1. 问题现象

真实问句：

- `访问其他web应用次数最多的客户端是谁？`

现网表现：

- OpenClaw 返回“还需要补充一点信息”
- 或出现“本次未查到数据”的错误型叙述

这类表现不符合预期，因为该问句本身已经具备可执行查询所需的关键语义：

- 查询模式：排行类
- 指标语义：访问次数
- 锚点对象：其他 Web 应用
- 目标对象：客户端

---

## 2. 边界判断

根据当前项目约定，主修复位置应放在 OpenClaw 主判侧，而不是网关本地执行侧。

原因：

- 当前链路是 query-only
- OpenClaw 负责语义理解、判定、打分、叙述
- 网关只负责执行 `resolvedQuerySeed`

因此，本次不继续在网关补“词语补丁式”本地主判，而是增强 OpenClaw skill 的提示与示例。

---

## 3. 本次修正

修改文件：

- `skills/openclaw-napm-query/agents/openai.yaml`
- `skills/openclaw-napm-query/SKILL.md`
- `skills/openclaw-napm-query/references/openclaw-integration.md`

新增规则：

1. 当问句同时出现 `访问量 / 访问次数 / 页面访问` 与 `客户端 / 客户端IP` 时：
   - 优先使用指标 `PGNPGE`
   - 目标对象优先使用 `ClientIPs`

2. 当问句同时出现 `其他web应用 / 其它web应用 / 未注册web应用 / Other Web Application` 时：
   - 视为显式 `WebApplication` 参数
   - 不再因为“其他”二字进入不必要的澄清

3. 对于 `谁` 这类单对象问法：
   - 优先使用 `topCount=1`

目标查询形态：

- `service=topValues`
- `metric=PGNPGE`
- `topMetric=PGNPGE`
- `groups=[{type:"WebApplication",argument:"Other Web Application"},{type:"ClientIPs"}]`

---

## 4. 这次为什么不修网关本地解析器

虽然本地解析器当前也会把该问句错误收敛成：

- `metric=TPIO`
- `groups=[WebApplication]`

但这个错误不应成为继续扩张网关主判职责的理由。

项目边界已经明确：

- 上游主判负责“这句话到底想查什么”
- 网关负责“按 seed 执行并回传结构化结果”

因此本次修正优先落在 OpenClaw 侧提示、few-shot 和接入说明上。

---

## 5. 预期效果

修正后，OpenClaw 对下面这类问句应更稳定地直接执行：

- `访问其他web应用次数最多的客户端是谁？`
- `最近访问其他web应用最多的客户端IP是谁？`
- `其他web应用里访问次数最高的客户端是谁？`

而不是进入：

- 无意义澄清
- 或“本次未查到数据”的错误叙述
