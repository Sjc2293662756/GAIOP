## 已收口的问题

### 会话状态隔离

- 插件不再使用进程级最新查询结果、调试地址、报告导出结果或待发送告警文本作为业务回退。
- 查询结果、调试地址和报告导出记录由 `ConversationOperationState` 按服务端可信会话范围保存；状态有结果 TTL、报告 TTL 和最大条目数淘汰。
- `before_tool_call` 从 OpenClaw 上下文生成并注入追踪标识；调用方传入的追踪标识会被覆盖，工具不能把模型提供的会话值当作可信范围。
- 跟进式报告导出仅可读取当前可信会话的已保存结果；没有可信范围且没有显式 `reportData` 时返回 `REPORT_DATA_NOT_FOUND`，不会回退到其他会话数据。
- 告警内容不再由发送 hook 的全局单例替换，避免请求乱序时把一个会话的告警发送给另一个会话。

### 综述和故障诊断的真实性

- 新增共享的 `ExecutionOutcome`，将每个计划查询明确记录为 `success`、`empty` 或 `failed`，并提供机器可读的完整度、失败来源和计数。
- 综述 API 的非 2xx 响应会以 `NAPM_HTTP_STATUS_ERROR` 抛出，不会被当作正常响应解析。
- 所有必需综述查询失败时，返回 `ok: false` 与 `SUMMARY_REQUIRED_DATA_UNAVAILABLE`，不会生成健康结论或报告数据。
- 部分查询失败时，返回 `partial: true`、`failures[]` 和 `overallStatus: "unknown"`。
- 所有必需查询成功但均无数据时，返回 `ok: true`、`empty: true` 和 `overallStatus: "unknown"`，与上游失败明确区分。
- 故障诊断的必需查询失败会立即停止流程，返回 `reportReady: false`；报告构建器会拒绝该会话。
- 故障诊断的必需查询返回空证据同样会停止流程，返回 `FAULT_DIAGNOSIS_REQUIRED_EVIDENCE_EMPTY`，不会把无证据结果写入正式报告。
