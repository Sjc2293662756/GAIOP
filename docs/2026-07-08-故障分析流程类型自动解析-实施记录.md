# 故障分析流程类型自动解析 — 实施记录

## 问题背景

观枢AI-1.0 在处理用户请求时频繁将"应用故障分析"与"业务故障分析"混淆。典型场景：

> 用户说："给我可观测239 的应用故障分析报告！"
> AI 执行：看到"239"联想到"239web"，走 `bs_app_slow`（B/S 业务故障分析）
> 实际情况："可观测239"在 NAPM 中是 **DefinedApp (Type=2)**，应该走 `cs_app_slow`（C/S 应用故障分析）

根因分析：
1. **分类器关键词不覆盖"应用故障"** — 原有 `classify()` 的 CS 关键词列表不含"应用"二字，用户说"应用故障分析"直接跌入 `network_slow` 默认
2. **AI 靠猜** — AI 没有 NAPM 对象类型的 ground truth，看到名称就联想
3. **SKILL.md 缺乏业务/应用区分指引** — 路由规则表只有 BS 示例，没有 CS 示例

## 解决方案

**用 NAPM 自身的 `applications` 目录作为 ground truth，名称匹配优先于关键词分类。**

```
用户说 "可观测239的应用故障分析报告"
  → extractTargetName() = "可观测239"
  → _getAppCatalog() → applications API（5min 缓存）
  → matchAppByName("可观测239", catalog) → {name:"可观测239", type:2, score:100}
  → resolveFlowTypeFromCatalog() → {flowType:"cs_app_slow", groupType:"DefinedApp"}
  → 走 CS 应用故障分析流程
```

#### 新增函数 1：`extractTargetName(input)`

从用户输入中提取候选目标名称。

**策略**：关键词锚定法 — 先在文本中定位"应用故障"/"业务故障"等关键词位置，再向前提取紧邻的名称。

**关键词匹配顺序**（先命中先返回）：
1. `(?:应用|业务)故障` — "应用故障" / "业务故障"
2. `(?:应用|业务)(?:慢|异常|延迟|分析|诊断)` — "应用慢" / "业务异常" 等
3. `故障(?:分析|报告|诊断)` — "故障分析" / "故障报告"（通用，无 应用/业务 前缀）

**名称提取逻辑**：
```
关键词定位后，取关键词之前的文本片段
  ├─ 有"的" → 取"的"之前的最后一个词（"可观测239的应用故障" → "可观测239"）
  └─ 无"的" → 取最后一个 CJK/字母数字连续段（"可观测239web业务故障" → "可观测239web"）
```

**前缀清理**：剥离残留的动作词/代词（"分析"、"帮我"、"请"、"给"、"出个" 等）。

**完整实现**：

```javascript
function extractTargetName(input = {}) {
  // 1. 显式 target 字段优先
  const label = input.target?.groupLabel || input.target?.groupArgument || '';
  if (label.trim()) return label.trim();

  // 2. 关键词锚定提取
  const desc = String(input.description || '');
  const kwPatterns = [
    /(?:应用|业务)故障/,
    /(?:应用|业务)(?:慢|异常|延迟|分析|诊断)/,
    /故障(?:分析|报告|诊断)/,
  ];
  let kwMatch = null;
  for (const pat of kwPatterns) {
    kwMatch = desc.match(pat);
    if (kwMatch) break;
  }
  if (!kwMatch) return null;

  const before = desc.slice(0, kwMatch.index).trim();
  if (!before) return null;

  let raw = null;
  const deMatch = before.match(/(\S+?)的$/);
  if (deMatch) {
    raw = deMatch[1];
  } else {
    const runMatch = before.match(/([一-龥a-zA-Z0-9_-]+)$/);
    if (runMatch) raw = runMatch[1];
  }
  if (!raw) return null;

  raw = raw.replace(/^(?:请帮我看一下|请帮我分析一下|帮我分析一下|...)+/, '').trim();
  return raw || null;
}
```

#### 新增函数 2：`matchAppByName(candidateName, catalog)`

在 NAPM applications 目录中按名称查找最佳匹配。

**计分规则**：

| 匹配方式 | 得分 | 示例（候选="可观测239"） |
|------|:--:|------|
| 精确匹配 | 100 | `name === "可观测239"` |
| 前缀匹配 | 80 | `name.startsWith("可观测239")` → "可观测239web" |
| 包含匹配 | 50 | `name.includes("可观测239")` → "交通可观测性分析平台" |
| 被包含匹配 | 40 | `"可观测239".includes(name)` 且 name 长度≥3 |

**得分相同时**：优先 Type=2（DefinedApp），因为其名称通常更短、更精确。

**完整实现**：

```javascript
function matchAppByName(candidateName, catalog = []) {
  if (!candidateName || catalog.length === 0) return null;
  const candidates = [];
  for (const app of catalog) {
    const name = String(app.name || '');
    if (!name) continue;
    if (name === candidateName)
      candidates.push({ name, type: Number(app.type)||0, score:100, matchType:'exact' });
    else if (name.startsWith(candidateName))
      candidates.push({ name, type: Number(app.type)||0, score:80, matchType:'prefix' });
    else if (name.includes(candidateName))
      candidates.push({ name, type: Number(app.type)||0, score:50, matchType:'contains' });
    else if (candidateName.includes(name) && name.length >= 3)
      candidates.push({ name, type: Number(app.type)||0, score:40, matchType:'contained' });
  }
  if (candidates.length === 0) return null;
  candidates.sort((a, b) => {
    if (b.score !== a.score) return b.score - a.score;
    if (a.type === 2 && b.type !== 2) return -1;
    if (b.type === 2 && a.type !== 2) return 1;
    return 0;
  });
  return candidates[0];
}
```

#### 新增函数 3：`resolveFlowTypeFromCatalog(match)`

根据 NAPM Type 判定流程类型和目标类型。

```javascript
function resolveFlowTypeFromCatalog(match) {
  const isBusiness = match.type === 3;  // Type=3 → WebApplication
  return {
    flowType: isBusiness ? 'bs_app_slow' : 'cs_app_slow',
    groupType: isBusiness ? 'WebApplication' : 'DefinedApp',
    groupArgument: match.name,
    groupLabel: match.name
  };
}
```

**Type 映射表**：

| NAPM Type | 含义 | flowType | groupType |
|:--:|------|------|------|
| 1 | BuiltinApplication | `cs_app_slow` | `DefinedApp` |
| 2 | DefinedApp | `cs_app_slow` | `DefinedApp` |
| 3 | WebApplication | `bs_app_slow` | `WebApplication` |
| 4 | CompositeApplication | `cs_app_slow` | `DefinedApp` |

#### 改动 3：新增 `_getAppCatalog()` 方法

```javascript
async _getAppCatalog() {
  const TTL_MS = 300_000; // 5 分钟缓存
  if (this._appCatalogCache
      && (Date.now() - this._appCatalogCache.fetchedAt < TTL_MS)) {
    return this._appCatalogCache.list;
  }
  try {
    const raw = await this.client.request('applications', {});
    const list = Array.isArray(raw) ? raw
      : (Array.isArray(raw?.rows) ? raw.rows : []);
    this._appCatalogCache = { list, fetchedAt: Date.now() };
    return list;
  } catch (_) {
    return null;  // 查询失败 → 回退到关键词分类器
  }
}
```

#### 改动 4：`start()` 中插入名称解析逻辑

**修改前**（第 143-146 行）：

```javascript
const description = String(input.description || input.fault?.description || '');
const flowType = input.flowType || classify(description);
const flow = getFlow(flowType);
const timeRange = this._resolveTimeRange(input.timeRange || input);
const target = isPlainObject(input.target) ? input.target : null;
```

**修改后**：

```javascript
const description = String(input.description || input.fault?.description || '');

// ── Resolve flowType ──
let flowType = input.flowType || null;
let resolvedTarget = isPlainObject(input.target) ? { ...input.target } : null;

if (!flowType) {
  // Step 1: 名称 → NAPM 目录解析
  const candidateName = extractTargetName(input);
  if (candidateName) {
    const catalog = await this._getAppCatalog();
    if (catalog) {
      const match = matchAppByName(candidateName, catalog);
      if (match) {
        const resolved = resolveFlowTypeFromCatalog(match);
        flowType = resolved.flowType;
        if (!resolvedTarget || !resolvedTarget.groupType) {
          resolvedTarget = {
            groupType: resolved.groupType,
            groupArgument: resolved.groupArgument,
            groupLabel: resolved.groupLabel
          };
        }
      }
    }
  }
  // Step 2: fallback 到关键词分类器
  if (!flowType) {
    flowType = classify(description);
  }
}

const flow = getFlow(flowType);
const timeRange = this._resolveTimeRange(input.timeRange || input);
const target = resolvedTarget;
```

## 实现的容错策略

每一步都有 fallback，保证不会比修改前更差：

| 失败点 | 处理 |
|------|------|
| 名称提取不到（无关键词匹配） | `extractTargetName()` 返回 `null` → 跳过目录查询 |
| `applications` API 调用失败 | `_getAppCatalog()` 返回 `null` → 跳过匹配 |
| 名称在目录中未命中 | `matchAppByName()` 返回 `null` → 跳过解析 |
| 调用方已传 `flowType` | 整个解析流程跳过，直接使用传入值 |

**最坏情况**：所有步骤都失败 → 回退到 `classify(description)`，行为与修改前完全一致。

## 设计权衡

| 决策 | 选择 | 权衡 |
|------|------|------|
| `applications` API 单次全量查询 + 5min 缓存 | ✅ | 避免每次 `start()` 都调 API；TTL 短到不至于错过新增应用 |
| 关键词锚定 → 名称提取 | ✅ | 避免从字符串开头全量匹配的贪婪问题；中文无空格场景下稳健 |
| 名称匹配优先，关键词 fallback | ✅ | ground truth > 启发式；AI 调 `start()` 不再需要自己猜 flowType |
| OtherApp 暂不自动发现 | ⚠️ | OtherApp 来源是 `groupArguments` API（非 `applications`），需要额外调用；作为后续迭代 |
| `resolveFlowTypeFromCatalog` 在 FlowRouter 中 | ✅ | 纯函数，无副作用，可单测，不依赖 Service 实例 |
