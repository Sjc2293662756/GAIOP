# OpenClaw 综合分析构造约束说明

日期：2026-05-28

## 1. 背景

功能一执行内核已经支持：

```text
overview + analysisPipeline.discoveryQuery
```

但真实生产链路中，`resolvedQuery` 的构造由 OpenClaw 完成。

因此只在本地 resolver 测通没有意义。必须约束真实 OpenClaw 在调用 `napm-skill-query` 前构造出正确结构，并在构造错误时由 plugin 边界阻断。

## 2. 本次修改目标

本次修改围绕 plugin 侧真实主链路：

- 增强 `napm-skill-query` tool schema。
- 增强 OpenClaw 构造提示。
- 新增综合分析边界 guard。
- 防止“为什么/原因/分析”类问题被构造成普通 TopN 后直接执行。

## 3. 构造规则

### 3.1 普通 TopN

用户问：

```text
最近一小时丢包最高的前10个IP
```

允许：

```json
{
  "service": "topValues",
  "queryModeKey": "topn",
  "groups": [
    { "type": "IPAddress" }
  ],
  "metrics": ["PLI", "PLO"],
  "topMetric": "PLI",
  "topCount": 10,
  "start": "<from napm-resolve-time-range>",
  "end": "<from napm-resolve-time-range>"
}
```

### 3.2 先发现再分析

用户问：

```text
丢包最严重的 IP 是谁，为什么？
找到连接失败最多的地址，然后分析它
哪个业务 HTTP 500 最严重，并分析原因？
```

必须构造：

```json
{
  "service": "overview",
  "queryModeKey": "overview",
  "analysisType": "comprehensive_analysis",
  "analysisMode": "discover_then_analyze",
  "analysisScene": "network",
  "overviewScene": "network",
  "analysisPipeline": {
    "targetObjectType": "IPAddress",
    "selection": {
      "rank": 1
    },
    "discoveryQuery": {
      "service": "topValues",
      "queryModeKey": "topn",
      "groups": [
        { "type": "IPAddress" }
      ],
      "metrics": ["PLI", "PLO"],
      "topMetric": "PLI",
      "topCount": 1
    }
  },
  "start": "<from napm-resolve-time-range>",
  "end": "<from napm-resolve-time-range>"
}
```

注意：

- `service=overview` 是兼容执行名。
- 用户语义必须写成 `analysisType=comprehensive_analysis`。
- `discoveryQuery` 不能携带 `start/end`。
- discovery 与 focused analysis 复用顶层 `start/end`。

## 4. 新增边界 guard

新增函数：

- `isComprehensiveAnalysisPrompt(prompt)`
- `isDiscoverThenAnalyzePrompt(prompt)`
- `validateComprehensiveAnalysisResolvedQuery(prompt, resolvedQuery)`

阻断规则：

如果用户问题包含：

```text
为什么 / 原因 / 分析 / 综合分析 / 根因 / 诊断 / 情况怎么样 / 是否异常
```

但 OpenClaw 构造的是：

```json
{ "service": "topValues" }
```

则阻断，要求重新构造综合分析 resolvedQuery。

如果是 discover-then-analyze 问题，但缺少：

```json
{
  "analysisType": "comprehensive_analysis",
  "analysisMode": "discover_then_analyze",
  "analysisPipeline": {
    "discoveryQuery": {
      "service": "topValues"
    }
  }
}
```

也阻断。

```text

```

```json
{
  "service": "overview",
  "analysisType": "comprehensive_analysis",

    "discoveryQuery": {
      "service": "topValues"
    }
  }
```
