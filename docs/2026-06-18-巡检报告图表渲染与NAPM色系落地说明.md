# 巡检报告图表渲染与 NAPM 色系落地说明

日期：2026-06-18

## 一、背景

巡检报告固定模板中有 4 个图表槽位（chartSlot），之前只输出占位表格（图表名称、类型、数据绑定等元信息），未嵌入真实 ECharts 图表。本次改造完成以下目标：

1. ECharts 输出 PNG 能力（echarts-chart-skill 侧）
2. chartSlot 占位表格 → 真实 ECharts PNG 图片嵌入 Word
3. 图表按 NAPM 产品色系规范渲染
4. 远端 Linux 服务端中文字体渲染修复
5. 通用报告管道支持 `type: chart` 段落

}

## 三、chartSlot → 真实图片嵌入

### 3.1 改造文件

`skills/openclaw-napm-report/services/InspectionFixedTemplateService.js`

### 3.2 新增函数

#### `buildEChartsOption(chartSpec, context)`

从 chart spec（`chart-specs.v1.json`）和巡检上下文构建完整 ECharts option。

- **数据提取**：`getByPath(context, chartSpec.datasetPath)` 从巡检数据中取出实际数据
- **折线图**（line）：读取 `dataset.points[]`，按 `xField` 和 `series[].field` 映射
- **柱状图**（bar）：读取 `dataset` 数组，按 `xField` 和 `series[].field` 映射

**数据绑定路径**：

| chartId | datasetPath | 数据类型 |
|---------|-------------|----------|
| `traffic.recentHour.total` | `inspection.trafficAnalysis.recentHour.dataset` | `{points:[], metrics:[]}` |
| `traffic.recentDay.total` | `inspection.trafficAnalysis.recentDay.dataset` | `{points:[], metrics:[]}` |
| `business.slowAccess.top` | `inspection.businessPerformance.slowAccess` | `[{businessName, slowCount, ...}]` |
| `business.httpErrors.top` | `inspection.businessPerformance.httpErrors` | `[{businessName, http400, http500}]` |

#### `renderChartPngBuffer(option, width, height)`

```js
async function renderChartPngBuffer(option, width = 960, height = 540) {
  const echarts = await import('echarts');
  const sharp = (await import('sharp')).default;
  const chart = echarts.init(null, undefined, {
    renderer: 'svg', ssr: true, width, height
  });
  chart.setOption(option);
  const svg = chart.renderToSVGString();
  chart.dispose();
  return sharp(Buffer.from(svg)).png().toBuffer();
}
```

### 3.3 改造方法

#### `preRenderCharts(template, context)` — 新增

扫描模板中所有 `type: "chartSlot"` 段落，**在构建文档 children 之前**批量预渲染为 PNG Buffer，存入 `Map<sectionId, {buffer, width, height}>`。

#### `renderChartSlot(section, context, chartBuffers)` — 修改

- **优先路径**：从 `chartBuffers` 中读取预渲染的 PNG Buffer，创建 `ImageRun` 嵌入段落
- **Fallback 路径**：若渲染失败（如 Jest 环境不支持 ESM import），回退为占位表格

#### `renderDocx(report)` — 修改

构建文档前先调用 `this._chartBuffers = await this.preRenderCharts(template, context)`，然后将 `chartBuffers` 传入各 section 渲染。

## 五、远端中文字体修复

### 5.1 问题

远端 Linux 服务器没有 CJK 字体，sharp 将 ECharts SVG 转为 PNG 时，中文字符渲染为空白/方块。

### 5.2 排查过程

```bash
# 确认问题
fc-list :lang=zh          # 空 — 无中文字体
ls /usr/share/fonts/      # 仅 DejaVu/Quicksand/Ubuntu (拉丁字体)
```

### 5.3 修复方案

1. 从阿里云镜像下载 `fonts-wqy-microhei`（文泉驿微米黑，开源 CJK 字体，5MB）
2. 解压安装到 `~/.fonts/`（**无需 sudo**）
3. `fc-cache -fv ~/.fonts` 刷新 fontconfig 缓存
4. 在 `buildEChartsOption()` 中所有文本组件添加 `fontFamily: 'WenQuanYi Micro Hei, ...'`

### 5.4 安装命令

```bash

# 提取字体文件
mkdir -p ~/.fonts
cd /tmp && ar x wqy-font.deb data.tar.xz
tar -xJf data.tar.xz
cp usr/share/fonts/truetype/wqy/wqy-microhei.ttc ~/.fonts/

# 刷新缓存
fc-cache -fv ~/.fonts
```

## 九、设计决策

### 9.1 为什么预渲染而非按需渲染

- `renderSection()` 是同步方法，而 `import('echarts')` 和 `import('sharp')` 是异步的
- 在 `renderDocx()` 入口处批量预渲染所有 chart，存入 Map，各 section 同步读取
- 避免将整条渲染链改为 async

### 9.2 为什么 fallback 而非报错

- Jest 不支持 ESM 动态 import → chart 渲染失败是预期行为
- 生产环境（Node.js + ESM support）正常工作
- fallback 占位表格确保测试不中断，生产有数据则自动生成图表

### 9.3 为什么色板用常量而非主题注册

- ECharts SSR 模式下 `echarts.registerTheme()` 不被使用
- 直接在 option 中内联颜色、样式，对 SSR→PNG 管线最可靠
- 色板从 NAPM 产品代码的 `shine/NI_NAPM` 主题提取，保持视觉一致

## 十一、NAPM API 数据格式对齐

### 问题

图表文字渲染正常，但数据线条/柱条不显示。排查发现 NAPM API 返回的 `timeValues` 是**列式结构**（`metricValues[]` 每列一个指标数组），而代码的 `extractRows()` 只认行式格式（`data`/`rows`/`items`），导致 0 条数据。

### API 实际返回格式

```json
// timeValues（列式）
{
  "metricValues": [
    { "metric": {"id":"TPIO"}, "values": [81, 99, 98, ...] },
    { "metric": {"id":"TPI"},  "values": [36, 39, 38, ...] },
    { "metric": {"id":"TPO"},  "values": [44, 59, 60, ...] }
  ],
  "interval": { "start": 1781770800, "end": 1781774400 },
  "granularity": 60
}

// topValues（也是列式，每行有 group.argument 为业务名）
[
  {
    "group": { "argument": "回溯238web", "label": "WEB应用", ... },
    "metricValues": [
      { "metric": {"id":"PGSLPCT"}, "value": 0.098 },
      { "metric": {"id":"PGNSLPGE"}, "value": 4 }
    ]
  }
]
```

### 修复

#### InspectionTrafficAnalysisService.js

`normalizeTimeSeriesDataset()` 新增列式→行式转置逻辑：

- 检测 `raw.metricValues`（列式标志）
- 按 `interval.start + index * granularity` 推算每行时间戳
- 交错各列 `values[index]` 拼接成 `{time, TPIO, TPI, TPO}` 行
- 支持 `valids` 数组过滤无效点

#### InspectionBusinessPerformanceService.js

`readObjectName()` 修复 `[object Object]` bug：
- NAPM API 的 `group` 是对象 `{argument:"回溯238web", ...}`
- 之前 `String(group)` → `"[object Object]"`
- 修复：对象情况优先提取 `candidate.argument`

## 十二、目录（TOC）修复

### 问题演进

1. **初始**：TOC 域码正确但 Word 不更新 → 显示空白
2. **排查**：Word "未找到目录项" → 标题样式缺少关键属性
3. **最终修复**：三个条件缺一不可

### 根因

Word TOC 域 `\o "1-2"` 要求标题样式同时满足：

| 条件 | 说明 | 缺失时的表现 |
|------|------|-------------|
| `w:link` | 链接字符样式（`Heading1` ↔ `Heading1Char`） | Word 不认其为内置标题 |
| `w:outlineLvl` | **0-based**：0=TOC Level 1, 1=TOC Level 2 | 二级标题进不了 `\o "1-2"` 范围 |
| `HeadingXChar` 样式 | `w:link` 指向的字符样式必须存在 | 双向链接断裂 |

### 修复方案

1. `buildDocumentStyles()` 中定义 `heading1`/`heading2`，设置 `link: 'Heading1Char'` 和 `outlineLevel: 0` / `outlineLevel: 1`
2. Post-processing 补全 `Heading1Char`/`Heading2Char` 字符样式（docx 库不会自动生成）
3. 使用 `TableOfContents` 生成正确的 `TOC \h \o "1-2"` 域码（非 `SimpleField`）

### 自动更新

`features: { updateFields: true }` 已在 settings.xml 生成 `<w:updateFields/>`。Word 不自动更新域的原因是该文件从网络/Gateway 下载时受**受保护视图**拦截。解决：Word 信任中心关闭"为来自 Internet 的文件启用受保护视图"，或打开后 Ctrl+A → F9。
