# 告警数据包普通摘要退化与专项渲染修复记录

## 现象

告警引用 `GJ-L9CUNLY9` 的三个候选数据包均完成分析，但最终回复主要描述 IP 对、流量大小、外部 IP 和扫描探测，没有围绕告警指标“用户体验时间（服务器）=1373.96 毫秒”回答服务端等待、HTTP 响应耗时、TCP RTT、TCP 重传及告警时间相关性。

模型还把确定性分析窗口 `14:43-14:47` 自行改写为 `14:43-14:48`，并暴露了内部事件 ID。

## 日志与代码证据

1. 生产日志确认组合工具成功恢复告警引用、识别三个候选并完成三次数据包分析；没有本次 IP 缺失或下载失败的证据。
2. `AlertMetricProfileService` 已将该指标解析为 `server_user_experience_time`，并生成五项专项证据检查。
3. `run_packet_analysis.js` 已生成 `analysis.alertEvidence`，但此前只作为 `alertContext`、`alertRenderHint` 和 `narrationInput` 提示模型。
4. `AlertPacketFinalReplyService` 的旧准入条件只要求文本包含“告警/数据包/重传”等宽泛词汇，完成态模型自由稿因此可以覆盖确定性结果。

## 根因

专项证据链路已执行，问题出在最终交付层：完成态模型文本被保存并由 `message_sending` 交付，确定性渲染只在没有模型稿时作为兜底。提示信息不是输出契约，无法约束模型逐项回答指标证据。

## 修复内容

### 1. 完成态统一确定性出口

- 告警数据包工作流的模型最终稿一律不准入。
- `before_message_write` 直接将模型文本替换为 `buildDeterministicFinalReply` 结果并写入最终内容状态。
- `message_sending` 继续使用同一份确定性内容并保留单轮去重。
- 失败、部分完成、等待确认和完成态使用同一确定性出口，避免模型泄露内部规划或自由改写时间。

### 2. 告警指标专项输出

确定性回复在存在触发指标时输出：

- 实际值、可解析阈值、命中规则和超阈值差值。
- 告警指标画像和逐候选结果。
- 服务端响应等待、HTTP 响应耗时、TCP RTT、TCP 重传、告警时间相关性等证据状态。
- `已捕获`、`部分捕获`、`未捕获`、`证据不足` 等明确状态。
- 仅保留与响应、时延、重传、丢包、错误等指标相关的专项观察；不再把流量/IP/扫描统计当作根因结论。
- 没有专项证据时明确说明“未捕获/证据不足，无法据此判断触发原因”。

### 3. 时间与内部字段保护

- 回复时间范围只来自工作流结果中的固定 `timeRange`，不接受模型扩展。
- 引用场景继续只展示 `referenceId`，不展示 `eventId/start/end`。
- 保留凭据和 URL 脱敏逻辑。

## 回归验收

- 普通 IP/流量/扫描摘要在完成态被拒绝。
- `1373.96 毫秒 > 1000 毫秒` 输出“超过 373.96 毫秒，命中阈值 Minor”。
- 五项专项证据逐项输出，时间戳落在告警窗口时标记“已关联”。
- `before_message_write` 与 `message_sending` 输出完全来自确定性渲染，模型自由稿不会交付。
- 最小插件安装目录不依赖完整 `skills/` 目录即可加载。
