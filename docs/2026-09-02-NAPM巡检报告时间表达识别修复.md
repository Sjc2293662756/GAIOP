# NAPM 巡检报告时间表达识别修复

日期：2026-09-02

## 问题现象

用户请求“给我系统最近一个月的巡检报告”时，报告只生成最近 1 小时和最近 1 天的流量图，业务性能窗口也变成最近 1 小时。报告文件结构和图表渲染正常，错误发生在上游时间表达识别。

根因是自动巡检参数构造调用了带“默认最近 1 小时”的查询解析入口，无法区分以下三种情况：

1. 用户明确选择最近 1 小时；
2. 用户没有提供时间范围；
3. 用户提供了时间表达，但解析器不支持。

“最近一个月”和“2026 年第一季度”原本属于第 3 种，却被当成第 1 种传入报告。

## 修复后的时间语义

| 用户表达 | 解析结果 |
| --- | --- |
| 最近/过去/近一个月 | 滚动最近 30 天 |
| 最近/过去/近三个月 | 滚动最近 90 天 |
| 最近 12 个月 | 滚动最近 365 天 |
| 其他最近 N 个月 | 按 `N * 30` 天规范化 |
| 本月/上个月 | `Asia/Shanghai` 当前/上一自然月 |
| `YYYY年M月` | 指定自然月，当前月截止到当前分钟 |
| `YYYY年第N季度` | 指定自然季度，当前季度截止到当前分钟 |
| `YYYY年` | 指定自然年，当前年截止到当前分钟 |

自然月、季度和年度的起止时间由服务端在 `Asia/Shanghai` 下生成，并对齐到分钟。未到来的自然时间段和非法季度不会生成查询窗口。

## 巡检窗口契约

- 用户明确选择时间时，主流量和业务性能查询共用该窗口。
- 时间跨度大于 1 天时，保留报告截止时最近 1 天和最近 1 小时辅助流量窗口。
- 用户未提供时间时，主流量仍默认最近 1 小时，辅助流量为最近 1 天，业务性能恢复默认最近 7 天。
- 如果检测到明确时间表达但无法解析，停止报告生成并返回 `INSPECTION_TIME_RANGE_UNRECOGNIZED`，禁止静默回退最近 1 小时。

## 粒度与图表

本次不修改统一自动粒度规则。修复后的典型结果为：

| 时间窗口 | 查询跨度 | 自动粒度 |
| --- | ---: | ---: |
| 最近一个月 | 30 天 | 3600 秒 |
| 最近一个季度 | 90 天 | 86400 秒 |
| 2026 年第一季度 | 2026-01-01 00:00 至 2026-03-31 23:59 | 86400 秒 |
| 最近一年 | 365 天 | 86400 秒 |

业务图仍是慢访问和 HTTP 400/500 异常 Top 图；异常筛选结果为空时使用无数据占位，不伪造空白图表。
