# 2026-04-29 Skill自主决策直查落地说明

> 说明：本文记录的是 2026-04-29 当时为了兜底可用性而引入的“Skill 本地自主解析”阶段性方案。  
> 按当前已经收口后的正式架构，OpenClaw / 上游应输出结构化 `resolvedQuery`，Skill 不再把“本地 prompt 解析”作为正式主路径。

## 本次目标

将 NAPM 查询链路从“依赖上游 decision / 网关兜底”调整为：

1. skill 可以在缺少上游 `decision` 时自主判定查询类型
2. skill 可以直接根据问句构造 NAPM API 查询参数
3. 查询结果优先交给 OpenClaw 做自然叙述
4. 避免再次出现“上游策略拦截后完全不查”的情况

## 本次修改文件

1. `skills/openclaw-napm-query/scripts/run_napm_query.js`
2. `skills/openclaw-napm-query/services/OpenClawNarrationContractService.js`

## 核心改动

### 1. 增加 skill 本地决策兜底

当上游没有传入合法 `decision` 时，不再直接返回：

- `由于上游决策未通过`
- `查询被上游策略拦截`

而是改为走 skill 本地兜底：

- `inferLocalDecision(...)`
- 自动识别清单类、TopN 类、趋势类、单对象指标类问法

### 2. 增加 skill 本地 resolvedQuery 构造

当上游没有传入 `resolvedQuery` 时，skill 直接从原始问句推断：

- `service`
- `groups`
- `metric / metrics`
- `topMetric / topCount`
- `start / end`

当前已重点覆盖：

1. Web 应用清单查询
2. TopN 排名查询
3. IP 单对象指标查询
4. “服务器响应时间”这类明确指标问法

### 3. 修正“服务器响应时间”落指标

本次本地直查中，`服务器响应时间` 优先落到：

- `TRTI`

而不是继续误落到：

- `RTTI`

### 4. 修正 TopN 叙述输入

针对 `topValues` 结果增加了二次整理：

1. 按指标值重新排序，避免上游原始行顺序不稳定
2. 从 `metricValues` 中提取真实对象名、数值、单位
3. 不再向 OpenClaw 传递 `对象1 / 对象2 / 无数据` 这类占位内容

### 5. 修正 Web 应用清单叙述输入

对于 `系统中有哪些web应用` 这类问法：

1. 仍保留原始全量返回数据
2. 叙述层优先使用过滤后的可读对象列表
3. 尽量把协议类名称和兜底项与真正业务应用区分开

## 本地验证结果

### 验证1

问句：

`系统中有哪些web应用`

结果：

1. 不再被“缺少上游 decision”拦截
2. 能直接命中 `groups -> WebApplication`
3. 可拿到 Web 应用列表数据

### 验证2

问句：

`最慢的前5个应用分别是谁`

结果：

1. skill 本地判定为 `GO_DIRECT_QUERY`
2. 自动构造 `topValues + WebApplication + PGTME + topCount=5`
3. TopN 结果已按页面延时数值重新排序
4. 叙述输入中对象名已为真实应用名

### 验证3

问句：

`101.254.114.238的服务器响应时间是多少`

结果：

1. 自动构造 `averageValues + IPAddress + TRTI`
2. 已确认不是 `RTTI`
