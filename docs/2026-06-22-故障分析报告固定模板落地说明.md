## 三、模板章节结构

### 章节列表及类型

```
封面 (cover)
  ├── 封面日期 (paragraphs)
  ├── 分页 (pageBreak)
  └── 目录 (toc) + 分页

1 故障概述 (heading L1)
  1.1 故障基本信息 (table: faultBasicInfo)
  1.2 故障时间线 (table: faultTimeline, condition: fault.timeline exists)
  1.3 综合影响评估 (table: healthSummary + narrative: fault.overview)

2 告警关联分析 (heading L1)
  2.1 告警概览 (table: alertCategoryStats)
  2.2 告警时序 (chartSlot: alert.timeline)
  2.3 关联告警详情 (table: alertDetails)
  → 告警结论 (narrative: alert.conclusion)

3 流量异常分析 (heading L1)
  3.1 流量趋势 (chartSlot: traffic.trend)
  3.2 流量异常明细 (table: trafficAnomalies, condition: exists)
  3.3 Top 受影响对象 (chartSlot + table: trafficTopIPs, condition: exists)
  → 流量结论 (narrative: traffic.conclusion)

4 业务性能影响 (heading L1)
  4.1 慢访问状况 (chartSlot + table: businessSlowTable)
  4.2 HTTP 错误状况 (chartSlot + table: businessErrorTable)
  → 业务结论 (narrative: business.conclusion)

5 数据包深度分析 (heading L1, condition: packetAnalysis exists)
  5.1 协议分布 (table: packetProtocol, condition: protocolHierarchy exists)
  5.2 关键端点与会话 (table: packetEndpoints + packetConversations)
  5.3 关键发现 (dataParagraphs: highlights, condition: exists)
  → 数据包结论 (narrative: packet.conclusion)

6 根因分析与建议 (heading L1)
  6.1 根因判断 (narrative: root_cause)
  6.2 修复建议 (dataParagraphs: fault.recommendations)
  6.3 预防措施 (dataParagraphs: fault.prevention)
```

### 条件章节

模板引入 `condition` 字段控制章节显隐：

| condition | 影响的章节 |
|-----------|-----------|
| `fault.timeline exists` | 1.2 故障时间线 |
| `trafficAnalysis.anomalies exists` | 3.2 流量异常明细 |
| `trafficAnalysis.topIPs exists` | 3.3 Top 受影响对象 |
| `packetAnalysis exists` | 整个第5章 |
| `packetAnalysis.protocolHierarchy exists` | 5.1 协议分布 |
| `packetAnalysis.endpoints exists` | 5.2 端点表 |
| `packetAnalysis.conversations exists` | 5.2 会话表 |
| `packetAnalysis.highlights exists` | 5.3 关键发现 |

条件在 `DiagnosticFixedTemplateService.buildChildren()` 中评估，不满足条件的章节完全不进入文档构建管线。

## 四、DiagnosticFixedTemplateService

### 继承结构

```
InspectionFixedTemplateService (基础引擎)
  ├── SummaryFixedTemplateService
  └── DiagnosticFixedTemplateService  ← 新增
```

### 覆盖点

```javascript
class DiagnosticFixedTemplateService extends InspectionFixedTemplateService {
  constructor(options)           // 指向 templates/diagnostic/
  buildContext(report)           // 构建 fault + alertAnalysis + trafficAnalysis + businessAnalysis + packetAnalysis 上下文
  buildRowsForSection(s, ctx)    // 12 个诊断专用 rowBuilder + 回退 super
  renderNarrative(s, ctx)        // AND/OR 条件评估 + 覆盖内联 buildHeading
  preRenderCharts(t, ctx)        // 跳过 condition=false 的 chartSlot
  buildChildren(r, bufs)         // 过滤 condition=false 的 section
  renderDocx(report)             // 完整文档管线
}
```

### 复用的父类能力

未覆盖以下方法，完全依赖父类实现：
- `renderSection()`, `renderCover()`, `renderToc()`, `renderParagraphs()`
- `renderStaticTable()`, `renderKeyValueTable()`, `renderTableSection()`
- `renderDataParagraphs()`, `renderChartSlot()`
- `buildEChartsOption()`, `renderChartPngBuffer()` — NAPM 色系图表管线
- JSZip 后处理（Heading1Char/Heading2Char）
- `loadTemplate()`, `loadNarrativeRules()`, `loadChartSpecs()` — JSON 模板缓存

### Row Builder 分发

```javascript
buildRowsForSection(section, context) {
  switch (section.rowBuilder) {
    case 'faultBasicInfo':      return ...  // fault + timeRange
    case 'faultTimeline':       return ...  // fault.timeline[]
    case 'healthSummary':       return ...  // 综合各域评估
    case 'alertCategoryStats':  return ...  // alertAnalysis.summary.byCategory[]
    case 'alertDetails':        return ...  // alertAnalysis.summary.unresolvedAlerts[]
    case 'trafficAnomalies':    return ...  // trafficAnalysis.anomalies[]
    case 'trafficTopIPs':       return ...  // trafficAnalysis.topIPs[]
    case 'businessSlowTable':   return ...  // businessAnalysis.slowAccess[]
    case 'businessErrorTable':  return ...  // businessAnalysis.httpErrors[]
    case 'packetProtocol':      return ...  // packetAnalysis.protocolHierarchy[]
    case 'packetEndpoints':     return ...  // packetAnalysis.endpoints[]
    case 'packetConversations': return ...  // packetAnalysis.conversations[]
    default: return super.buildRowsForSection(section, context)
  }
}
```

## 五、叙述规则

### 条件语法

支持以下条件类型（优先级从高到低）：

1. **exists / empty** — `"packetAnalysis exists"` / `"fault.timeline empty"`
2. **比较** — `==`, `!=`, `>`, `>=`, `<`, `<=`
3. **AND** — `"A > 3 AND B.length > 0"`
4. **OR** — `"A > 3 OR B > 0"`
5. **truthy** — 直接路径查找
6. **default** — 无条件回退

### 规则组示例

**fault.overview**（按严重级别）:
```
severity == critical  → "⚠ 严重故障：...需立即处理"
severity == major     → "⚠ 重大故障：...需尽快排查"
severity == minor     → "轻微故障：...建议安排排查"
default               → "故障分析报告已生成..."
```

**traffic.conclusion**（AND 组合）:
```
anomalies.length > 0 AND overallStatus == critical
  → "流量在 14:05 出现显著异常：...，与告警时间高度吻合"
missingPointCount > 0 → "存在 N 个缺失点..."
default               → "流量详情见上方趋势图..."
```

**root_cause**（综合判断）:
```
critical > 3 AND anomalies.length > 0
  → "综合判断：故障根因大概率与...相关，建议优先排查..."
overallStatus == critical → "综合判断：故障级别为严重..."
anomalies.length > 0      → "综合判断：故障主要表现为流量异常..."
default                   → "建议结合以上各维度数据进一步分析..."
```

## 六、图表

### 规格定义

所有图表继承 NAPM 全局色板（12 色霓虹循环）和 NAPM 样式常量：

```javascript
NAPM_COLOR_PALETTE = ['#2fe74e','#fdf756','#2ec8e5','#2e8ae6','#a830e5','#e74d2e', ...]
NAPM_STYLE = { chartWidth: 620, chartHeight: 360, fontFamily: 'WenQuanYi Micro Hei, Microsoft YaHei, ...' }
```

### 图表详情

| chartId | chartType | 数据路径 | 系列 | 无数据行为 |
|---------|-----------|---------|------|-----------|
| `alert.timeline` | line | `alertAnalysis.timeline` | critical_total, major_total, minor_total | 跳过渲染 |
| `traffic.trend` | line | `trafficAnalysis.trend.dataset` | TPIO, TPI, TPO | 跳过渲染 |
| `traffic.topIPs` | bar | `trafficAnalysis.topIPs` | TPIO, TPI, TPO | 条件隐藏 |
| `business.slowAccess` | bar | `businessAnalysis.slowAccess` | slowCount, avgPageDelayMs | 跳过渲染 |
| `business.httpErrors` | bar | `businessAnalysis.httpErrors` | http400, http500 | 跳过渲染 |

### 图表预渲染优化

`preRenderCharts()` 在数据点数为 0 时**跳过渲染**（不生成空白 PNG），回退到静态 key-value 表格展示图表元信息。

## 七、集成与路由

### 触发路径

```
用户触发 (OpenClaw)
  → openclaw-napm-fault-diagnosis (数据采集，待建)
  → 产出 reportData: { reportType: "diagnostic_report", templateId: "napm_fault_diagnosis_v1", ... }
  → ReportInputContractService.normalizeReportInput()
  → ReportGenerationService.generate()
  → ReportTemplateService.renderDocx()
  → if (reportType === 'diagnostic_report') → renderDiagnosticDocx()
  → DiagnosticFixedTemplateService.renderDocx()
  → 产出 .docx 文件
```

### 路由逻辑

```javascript
// ReportTemplateService.renderDocx(report)
if (report.reportType === 'inspection_report' || report.templateId === 'napm_traffic_health_inspection_v1')
  → renderInspectionDocx()
else if (report.reportType === 'summary_report' || report.templateId === 'napm_summary_overview_v1')
  → renderSummaryDocx()
else if (report.reportType === 'diagnostic_report' || report.templateId === 'napm_fault_diagnosis_v1')
  → renderDiagnosticDocx()   // ← 新增
else
  → 通用渲染管线 (quick_report, comparative_report, operation_report)
```

### 向后兼容

- 不传 `templateId` 且仅含 `sections` 的 `diagnostic_report` 仍走通用渲染（保持现有行为）
- 传 `templateId: "napm_fault_diagnosis_v1"` 或 `reportType: "diagnostic_report"` + 新数据字段时触发固定模板
