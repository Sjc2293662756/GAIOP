# NAPM 统一自动时间粒度规则

日期：2026-09-02

## 目标规则

所有需要根据查询跨度自动选择 `timeValues.granularity` 的运行时模块统一使用以下规则：

| 查询跨度 `t` | 自动粒度 |
| --- | ---: |
| 无效、缺失或 `t <= 6小时` | `60` 秒（1 分钟） |
| `6小时 < t <= 3天` | `300` 秒（5 分钟） |
| `3天 < t < 3,600,000秒` | `3600` 秒（1 小时） |
| `t >= 3,600,000秒` | `86400` 秒（1 天） |

原始需求中 `30天` 到 `3,600,000秒`（约 41.67 天）未明确给出单独粒度。为保证规则连续，该区间沿用 1 小时粒度。精确边界按上表处理：6 小时仍为 1 分钟，3 天仍为 5 分钟，3,600,000 秒开始为 1 天。

## 唯一实现

共享实现位于 `skills/shared/TimeGranularityPolicy.js`，由以下自动选择入口共同调用：

- 普通 `timeValues` 查询的运行时归一化与元数据约束；
- 巡检报告流量查询；
- 综述报告查询计划与 SummaryClient 兜底；
- 故障诊断查询。

巡检目录中的旧兼容实现也调用同一策略，避免历史入口继续保留固定的日窗口小时粒度。

合法的显式请求粒度不被自动策略覆盖。后端返回合法 `raw.granularity` 时，报告时间轴继续使用响应粒度，并保留请求粒度、实际粒度及不一致证据。

报告侧不得为了压缩图表点数改变时序数据粒度。年度等长窗口在取得日粒度数据后继续按日展示；图表通过横轴标签自动抽稀和重叠隐藏控制密度，不再生成额外的周粒度。

## 时间窗口与粒度的计算链路

自动粒度只依赖最终的查询跨度，不直接依赖“日报”、“月报”、“季报”或“年报”等报告名称。运行时按以下顺序处理：

1. 解析用户时间表达，得到滚动窗口、自然窗口或自定义窗口。
2. 由服务端生成 Unix 秒级 `start/end`，并向下对齐到分钟。
3. 自然月、自然季度和自然年使用 `Asia/Shanghai` 本地边界，不依赖 Node 进程时区。
4. 计算 `t = end - start`，再调用 `TimeGranularityPolicy` 选择请求粒度。
5. 调用 NAPM `timeValues` 后，如果响应携带合法实际粒度，以响应粒度生成图表横轴。
6. 在查询证据中分别记录请求粒度、实际粒度、有效粒度及不一致状态。

因此，同一种报告类型可以因为用户选择的时间范围不同而使用不同粒度；同一个“本季度”请求在季度初和季度末也可能因实际跨度不同而选中不同粒度。

## 巡检报告时间表达映射

以下映射已贯通自动巡检的“用户原句 -> 工具参数 -> 主窗口/业务窗口 -> 自动粒度”链路：

| 用户表达 | 标准窗口 | 窗口类型 |
| --- | --- | --- |
| 最近/过去/近一个月 | 最近 30 天 | 滚动 |
| 最近/过去/近三个月 | 最近 90 天 | 滚动 |
| 最近 12 个月 | 最近 365 天 | 滚动 |
| 其他最近 N 个月（`1 <= N <= 33`） | `N * 30` 天 | 滚动 |
| 本月/上个月 | 当前/上一自然月 | 自然日历 |
| 本季度/上一季度 | 当前/上一自然季度 | 自然日历 |
| 最近一个季度 | 最近 90 天 | 滚动 |
| 最近一年 | 最近 365 天 | 滚动 |
| 今年/去年 | 当前/上一自然年 | 自然日历 |
| `YYYY年M月` | 指定自然月 | 自定义固定边界 |
| `YYYY年第N季度` | 指定自然季度 | 自定义固定边界 |
| `YYYY年` | 指定自然年 | 自定义固定边界 |

指定自然时间段尚未结束时，`end` 截止到当前分钟；已结束时，`end` 为下一个时间段开始前 1 分钟。未到来的自然时间段、非法季度或其他明确但无法解析的时间表达会返回 `INSPECTION_TIME_RANGE_UNRECOGNIZED`，不得静默回退到最近 1 小时。

用户完全未提供时间范围时，不属于解析失败：巡检主流量默认最近 1 小时，辅助流量为最近 1 天，业务性能默认最近 7 天。

## 典型窗口的粒度结果

| 请求窗口 | 典型跨度 | 自动请求粒度 | 预计点数 |
| --- | ---: | ---: | ---: |
| 最近 1 小时 | 3600 秒 | 60 秒 | 约 60 |
| 最近 1 天 | 86400 秒 | 300 秒 | 约 288 |
| 最近 7 天 | 604800 秒 | 3600 秒 | 约 168 |
| 最近一个月 | 2592000 秒 | 3600 秒 | 约 720 |
| 最近一个季度 | 7776000 秒 | 86400 秒 | 约 90 |
| 2026 年第一季度 | 2026-01-01 00:00 至 2026-03-31 23:59 | 86400 秒 | 约 90 |
| 最近一年 | 31536000 秒 | 86400 秒 | 约 365 |

自然月、当前季度和当前年的实际跨度会随报告生成时刻变化，必须使用实际 `start/end` 重新计算，不能因为名称中包含“月”、“季度”或“年”就强制使用固定粒度。

## 巡检主窗口与辅助窗口

- 用户选择的窗口是 `primaryWindow`，同时作为巡检报告和业务性能聚合的主时间口径。
- 当主窗口跨度大于 1 天时，报告另行查询截止时最近 1 天和最近 1 小时的辅助流量窗口。
- 每个流量窗口按自身的 `start/end` 独立选择粒度：例如月度主图使用 3600 秒，辅助最近 1 天使用 300 秒，辅助最近 1 小时使用 60 秒。
- 业务性能部分使用 `topValues` 聚合，共用用户选择的时间窗口，但不使用 `timeValues.granularity`。
- 主窗口和辅助窗口是包含关系，不是互相冲突的报告口径；报告标题必须明确区分用户主窗口和“报告截止时”辅助窗口。
