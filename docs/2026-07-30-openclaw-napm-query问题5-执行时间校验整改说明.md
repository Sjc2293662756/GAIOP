# openclaw-napm-query 问题 5：执行时间校验整改说明

日期：2026-07-30  
状态：本地整改和回归已完成。

## 问题与影响

`QueryValidator` 原先只在时间可以转换为有限数字时继续检查，导致非数字、零值、负数、相等时间和小数时间戳可能绕过校验并进入 NAPM 请求。

## 最终校验规则

执行态 `start/end` 必须同时满足：

- 两者均存在。
- 是有限的正整数 Unix 秒。
- `end > start`。
- 两者均按 60 秒分钟边界对齐。

任一条件不满足时必须在调用 NAPM 前失败。

## 修改内容

- `QueryValidator` 显式区分字段存在性和数值有效性。
- 增加正整数、顺序和分钟对齐校验。
- 错误详情只记录安全的查询摘要，不记录对象参数值。
- 插件执行阶段继续执行同类结构化校验，防止 direct Tool 调用绕过。

## 回归验证

`test/query-validator-time-contract.test.js` 覆盖：

- 非数字字符串。
- 负数与零时间戳。
- 小数时间戳。
- 相等和反向区间。
- 非分钟对齐区间。
- 合法正整数分钟区间。

全量 Jest：73 个 suite、496 个测试全部通过。

## 验收结论

CLI、内部调用和 Tool 执行链均不能把非法执行时间发送到 NAPM。
