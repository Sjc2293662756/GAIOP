## 结论

`napm-openclaw-plugin.remote.with-comments.js` 不在当前 OpenClaw 加载链中，远端运行环境也不存在该文件。该文件已从本地项目根目录移出并归档，不影响生产插件。

`openclaw.plugin.json` 是 OpenClaw 加载 NAPM 插件时使用的必要 manifest，不能清理。它负责声明插件 ID、激活能力、配置校验规则和允许注册的工具契约。诊断确认其 7 个生产工具契约正确，但存在一个失效配置字段和两个遗漏的可选开发诊断工具契约，现已在本地修复。

## 运行链确认

远端 OpenClaw Gateway 的插件加载链为：

```text
OpenClaw Gateway
  -> extensions/napm-openclaw-plugin/index.mjs
  -> index.js（不存在时回退）
  -> napm-openclaw-plugin.remote.js
  -> openclaw.plugin.json 合约校验
  -> 注册生产工具和消息 Hook
```

当前正式插件通过同进程动态 `require()` 调用各 Skill 的 `handleSkillCall()`，不再使用旧注释文件中的 Node 子进程执行模式。正式插件和 7 个 Skill 入口脚本的远端哈希与诊断时的本地文件一致。

## Manifest 的作用

`openclaw.plugin.json` 当前承担以下职责：

1. 使用 `id=napm-openclaw-plugin` 标识插件。
2. 声明插件需要 `tool` 和 `hook` 两类能力。
3. 使用 `configSchema` 约束插件配置。
4. 使用 `contracts.tools` 声明允许插件注册的工具名。

OpenClaw 在 `registerTool()` 时执行单向校验：插件实际注册的工具必须出现在 `contracts.tools` 中；manifest 可以提前声明当前未启用的可选工具。未声明的工具会被拒绝注册，而不只是输出普通告警。

## 已发现问题

### 遗留的 `gatewayBaseUrl` 配置

manifest 原先暴露 `gatewayBaseUrl`，但当前正式插件没有任何活动调用使用该配置。远端插件配置也没有设置该字段。继续保留会让维护人员误以为当前查询仍经过旧 Gateway Base URL。

处理：保留必要的空对象 `configSchema`，移除 `gatewayBaseUrl` 属性。

### 开发诊断工具缺少契约

当 `NAPM_ENABLE_DEV_RESOLVER_TOOLS=true` 时，插件会额外注册：

- `napm-resolve-query`
- `napm-mainflow-query`

原 manifest 未声明这两个工具，导致开发开关即使启用，OpenClaw 仍会拒绝注册它们。生产环境没有配置该开关，因此现有 7 个生产工具未受影响。

处理：将两个诊断工具加入 `contracts.tools`。生产环境仍只注册 7 个工具；开发模式可注册全部 9 个工具。
