# 2026-05-08 企业微信边界引导改为动态系统示例说明

## 一、问题背景

企业微信侧在命中边界拦截或技能前置拒绝时，会返回一段固定引导语：

- `239web最近异常吗`
- `某系统今天比昨天差吗`
- `这个监控结果怎么理解`

这段话存在两个明显问题：

1. 示例写死为 `239web`，不适用于所有现场。
2. 引导内容和当前系统实际对象脱节，用户容易觉得回复“像模板话术”。

本次修改的目标是：

- 保留边界拒绝能力；
- 但把引导示例改成“基于当前系统真实应用/业务组动态生成”；
- 拿不到元数据时，再降级为通用说法，不再写死 `239web`。

## 二、修改位置

本次修改的是远端运行中的企业微信插件产物：

- `/home/netinside/.openclaw/extensions/wecom-openclaw-plugin/dist/index.cjs.js`
- `/home/netinside/.openclaw/extensions/wecom-openclaw-plugin/dist/index.esm.js`

说明：

- 这里是企微真实运行链路使用的插件文件。
- 不是仅修改本地仓库源码就会立刻生效。

## 三、具体改动

### 1. 新增动态引导示例缓存

新增了轻量缓存：

- `NAPM_BOUNDARY_GUIDE_CACHE_TTL_MS = 5 * 60 * 1000`
- `napmBoundaryGuideExamplesCache`

作用：

- 避免每次命中边界都重复查一次应用/业务组元数据；
- 5 分钟内复用一次最近查询结果。

### 2. 新增动态示例装配逻辑

新增了以下函数：

- `pickNapmGuideName(items, fallback)`
- `normalizeNapmGuideItems(skillResult)`
- `loadNapmBoundaryGuideExamples(runtime)`

逻辑说明：

1. 通过插件里现有的 `requestNapmSkillQuery(...)` 调用 NAPM skill；
2. 分别查询：
   - `WebApplication`
   - `BusinessGroup`
3. 从返回结果中提取真实对象名；
4. 生成动态示例：
   - `<真实应用名>最近异常吗`
   - `<真实业务组名>今天比昨天差吗`
   - `这个监控结果怎么理解`

### 3. 改造边界回复函数

以下函数已从固定文本改为动态文本：

- `buildWeComGeneralBoundaryReply(runtime)`
- `buildWeComSystemBoundaryReply(runtime)`

原来是同步固定字符串；
现在是异步查询当前系统对象后再拼接引导语。

### 4. 调整调用点

原来的调用方式：

```js
buildWeComGeneralBoundaryReply()
buildWeComSystemBoundaryReply()
```

现已改为：

```js
await buildWeComGeneralBoundaryReply(runtime)
await buildWeComSystemBoundaryReply(runtime)
```

这样边界命中时才能等待动态示例加载完成。

## 四、降级策略

如果运行时暂时拿不到元数据，不会报错中断主流程，而是自动降级为：

- `某个应用最近异常吗`
- `某个业务组今天比昨天差吗`

这样即使元数据接口偶发失败，也不会再出现固定 `239web` 的问题。

## 五、远端部署情况

本次已完成：

1. 将补丁后的 `index.cjs.js`、`index.esm.js` 回传到远端插件目录；
2. 重启真实运行服务：
   - `systemctl --user restart openclaw-gateway.service`
3. 验证网关恢复正常：
   - `openclaw-gateway.service` 已重新启动
   - 网关监听正常
   - 企业微信 WebSocket 重新认证成功

## 六、特别说明

本次只解决“边界引导语写死示例”的问题。

它不等于：

- 重新把企微插件改回本地语义主判定；
- 也不等于让企微插件重新接管 OpenClaw 的主理解链。

当前仍保持既定方向：

- OpenClaw 主链负责主要理解与调度；
- 企微插件仅保留必要的边界兜底与敏感信息拦截；
- 边界兜底中的引导语，改为动态贴合当前系统对象。

## 七、当前效果预期

后续再命中这类边界回复时，引导语应优先表现为类似：

- `可观测239web最近异常吗`
- `服务器网段今天比昨天差吗`
- `这个监控结果怎么理解`

如果现场元数据暂时取不到，则会退化为：

- `某个应用最近异常吗`
- `某个业务组今天比昨天差吗`

不会再固定出现 `239web最近异常吗` 这一条模板话术。
