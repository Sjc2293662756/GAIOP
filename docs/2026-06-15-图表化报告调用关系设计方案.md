# 图表化报告调用关系设计方案

日期：2026-06-15

## 1. 设计结论

生成带图报告时，采用三段式流水线：

```text
openclaw-napm-query / openclaw-napm-packet-analysis
  -> echarts-chart-skill
  -> openclaw-napm-report
```

核心原则：

- 查询或数据包 skill 负责产出结构化数据。
- `echarts-chart-skill` 负责把结构化数据转换成图表资源。
- `openclaw-napm-report` 只负责消费已经生成好的图表资源，并把它嵌入 docx。
- OpenClaw 或插件编排层负责串联多个 skill，不把跨 skill 流程塞进某一个业务 skill。

换句话说，图表是报告生成前准备好的 artifact；report skill 不理解“应该画什么图”，也不直接调用 ECharts。

## 2. 背景与目标

当前项目已有三个核心能力边界：

- `openclaw-napm-query`：负责 NAPM 指标、清单、排行、趋势、综合分析等结构化查询。
- `openclaw-napm-packet-analysis`：负责数据包预览、下载、分析。
- `openclaw-napm-report`：负责把结构化 `reportData` 转成 docx 报告。

新增 `echarts-chart-skill` 后，需要支持“查询结果生成报告时自动插入图表”，但不能破坏现有 report skill 的纯 artifact generator 边界。

目标：

- 让报告支持图表 section。
- 让图表生成过程可审计、可复用、可降级。
- 让 query、packet、chart、report 四类能力边界清晰。
- 支持后续扩展更多图表类型，而不反复改 report 生成主链路。

非目标：

- 不让 report skill 直接查询 NAPM。
- 不让 report skill 自己做自然语言理解或图表推荐。
- 不让 query skill 直接生成 Word。
- 不在 PDF 尚未支持时假装生成 PDF。

## 3. 推荐调用时序

### 3.1 查询加带图报告

```text
用户：
  查询最近一天响应时间趋势，并生成带图报告

OpenClaw / 插件编排层：
  1. 判断这是“数据查询 + 报告导出 + 需要图表”的复合请求。
  2. 调用 openclaw-napm-query，得到 queryResult / reportData。
  3. 从 queryResult 或 reportData.sections 中提取适合可视化的数据。
  4. 构造 ChartRequest。
  5. 调用 echarts-chart-skill 生成 option、html、svg 或 png。
  6. 把图表 artifact 注入 reportData.sections。
  7. 调用 openclaw-napm-report 生成 docx。
  8. 返回报告文件路径、下载链接和必要的降级说明。
```

### 3.2 数据包分析加带图报告

```text
用户：
  分析 101.254.114.238 最近一小时的数据包，并生成带图报告

OpenClaw / 插件编排层：
  1. 调用 openclaw-napm-packet-analysis。
  2. 将 packet result 转成 reportData.sections。
  3. 对协议分布、Top endpoints、Top conversations 等结构化数据构造 ChartRequest。
  4. 调用 echarts-chart-skill 生成图表 artifact。
  5. 把图表 artifact 注入 reportData.sections。
  6. 调用 openclaw-napm-report 生成 docx。
```

### 3.3 后续“把以上生成带图报告”

```text
用户：
  把以上结果生成带图报告

OpenClaw / 插件编排层：
  1. 复用最近一次有效 queryResult / packetResult / reportData。
  2. 若最近结果已有 chart artifacts 且仍可访问，直接复用。
  3. 若没有 chart artifacts，但有可视化数据，则补跑 echarts-chart-skill。
  4. 调用 openclaw-napm-report。
```

## 4. 模块职责

### 4.1 OpenClaw / 插件编排层

编排层是跨 skill 工作流的 owner。

职责：

- 判断用户是否要求报告。
- 判断报告是否需要图表。
- 决定先调用 query skill 还是 packet skill。
- 将源结果转换成 `reportData`。
- 将源数据转换成 `ChartRequest`。
- 调用 `echarts-chart-skill` 生成图表资源。
- 将图表 artifact 注入 `reportData.sections`。
- 调用 `openclaw-napm-report`。
- 处理图表失败时的降级策略。
- 保留跨 skill audit trace。

建议新增服务：

```text
ChartReportOrchestratorService
```

可放在插件层或未来 workflow 层，避免污染 query、packet、report 三个 skill。

### 4.2 openclaw-napm-query

职责：

- 执行 NAPM 查询。
- 返回结构化结果。
- 尽量产出可转报告的 `reportData`。
- 可选产出 `visualizationHints`，提示编排层哪些数据适合画图。

不负责：

- 不生成图片。
- 不生成 Word。
- 不直接调用 `echarts-chart-skill`。

### 4.3 openclaw-napm-packet-analysis

职责：

- 完成数据包预览、下载、分析。
- 返回协议分布、端点、会话、DNS、HTTP、TLS 等结构化分析结果。
- 可选产出 `visualizationHints`。

不负责：

- 不生成 Word。
- 不直接嵌图。

### 4.4 echarts-chart-skill

职责：

- 接收 `ChartRequest`。
- 推荐或确定图表类型。
- 生成 ECharts option。
- 输出 HTML/SVG/PNG 等图表 artifact。
- 返回图表文件路径、尺寸、mimeType、option 路径、预览路径。

不负责：

- 不查询 NAPM。
- 不理解 NAPM 领域边界。
- 不生成报告。

### 4.5 openclaw-napm-report

职责：

- 校验 `reportData`。
- 识别 `summary`、`table`、`finding`、`analysis`、`recommendation`、`metadata`、`chart` 等 section。
- 对 `chart` section 只读取并嵌入已有图片。
- 生成 docx 和 audit JSON。

不负责：

- 不调用 ECharts。
- 不做图表推荐。
- 不从 rows 推断 chartType。
- 不查询 NAPM。

## 5. 数据契约设计

### 5.1 visualizationHints

`visualizationHints` 是源 skill 给编排层的可选提示，不是 report skill 的输入必需项。

示例：

```json
{
  "visualizationHints": [
    {
      "id": "response-time-trend",
      "title": "响应时间趋势",
      "sourceSectionId": "time-series-table",
      "goal": "trend",
      "chartType": "line",
      "datasetPath": "narrationInput.result.series",
      "xField": "time",
      "yField": "responseTime",
      "series": [
        { "name": "响应时间", "field": "responseTime" }
      ],
      "width": 960,
      "height": 540
    }
  ]
}
```

设计要点：

- `visualizationHints` 只描述“怎么画”，不保存最终图片。
- 如果没有 hint，编排层可根据 query service 做保守默认映射。
- hint 不应该成为 query 执行成功的必要条件。

### 5.2 ChartRequest

编排层调用 `echarts-chart-skill` 时使用 `ChartRequest`。

示例：

```json
{
  "title": "响应时间趋势",
  "chartType": "line",
  "goal": "trend",
  "dataset": [
    { "time": "10:00", "responseTime": 32 },
    { "time": "10:05", "responseTime": 45 }
  ],
  "xField": "time",
  "yField": "responseTime",
  "series": [
    { "name": "响应时间", "field": "responseTime" }
  ],
  "width": 960,
  "height": 540
}
```

常见映射：

| 查询类型 | goal | 推荐图表 |
| --- | --- | --- |
| `timeValues` / 趋势 | `trend` | `line` |
| `topValues` / 排行 | `comparison` | `bar` |
| 占比 / 协议分布 | `composition` | `pie` |
| 多指标对比 | `comparison` | `bar` 或 `line` |
| 会话流向 | `flow` | `sankey` |
| 端点关系 | `relationship` | `graph` |

### 5.3 ChartArtifact

`echarts-chart-skill` 返回图表 artifact。

推荐结构：

```json
{
  "ok": true,
  "chartId": "chart-response-time-trend-001",
  "kind": "echarts",
  "title": "响应时间趋势",
  "imagePath": "/home/netinside/.openclaw/reports/assets/napm-diagnostic-report-xxx/chart-001.png",
  "svgPath": "/home/netinside/.openclaw/reports/assets/napm-diagnostic-report-xxx/chart-001.svg",
  "htmlPath": "/home/netinside/.openclaw/reports/assets/napm-diagnostic-report-xxx/chart-001.html",
  "optionPath": "/home/netinside/.openclaw/reports/assets/napm-diagnostic-report-xxx/chart-001.option.json",
  "mimeType": "image/png",
  "width": 960,
  "height": 540,
  "generatedAt": "2026-06-15T16:30:00.000+08:00"
}
```

### 5.4 reportData chart section

编排层将 `ChartArtifact` 注入 `reportData.sections`：

```json
{
  "type": "chart",
  "title": "响应时间趋势",
  "content": "最近一天服务器响应时间存在明显波动。",
  "chart": {
    "kind": "echarts",
    "chartId": "chart-response-time-trend-001",
    "title": "响应时间趋势",
    "imagePath": "/home/netinside/.openclaw/reports/assets/napm-diagnostic-report-xxx/chart-001.png",
    "svgPath": "/home/netinside/.openclaw/reports/assets/napm-diagnostic-report-xxx/chart-001.svg",
    "htmlPath": "/home/netinside/.openclaw/reports/assets/napm-diagnostic-report-xxx/chart-001.html",
    "optionPath": "/home/netinside/.openclaw/reports/assets/napm-diagnostic-report-xxx/chart-001.option.json",
    "mimeType": "image/png",
    "width": 960,
    "height": 540,
    "caption": "数据来源：NAPM timeValues 查询结果"
  }
}
```

report skill 只依赖：

- `section.type = "chart"`
- `section.chart.imagePath`
- `section.chart.mimeType`
- `section.chart.width`
- `section.chart.height`
- `section.chart.caption`

`svgPath`、`htmlPath`、`optionPath` 主要用于审计和预览。

## 6. 图表文件存储

推荐目录：

```text
skills/openclaw-napm-report/output/assets/{reportId}/
```

示例：

```text
skills/openclaw-napm-report/output/
  napm-diagnostic_report-20260615-163000-a1b2c3.docx
  napm-diagnostic_report-20260615-163000-a1b2c3.json
  assets/
    napm-diagnostic_report-20260615-163000-a1b2c3/
      chart-001.option.json
      chart-001.html
      chart-001.svg
      chart-001.png
```

设计理由：

- 图表资源和报告 audit 同生命周期。
- report audit 可以记录所有图表 artifact。
- 后续清理报告时可以一起清理 assets。
- 不需要 report skill 到处找临时文件。

## 7. 图片格式策略

当前 `echarts-chart-skill` 已支持：

- HTML
- SVG

Word 报告长期建议使用 PNG：

- docx 对 PNG 兼容性最好。
- SVG 在不同 Word/WPS/LibreOffice 环境下兼容性不稳定。
- HTML 适合预览，不适合直接嵌入 docx。

推荐阶段：

```text
阶段 1：
  支持 SVG 产出和 HTML 预览，reportData 记录 chart artifact。
  若 report 嵌图能力尚未完成，报告可先显示图表预览路径。

阶段 2：
  echarts-chart-skill 增加 PNG 输出。
  openclaw-napm-report 使用 PNG 嵌入 docx。

阶段 3：
  同时保留 PNG、SVG、HTML、option.json。
  PNG 用于 docx，HTML 用于浏览器预览，option.json 用于审计和复现。
```

PNG 生成方案：

```text
优先方案：
  ECharts HTML -> headless browser screenshot -> PNG

备选方案：
  ECharts SVG -> SVG to PNG 转换
```

## 8. 降级与失败策略

### 8.1 图表失败不阻断报告

默认策略：

```text
查询成功、报告可生成、图表失败：
  继续生成报告
  保留文本和表格
  在报告中说明图表生成失败
  audit 中记录失败原因
```

除非用户明确要求“必须包含图表”，否则不要让图表失败导致整个报告失败。

### 8.2 失败 section

```json
{
  "type": "chart",
  "title": "响应时间趋势",
  "chart": {
    "status": "failed",
    "errorCode": "CHART_RENDER_FAILED",
    "message": "图表渲染失败，报告已保留原始数据表。"
  }
}
```

报告展示：

```text
图表生成失败，以下保留原始数据表。
失败原因：CHART_RENDER_FAILED
```

### 8.3 数据不足

如果数据不足以画图：

- 少于 2 个时间点时，不生成趋势图。
- TopN 为空时，不生成排行图。
- 占比数据没有数值字段时，不生成饼图。

编排层应将原因写入 audit：

```json
{
  "chartSkipped": true,
  "reason": "INSUFFICIENT_DATA",
  "hintId": "response-time-trend"
}
```

## 9. 代码改造点

### 9.1 echarts-chart-skill

建议新增或完善：

```text
scripts/render_chart_artifact.js
```

职责：

- 接收 `ChartRequest`。
- 生成 `option.json`。
- 生成 `preview.html`。
- 生成 `preview.svg`。
- 生成 `preview.png`。
- 返回统一 `ChartArtifact` JSON。

输出示例：

```json
{
  "ok": true,
  "artifact": {
    "chartId": "chart-001",
    "kind": "echarts",
    "imagePath": ".../chart-001.png",
    "htmlPath": ".../chart-001.html",
    "optionPath": ".../chart-001.option.json",
    "mimeType": "image/png",
    "width": 960,
    "height": 540
  }
}
```

### 9.2 插件编排层

建议新增：

```text
ChartReportOrchestratorService
```

核心方法：

```js
async function enrichReportDataWithCharts(reportData, sourceResult, options = {}) {
  // 1. collect visualization hints
  // 2. build ChartRequest
  // 3. call echarts-chart-skill
  // 4. inject chart sections
  // 5. return enriched reportData
}
```

建议输出：

```json
{
  "reportData": {},
  "chartArtifacts": [],
  "chartFailures": [],
  "audit": {}
}
```

### 9.3 openclaw-napm-report

改造文件：

```text
skills/openclaw-napm-report/services/ReportGenerationService.js
skills/openclaw-napm-report/services/ReportTemplateService.js
skills/openclaw-napm-report/references/report-workflow-contract.md
skills/openclaw-napm-report/SKILL.md
```

新增能力：

- `ReportGenerationService.validate` 支持 `section.type === "chart"`。
- `ReportTemplateService` 支持 `ImageRun`。
- contract 文档声明 report skill 只消费 chart artifact。

校验规则：

```text
chart section:
  如果 chart.status = failed，则允许生成降级说明。
  否则必须存在 chart.imagePath。
  mimeType 建议为 image/png。
  width / height 缺失时使用默认尺寸。
```

### 9.4 query / packet skill

可选增强：

- 在 query result 或 reportData.audit 中产出 `visualizationHints`。
- 对典型结果添加稳定 section id，方便 hint 定位数据。
- 不把图表生成逻辑放进 query / packet skill。

## 10. 推荐落地顺序

### 第一阶段：报告支持 chart section

目标：

- report skill 能识别 `section.type = "chart"`。
- 若有图片路径，嵌入 docx。
- 若图表失败，生成降级说明。

涉及：

- `ReportGenerationService.js`
- `ReportTemplateService.js`
- report skill 文档

### 第二阶段：chart skill 输出统一 artifact

目标：

- `echarts-chart-skill` 提供一个统一命令，从 `ChartRequest` 到 `ChartArtifact`。
- 生成 option、html、svg、png。

涉及：

- `echarts-chart-skill` scripts
- `echarts-chart-skill` README / SKILL.md

### 第三阶段：插件编排层串联

目标：

- 新增 `ChartReportOrchestratorService`。
- 对 query 和 packet 结果补图表。
- 把 chart sections 注入 reportData。

涉及：

- 插件主入口
- 编排服务
- 端到端测试

### 第四阶段：source skill 增加 visualizationHints

目标：

- query / packet 输出更稳定的可视化提示。
- 降低编排层猜字段的成本。

涉及：

- query reportData 生成逻辑
- packet reportData 生成逻辑

## 11. 验收场景

### 11.1 趋势报告

输入：

```text
查询最近一天服务器响应时间趋势，并生成带图报告
```

期望：

- 先执行 NAPM 趋势查询。
- 生成折线图。
- Word 报告包含摘要、趋势图、数据表、审计信息。

### 11.2 TopN 报告

输入：

```text
查询最近一天丢包最严重的 5 个 IP，并生成带图报告
```

期望：

- 先执行 TopN 查询。
- 生成柱状图。
- Word 报告包含排行图和排行表。

### 11.3 数据包分析报告

输入：

```text
分析 101.254.114.238 最近一小时的数据包，并生成带图报告
```

期望：

- 先执行 packet analysis。
- 协议分布生成饼图。
- Top endpoints 生成柱状图。
- Word 报告包含 packet 摘要、图表、表格、下载或预览链接。

### 11.4 图表失败降级

输入：

```text
查询最近一天响应时间趋势，并生成带图报告
```

条件：

```text
echarts-chart-skill 渲染失败
```

期望：

- 报告仍然生成。
- 报告中显示图表生成失败说明。
- 原始表格仍然保留。
- audit 记录 `CHART_RENDER_FAILED`。

## 13. 最终边界

最终边界应保持如下：

```text
query skill:
  只关心数据是否查对。

packet skill:
  只关心数据包是否分析对。

chart skill:
  只关心图表 artifact 是否生成对。

report skill:
  只关心 reportData 是否渲染成 docx。

OpenClaw / 插件编排层:
  负责把这些能力串成一次完整用户工作流。
```

这个设计能保证新增图表能力时，不把 report skill 重新变成一个“大而全”的流程控制器，也不会让 query / packet skill 背上报告格式细节。
