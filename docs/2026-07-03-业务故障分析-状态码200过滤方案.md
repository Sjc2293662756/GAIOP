# 业务故障分析 — 状态码 200 过滤方案

> 日期：2026-07-03
> 需求：Step3 页面状态码详情分析中，状态码为 200 的记录不展示，仅展示非 200 状态码

---

## 一、影响范围分析

### 1.1 当前行为

`pageViews` API 返回该页面的**所有访问记录**，包括 HTTP 200（正常）和 非 200（异常）。Step3 表格展示全部记录，导致表格中混入大量正常访问行，干扰异常定位。

示例：
```
开始时间                | 页面 | 客户端IP      | 状态码 | 200 | 400 | 500
2026-07-02 15:31:36    | /    | 66.132.224.233 | 200  | 1   | 0   | 0    ← 正常访问，不应展示
2026-07-02 05:01:43    | /    | 172.245.21.30  | 400  | 0   | 1   | 0    ← 异常，应展示
```

### 1.2 改动点

只需改 **1 处**——`_extractStep3Data` 方法。下拉链：

```
pageViews API 返回 → _extractStep3Data 提取 → rowBuilder 渲染 → 模板表格
                        ↑ 在此过滤
```

| 组件 | 是否需要改 | 原因 |
|------|:--:|------|
| `_extractStep3Data()` — FaultDiagnosisService.js | ✅ 需要 | 在提取每行时过滤 `httpStatus != 200` |
| `buildBsPageDetailsRows()` — BsFaultTemplateService.js | ❌ 不需要 | 只负责格式化，不管过滤 |
| `napm_bs_fault_diagnosis_v2.json` 模板 | ❌ 不需要 | 表格结构不变 |
| `_bsStep3()` — FaultDiagnosisSteps.js | ❌ 不需要 | 查询逻辑不变 |
| `_analyzeBsStep3()` | ❌ 不需要 | 分析逻辑不受影响 |

## 二、实现设计

### 2.1 过滤位置

在 `FaultDiagnosisService._extractStep3Data()` 的第 2 层循环中，添加一行过滤条件：

```javascript
// 当前代码
for (const r of rows) {
  allVisits.push({
    startTime: r.startTime || '-',
    page: r.page || key.replace('pageDetail_', ''),
    clientIp: r.clientIp || '-',
    httpStatus: r.httpStatus ?? '-',
    ...
  });
}

// 过滤后
for (const r of rows) {
  if (String(r.httpStatus) === '200') continue;  // ← 跳过 200
  allVisits.push({ ... });
}
```

### 2.2 过滤条件

| 状态码 | 是否展示 | 理由 |
|:--:|:--:|------|
| 200 | ❌ 不展示 | 正常访问，不干扰异常定位 |
| 301/302 | ✅ 展示 | 重定向，可能涉及配置问题 |
| 400 | ✅ 展示 | 客户端错误 |
| 404 | ✅ 展示 | 路径不存在，可能是扫描 |
| 500/502/503 | ✅ 展示 | 服务端错误 |

过滤逻辑：`String(r.httpStatus) !== '200'`——只跳过 200，其他全部展示。

### 2.3 边界情况

| 场景 | 处理 |
|------|------|
| 某页面所有访问都是 200 | Step3 该页面无数据行——`pageDetails` 中该页面不出现 |
| `httpStatus` 为空/null/undefined | 保留展示（可能的数据异常需要被看见） |
| pageViews 返回空数组 | 已有空数据处理——不进入循环 |

---

## 三、对 Step3 分析提示的影响

Step3 的 `_analyzeBsStep3` 仍分析**原始数据**（不过滤 200），因为分析需要看到全貌——200 占比高说明大部分访问正常，这也是有价值的判断信息。

模板中的"分析提示"（`dataParagraphs: diagnosis.step3Hints`）继续基于完整数据分析生成，不受表格过滤影响。

表格和提示分工：
- **表格**：只展示异常（非 200）→ 帮助快速定位
- **分析提示**：基于全量数据判断 → 给出准确结论
