# “单个业务分析报告”未发送附件根因与修复方案

## 1. 问题现象

企业微信请求：

```text
生成回溯238web的单个业务分析报告
```

助手只回复“报告已生成……完整报告将以附件形式发送”，但用户没有收到 Word 附件。

## 2. 远端日志证据

测试服务器同一请求（`2026-08-21 10:43:41`，reqId 已在服务器日志中关联）显示：

1. 模型先尝试调用 `napm-fault-diagnosis`，被插件门禁拦截。
2. 模型随后尝试调用 `napm-report-export`，仍未形成有效报告源。
3. 最终文本声称报告已生成，但没有 `mediaUrl` 或 `mediaUrls`。
4. 同一时间窗口没有报告上传、上传完成或媒体发送事件。

因此问题不在企业微信附件通道，而在报告工作流没有真正启动；最终文本是模型在工具调用失败后的错误声明。

## 3. 根因

`plugin/ReportIntentClassifier.js` 原先只识别“综述报告、日报、周报”等明确词语。
“单个业务分析报告”不命中任何报告意图，结果为 `none`。`reply_dispatch` 只对
`inspection` 或 `summary` 自动执行报告链路，所以本请求没有进入：

```text
单个业务对象
  -> NapmObjectTargetResolver（从 NAPM 目录确认对象和类型）
  -> napm-summary（带 WebApplication/回溯238web target）
  -> napm-report-export
  -> MEDIA 附件发送
```

同时，模型系统提示中的故障诊断示例使它把“分析报告”自行理解成故障工具，造成错误重试。

## 4. 修复方案

### 4.1 报告意图分类

新增单对象综述模式：

- `单个/指定/某个 + 业务/应用 + 分析报告`
- `单个/指定/某个 + 业务/应用 + 综述分析`
- `业务/应用 + 分析报告`

故障、诊断、报错、根因、页面性能、慢等故障语义不进入该模式，仍由
`napm-fault-diagnosis` 处理。

### 4.2 工具门禁

当请求被判定为 summary 时，只允许 `napm-summary` 和 `napm-report-export`，阻止模型绕行
`napm-fault-diagnosis`、`napm-skill-query` 或其他 NAPM 入口。具体对象仍由
`NapmObjectTargetResolver` 查询实时目录；对象不存在、歧义或目录不可用时失败闭合，不能退化为全局报告。

### 4.3 交付契约

自动链路必须满足：

- `napm-summary` 成功返回 `reportSourceId`；
- `napm-report-export` 成功返回 `filePath`；
- 最终回复 payload 同时包含 `mediaUrl` 和 `mediaUrls`；
- 没有有效报告文件时不得输出“报告已生成”。

## 5. 交付失败闭环（2026-08-24）

上一版修复仍存在一个交付层风险：`napm-summary` 或 `napm-report-export` 可能返回结构不完整的成功结果，模型随后根据成功标志自行生成“报告已生成”，但实际没有可发送文件。该风险与企业微信媒体通道无关，属于插件对工具结果的校验不完整。

自动综述交付现在使用以下硬性契约：

1. `napm-summary.details.ok === true`，且必须返回非空 `reportSourceId`；缺失时不调用导出。
2. `napm-report-export.details.ok === true`，且必须返回非空 `filePath`；缺失时视为导出失败。
3. 成功结果统一填充 `mediaUrl` 和 `mediaUrls`，由统一回复分发器发送真实文件。
4. 任一环节失败时返回确定性的失败结果，不返回 `null`，也不输出“报告已生成”或伪造下载路径。

失败提示统一为：

```text
综述报告生成失败：数据汇总或文档导出未完成，请稍后重试。
```

这样可以把“工具成功”“文件已生成”“附件已发送”三个状态分开，避免模型自由补全交付结论。

## 6. 验证结果

- 报告分类器回归：`生成回溯238web的单个业务分析报告` → `summary`。
- 自动交付集成回归：目标解析为 `WebApplication/回溯238web`，只调用一次 summary 和一次 export，最终携带 Word 媒体。
- 工具门禁回归：同一问法调用 fault diagnosis 被阻止，调用 summary 被允许。
- 定向报告交付测试：36 项通过。
- 全量回归：96 个测试套件、749 项测试全部通过。
- 新增失败闭环回归覆盖：摘要执行失败、摘要缺少成功标志、摘要缺少 `reportSourceId`、导出执行失败、导出成功但缺少 `filePath`。

## 7. 影响范围

本修复只改变“单个业务/应用分析报告”这一报告意图及其错误工具拦截，不改变：

- 真正的业务故障分析报告；
- 应用故障分析报告；
- 巡检报告；
- 全局或维度整体综述；
- 普通 NAPM 查询、告警和数据包分析。
