# 数据包预览风险评估与下载确认方案

## 背景

数据包下载存在明显的资源风险：如果目标链路是高速传输，即使时间窗口只有几分钟，也可能产生非常大的 pcap 文件。直接进入下载和 tshark 分析可能导致：

- 下载耗时过长。
- 磁盘空间被快速占满。
- OpenClaw 任务超时。
- tshark 分析消耗大量 CPU / 内存。
- 用户并不知道本次下载会有多大，无法判断是否应该缩小时间范围。

因此，数据包分析流程必须把 `packetsPreview` 的结果从“仅判断有没有数据”升级为“下载前风险评估”。

## 目标

- 在下载前先调用 `packetsPreview`。
- 从预览结果中提取有用概览信息，例如预计数据包大小、包数量、时间分布、通信双方、流量分布。
- 根据预览结果给出风险等级和建议动作。
- 对超过阈值的任务，不自动下载，先让用户确认或建议缩小时间范围。
- 让 OpenClaw 最终回答能明确告诉用户：当前时间段内大概有多少包、多大、是否建议下载。

## 当前现状

当前 `openclaw-napm-packet-analysis` 已经有 preview gate：

```text
packetQuery
  -> packetsPreview
  -> if preview has data: packetsDown
  -> tshark
```

但现有 `requestPreview()` 主要返回：

```json
{
  "ok": true,
  "empty": false,
  "statusCode": 200,
  "contentType": "...",
  "bytes": 1234,
  "data": "...",
  "urlMasked": "..."
}
```

这里的 `bytes` 是 preview HTTP 响应体大小，不等同于将要下载的 pcap 文件大小。

缺口是：没有把 preview API 返回的数据结构解析成业务可读的下载风险摘要。

## 设计原则

- preview 是下载前的强制安全门。
- preview 摘要必须进入结构化 JSON，不只写在自然语言里。
- 大文件风险由代码判断，不依赖模型自由发挥。
- 阈值可通过环境变量配置。
- 默认保守：超过阈值时不自动下载。
- 用户确认后才允许继续下载。
- 如果 preview 返回字段不稳定，解析器要兼容多种字段名，并保留原始 `data` 供排查。

## 总体流程

```text
用户请求：分析某 IP / 事件 / 区间的数据包
  -> OpenClaw 构造 packetQuery
  -> packet skill 调用 packetsPreview
  -> normalizePreviewOverview()
  -> assessPacketDownloadRisk()
  -> 返回 preview.overview + preview.risk
  -> 如果风险可接受且模式允许下载：继续 packetsDown
  -> 如果风险较高：停止下载，提示用户确认或缩小时间范围
  -> 用户确认后：复用同一 criteria，显式 forceDownload 或 confirmDownload
```

## 字段提取策略

由于 `packetsPreview` 实际返回结构可能随版本变化，解析器不应只依赖一个字段名。

### 数据包数量候选字段

按优先级尝试：

```text
packetCount
packets
packetsCount
packetNum
packetNumber
totalPackets
totalPacketCount
count
num
```

### 数据包大小候选字段

按优先级尝试：

```text
packetBytes
packetSize
packetsSize

totalSize
fileSize
pcapSize
captureSize
bytes
size
```

注意：`response.body.length` 只能表示 preview 响应大小，不应作为预计 pcap 大小。

### 流量/分布候选字段

兼容以下结构：

```text
timeBuckets
timeline
flowDistribution

```

### 通信双方候选字段

兼容以下结构：

```text

flows
```

## 风险等级

建议新增环境变量：

```text
PACKET_PREVIEW_WARN_BYTES=209715200
PACKET_PREVIEW_BLOCK_BYTES=1073741824
PACKET_PREVIEW_WARN_PACKETS=200000
PACKET_PREVIEW_BLOCK_PACKETS=1000000
PACKET_PREVIEW_CONFIRM_DOWNLOAD=true
```

默认阈值：

| 风险等级 | 条件 |
|---|---|
| `low` | 未超过 warn 阈值 |
| `medium` | 超过 warn bytes 或 warn packets |
| `high` | 超过 block bytes 或 block packets |
| `unknown` | preview 有数据，但无法解析大小/包数 |

建议行为：

| 风险等级 | 默认动作 |
|---|---|
| `low` | 可继续下载 |
| `medium` | 建议确认后下载 |
| `high` | 默认不下载，建议缩小时间范围 |
| `unknown` | 默认不下载或只允许用户显式确认后下载 |

## 下载决策

新增决策字段：

```json
{
  "decision": {
    "next_action": "CONFIRM_DOWNLOAD",
    "reason": "PACKET_PREVIEW_RISK_MEDIUM",
    "message": "预览显示预计 256 MB，建议确认后再下载。"
  }
}
```

建议动作枚举：

```text
CONTINUE_DOWNLOAD
CONFIRM_DOWNLOAD
SUGGEST_NARROW_TIME_RANGE
NO_DOWNLOAD
PREVIEW_ONLY
```

## 模式行为调整

### `preview_only`

只返回预览概览和风险评估，不下载。

适合：

- 用户问“有没有包”
- 用户问“先看看数据包多大”
- 大时间范围任务

### `preview_download`

先预览，风险为 `low` 时自动下载。

如果 `medium/high/unknown`：

- 不下载。
- 返回 `CONFIRM_DOWNLOAD` 或 `SUGGEST_NARROW_TIME_RANGE`。

### `preview_download_analyze`

先预览，风险为 `low` 时下载并分析。

如果 `medium/high/unknown`：

- 不下载。
- 不调用 tshark。
- 让用户确认或缩小范围。

### `download_only` / `download_analyze`

默认仍应走 preview gate，除非显式：

```json
{
  "forceDownload": true,
  "previewRiskAccepted": true
}
```

## 用户交互示例

### 风险可接受

```text
预览结果显示：最近一小时有约 8,280 个数据包，预计大小 24 MB，风险较低。
我可以继续下载并分析。
```

### 风险中等

```text
预览结果显示：最近一小时有约 420,000 个数据包，预计大小 650 MB。
这个包比较大，直接下载和分析可能耗时较长。
建议你选择：
1. 确认继续下载
2. 缩小到最近 10 分钟
3. 只查看预览概览
```

### 风险较高

```text
预览结果显示：最近一小时预计超过 4.8 GB，风险较高。
我不会自动下载，建议先缩小时间范围，例如最近 5 分钟或指定异常发生的分钟段。
```

### 预览字段不可解析

```text
预览接口确认当前条件下有数据包，但没有返回可解析的预计大小或包数。
为避免误下载大文件，本轮不自动下载。你可以确认继续下载，或先缩小时间范围。
```

```js
function normalizePreviewOverview(parsed, criteria) {}
function extractNumericByCandidateKeys(value, candidateKeys) {}

function formatBytes(bytes) {}
```

职责：

- 从 preview 返回中提取包数和大小。
- 兼容对象、数组、嵌套对象。
- 提取 top endpoints / conversations / time buckets。
- 保留字段来源，方便排查。

### 2. 新增风险评估器

新增函数：

```js
function assessPacketDownloadRisk(overview, criteria, filePolicy) {}
```

职责：

- 读取阈值环境变量。
- 计算 `low/medium/high/unknown`。
- 给出 `recommendation` 和 `suggestedActions`。

### 3. 修改 `requestPreview()`

当前返回：

```js
{
  ok,
  empty,
  bytes,
  data
}
```

修改后：

```js
{
  ok,
  empty,
  responseBytes,
  data,
  overview,
  risk
}
```

其中：

- `responseBytes` 表示 preview 响应体大小。
- `overview.estimatedBytes` 表示预计下载包大小。

### 4. 修改下载门禁

在 `preview_download` 和 `preview_download_analyze` 中：

```text

  -> 继续下载
否则
  -> 停止下载，返回 decision
```

允许用户显式确认：

```json
{
  "previewRiskAccepted": true
}
```

或：

```json
{
  "forceDownload": true
}
```

### 5. 修改 summary/narrationInput

`summarizePreview()` 增加：

```json
{
  "overview": {},
  "risk": {}
}
```

`buildSummary()` 增加：

```text

```

## OpenClaw 编排要求

OpenClaw 在最终回答时应遵守：

- 不要只说“预览接口返回了数据”。
- 必须展示 preview 中的概览字段。
- 风险不低时，不要声称已经下载。
- 风险不低时，引导用户确认或缩小时间范围。
- 用户说“继续下载”时，复用上一轮 criteria，并设置 `previewRiskAccepted=true`。

## 对业务 DownServlet 链路的影响

普通 `packetsPreview/packetsDown` 链路可以直接通过 preview 做风险评估。

业务 `DownServlet` 链路当前没有等价的 `packetsPreview`。因此建议分两阶段处理：

### 阶段一

业务 `DownServlet` 保持当前逻辑：

```text
businessName -> pageFamilyId -> pageFamilyDetailId -> DownServlet
```

由于没有 preview，下载前应默认提示：

```text
该业务 DownServlet 链路没有 packetsPreview 风险预估，本轮建议先构造链接或让用户确认后下载。
```

### 阶段二

如果后续确认 DownServlet 也能通过某个接口预估大小，则将该接口接入同一套 `overview/risk` 结构。

## 实施步骤

### 第一阶段：只做结构化预览摘要

- 新增 `normalizePreviewOverview()`。
- `requestPreview()` 返回 `overview`。
- `summarizePreview()` 暴露 `overview`。
- 不改变下载行为。

价值：先看真实 preview 返回字段，避免盲目拦截。

### 第二阶段：加入风险等级但不阻断

- 新增 `assessPacketDownloadRisk()`。
- 返回 `preview.risk`。
- final answer 中提示风险。
- 仍不阻断下载。

价值：让用户先看到风险信息。

### 第三阶段：启用下载门禁

- 对 `medium/high/unknown` 阻断自动下载。
- 返回 `CONFIRM_DOWNLOAD` 或 `SUGGEST_NARROW_TIME_RANGE`。
- 支持 `previewRiskAccepted=true` 继续下载。

价值：真正防止误下载超大包。

### 第四阶段：接入会话追问

- 用户说“继续下载”时继承上一轮 packet criteria。
- 设置 `previewRiskAccepted=true`。
- 继续执行 `preview_download` 或 `preview_download_analyze`。

价值：形成完整用户体验。

## 推荐默认策略

建议先实施前三阶段，但第三阶段默认只对 `high/unknown` 阻断，对 `medium` 只提示。

初始配置：

```text
PACKET_PREVIEW_WARN_BYTES=209715200
PACKET_PREVIEW_BLOCK_BYTES=1073741824
PACKET_PREVIEW_WARN_PACKETS=200000
PACKET_PREVIEW_BLOCK_PACKETS=1000000
PACKET_PREVIEW_BLOCK_UNKNOWN=true
PACKET_PREVIEW_BLOCK_MEDIUM=false
```

这样不会过度打断用户，但能挡住明显高风险下载。

## 结论

数据包分析应从“有包就下载”升级为：

```text
先预览
  -> 提取包数/大小/分布
  -> 评估风险
  -> 风险可接受才下载
  -> 风险较高则让用户确认或缩小区间
```

这能避免高速链路、小时间窗口、大 pcap 文件造成的下载和分析风险，也能让用户在下载前做明确决策。
