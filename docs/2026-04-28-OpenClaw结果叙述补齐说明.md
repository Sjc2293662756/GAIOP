# OpenClaw结果叙述补齐说明

## 1. 问题背景

当前主链路已经能够正常查到 NAPM 数据，但在 `GATEWAY_FORWARD_DISPLAY_TEXT=false`、`SKILL_FORWARD_DISPLAY_TEXT=false` 的 query-only 模式下，最终回复依赖 OpenClaw 根据机器载荷自行叙述。

原先虽然已经返回了 `narrationInput`，但存在两个问题：

- `narrationInput` 里缺少足够明确的叙述结构，OpenClaw 只能从原始 `rows/structuredRows` 自行摸索。
- skill prompt 只说“优先用 narrationInput”，但没有明确要求“本轮必须产出最终中文回复”。

这会导致一种典型现象：

- 数据已经查到
- `responseMode=machine_narration_input`
- 但 OpenClaw 没有把结果转成最终自然语言

---

## 2. 本次改动

本次改动补齐了统一的 OpenClaw 叙述契约，核心目标是让“查到数据后可叙述”在当前仓库内尽量闭环。

### 2.1 新增统一契约服务

新增文件：

- `skills/openclaw-napm-query/services/OpenClawNarrationContractService.js`

职责：

- 统一生成 `displayText / replyText / responseMode / narrationInput`
- 在 `narrationInput.result` 中补齐 `narrationStructure`
- 在 `narrationInput` 中补齐 `followUp` 与 `renderPolicy`

### 2.2 网关出口统一接入

修改文件：

- `旧 gatewayRoutes 路由入口（现已移除）`

效果：

- `attachReplyContract()` 不再只返回基础 `summary + rows`
- 现在会自动补齐更完整的 OpenClaw 叙述载荷

### 2.3 skill 执行器统一接入

修改文件：

- `skills/openclaw-napm-query/scripts/run_napm_query.js`

效果：

- skill 与网关最终输出使用同一套契约
- 避免网关直调与 skill 调用在叙述字段上出现分叉

### 2.4 agent 提示补强

修改文件：

- `skills/openclaw-napm-query/agents/openai.yaml`
- `skills/openclaw-napm-query/SKILL.md`

新增要求：

- 当 `responseMode=machine_narration_input`
- 且 `narrationInput.narrationRequired=true`
- OpenClaw 必须在当前轮直接生成最终中文回复
- 优先消费 `narrationInput.result.narrationStructure`

---

## 3. 新增载荷重点

当前返回给 OpenClaw 的 `narrationInput` 重点包含：

- `summary`
  - `mode / title / highlights / rowCount / empty`
- `result`
  - `rows / structuredRows / structuredSeries / enrichedRows / compareResult / overview`
  - `narrationStructure`
- `followUp`
  - `prompts`
  - `actions`
- `renderPolicy`
  - 明确要求直接输出最终中文回复
  - 不允许虚构对象、指标、数值、时间、原因、建议

其中 `narrationStructure` 会按结果类型自动生成，例如：

- `topn`
- `trend`
- `overview`
- `compare`
- `metric_list`
- `group_list`
- `query`

---

## 4. 预期效果

改动后，OpenClaw 在看到工具结果时，应该更容易完成这件事：

1. 识别当前是 `machine_narration_input`
2. 读取 `narrationInput.result.narrationStructure`
3. 基于结构化叙述材料直接生成最终中文回复

也就是说，后续重点不再是“有没有数据”，而是“OpenClaw 是否正确消费这份更完整的叙述契约”。

---

## 5. 验证方式

本次已新增测试文件：

- `test/openclaw-narration-contract.test.js`

覆盖点：

- `topValues` 结果能生成 `machine_narration_input + narrationStructure`
- 开启文案透传时仍能保留 `displayText / replyText`

---

## 6. 后续联调建议

如果联调后仍出现“查到数据但不叙述”，优先排查：

1. OpenClaw 是否真的读取 `narrationInput`
2. OpenClaw 是否优先读取 `narrationInput.result.narrationStructure`
3. OpenClaw 是否在 `machine_narration_input` 模式下继续向模型发起最终回复生成
4. 是否被上层框架错误地当成“工具执行已结束，无需继续回答”
