### 4.2 时间覆盖验证

## 七、关键发现与优化建议

### 7.1 关键发现

| # | 发现 | 严重程度 | 详情 |
|---|------|---------|------|
| 1 | **LLM 推理占总耗时 77%** | ⚠️ 中 | LLM 两次推理（工具决策 + 格式化）约 8-9 秒，其中 prefill 约 2.5s 用于处理 16K token 系统上下文 |
| 2 | **Prompt 膨胀严重** | ⚠️ 中 | 系统上下文 + 7 个 Tool 定义 ~16K token/轮，其中 85% 与当前查询无关 |
| 3 | **同进程架构优势明显** | ✅ 好 | Hook+Skill+API 总计 <300ms，节省旧架构 ~730-1,070ms |
| 4 | **NAPM API 服务器时钟偏移 61 天** | ⚠️ 中 | API 服务器显示 `2026-05-08`（应为 `2026-07-08`），API URL 中的 start/end 时间戳可能受影响 |
| 5 | **新架构缺失审计日志** | ⚠️ 低 | 删除 executors 后 `napm_plugin_skill_executor_invoked` 事件不再输出，7/8 查询在 audit.log 中无记录 |
| 6 | **API 调用 `end-start=7200` 而非 3600** | ⚠️ 低 | 虽然 timeRange.key="last1hour"，但实际窗口为 2 小时，可能受 API 时钟偏移影响 |

### 7.2 优化建议（按优先级）

| 优先级 | 方案 | 预期节省 | 风险 | 实施难度 |
|--------|------|---------|------|---------|
| **P0** | **精简路由上下文** — 合并重复规则、用紧凑格式（约从 5,000 → 2,000 token） | **1-2s** | 低 | 低 |
| **P1** | **精简 Tool Schema** — `createSkillToolDefinition` 的 `resolvedQuery` schema 包含 30+ 属性逐字段描述，可大幅缩减 | **0.5-1s** | 中 | 中 |
| **P2** | **动态上下文注入** — 根据查询类型只注入相关路由规则（如 query 类只注入 3-5 条规则） | **1-2s** | 中 | 中 |
| **P3** | **补充审计日志** — 在 `execute()` 回调中添加 `appendPluginAuditEvent` | N/A | 低 | 低 |
