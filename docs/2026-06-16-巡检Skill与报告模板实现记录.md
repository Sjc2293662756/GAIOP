# 巡检 Skill 与报告模板实现记录

日期：2026-06-16

## 目标

根据巡检报告模板和巡检报告接口字段说明，落地一条本地可运行链路：

1. `openclaw-napm-inspection` 负责查询 NetInside/NAPM 巡检数据。
2. `openclaw-napm-inspection` 产出结构化 `inspection` 与 `reportData`。
3. `openclaw-napm-report` 只负责渲染 `inspection_report` Word 报告，不再发起 NAPM 查询。

## 已实现模块

- `skills/openclaw-napm-inspection/scripts/run_inspection_snapshot.js`
  - 支持 `--payload`、`--input`、stdin。
  - 支持命令行覆盖 `format/title/customerName/projectName/reportDate/nowSeconds/host/username/password`。

- `skills/openclaw-napm-inspection/services/InspectionClient.js`
  - 使用 `UserName` / `Password` 查询参数认证。
  - 对审计和输出中的密码做 `Password=***` 打码。

- `InspectionFieldMapperService`
  - 映射设备基本信息、性能状况、数据保留、配置、原始数据包存储。

- `InspectionTrafficAnalysisService`
  - 查询 `timeValues`。
  - 固定 `groupType1=TotalTraffic`。
  - 指标为 `TPIO,TPI,TPO`。
  - 生成最近 1 小时和最近 1 天数据集、统计摘要、证据引用和结论。

- `InspectionBusinessPerformanceService`
  - 查询 `topValues`。
  - 固定 `groupType1=WebApplication`。
  - 慢访问指标：`PGSLPCT,PGNSLPGE,PGTME`。
  - HTTP 错误指标：`PGHTTP400`、`PGHTTP500`。
  - 生成慢访问、HTTP 400/500、证据引用和结论。

- `InspectionReportDataService`
  - 汇总巡检结果。
  - 输出 `reportData.reportType = "inspection_report"`。
  - 输出 `templateId = "napm_traffic_health_inspection_v1"`。

- `openclaw-napm-report`
  - `ReportGenerationService` 支持 `inspection_report`。
  - `ReportInputContractService` 支持直接传入 `inspection` 或巡检 skill 的完整结果。
  - `ReportTemplateService` 新增巡检报告渲染分支。

## 调用方式

现场查询：

```bash
node skills/openclaw-napm-inspection/scripts/run_inspection_snapshot.js --payload "{\"customerName\":\"北京烟草\"}"
```

使用 fixture：

```bash
node skills/openclaw-napm-inspection/scripts/run_inspection_snapshot.js --input inspection-input.json
```

生成 Word：

```bash
node skills/openclaw-napm-report/scripts/generate_napm_report.js --input inspection-result.json
```

其中 `inspection-result.json` 可以是巡检 skill 的完整输出，也可以只包含 `reportData`。
