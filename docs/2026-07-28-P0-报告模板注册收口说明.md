# P0 报告模板注册收口说明

## 状态

本地代码和定向回归已完成，并已于 2026-07-28 部署到远端测试环境。本次只解决报告数据契约、模板选择和 Word 渲染的一致性；附件 MEDIA 发送、下载鉴权和运行数据目录治理仍未完成，现场验收不以企业微信附件送达作为通过条件。

## 问题与决策

此前 producer 可生成 `quick_report`、无模板 ID 的 `diagnostic_report` 以及数据包诊断报告，但 renderer 仅能渲染少量固定模板。这会使有效查询结果在生成报告时才失败。

整改采用受控通用模板，而不是恢复任意文本拼接：普通查询、综合分析、告警和数据包分析统一使用 `quick_report + napm_generic_query_v1`；真正的故障诊断仍只能使用对应 flow 的固定模板。

## 注册表

唯一注册真源位于 `skills/openclaw-napm-report/services/ReportTemplateRegistry.js`。每个条目固定：

| schema | reportType | templateId | renderer |
|---|---|---|---|
| `openclaw_napm_report_data.v1` | `quick_report` | `napm_generic_query_v1` | 受控通用 Word 模板 |
| 同上 | `inspection_report` | `napm_traffic_health_inspection_v1` | 巡检固定模板 |
| 同上 | `summary_report` | `napm_summary_overview_v1` | 综述固定模板 |
| 同上 | `diagnostic_report` | `napm_bs_fault_diagnosis_v2` | B/S 业务故障模板 |
| 同上 | `diagnostic_report` | `napm_bs_page_perf_v1` | B/S 页面性能模板 |
| 同上 | `diagnostic_report` | `napm_cs_fault_diagnosis_v1` | C/S 应用故障模板 |

`comparative_report`、`operation_report` 和没有 template ID 的 `diagnostic_report` 不再是可生成组合。生成服务会在渲染前返回 `REPORT_TEMPLATE_NOT_FOUND`，不会产生空文档或改用错误模板。

通用模板只接受 `summary`、`table`、`finding`、`recommendation`、`items` 五种 section。未实现的 section（例如 chart）会被输入校验拒绝，避免内容静默丢失。

## Producer 迁移

- NAPM 普通查询和综合分析的 `reportData` 改为 `quick_report + napm_generic_query_v1`。
- 告警报告改为同一通用模板，不再伪装为故障诊断报告。
- 数据包报告构建器与输入归一层均输出同一通用模板组合。
- 故障诊断的“生成报告”及公开构建方法按 `bs_app_slow`、`bs_page_perf`、`cs_app_slow` 选择已注册的固定模板。
- `ReportGenerationService` 和 `ReportTemplateService` 都先校验注册表，producer 与 renderer 不能再各自维护可支持类型列表。

## 已验证

```text
npx jest test/report-template-registry.test.js test/generic-report-template.test.js test/napm-report-data-contract.test.js test/napm-report-input-contract.test.js test/summary-fault-failure-propagation.test.js --runInBand
```

结果：5 个测试套件、18 个断言通过。覆盖通用模板实际生成 DOCX、未注册组合拒绝、未实现 section 拒绝、查询/数据包输入归一，以及故障 flow 到模板 ID 的映射。

所有变更文件通过 `node --check` 与 `git diff --check`。

## 后续约束

- 报告新增类型、模板或 schema 版本时，必须先登记注册表，再实现 producer、renderer 和端到端测试；不得仅修改其中一端。
- `test/napm-report-generation-service.test.js` 仍有旧断言把无模板诊断 payload 当作可生成输入，应在 QA-001 中改为固定模板输入或显式拒绝断言，不能据此恢复旧的宽松行为。
- T08 必须将生成结果转换为企业微信认可的 MEDIA 附件，并提供独立输出目录、授权访问、保留期和发送状态追踪后，报告能力才可作为上线条件通过。
