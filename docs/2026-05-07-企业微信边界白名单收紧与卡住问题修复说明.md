# 2026-05-07 企业微信边界白名单收紧与卡住问题修复说明

## 一、本次问题现象

本轮联调中，企业微信入口出现了两类连续问题：

### 1. 非 NAPM 问题仍被正常回答

例如：

- `今天金价`
- `今天是什么节日`
- `什么是玫瑰`

这些都不属于当前 NAPM / 监控分析技能边界，但仍然被放入通用链路，甚至直接得到百科式回答。

### 2. 在边界收紧后，非 NAPM 问题又出现“卡住”

例如用户再次测试：

- `什么是玫瑰`

现象不是正常被拒绝，而是企业微信侧看起来一直停在“思考中”，没有完成最终回复。

---

## 二、根因拆解

本次问题实际上分成两个层面。

### 1. 第一层根因：边界主判定过宽

远端企业微信插件中，`looksLikeNapmQuery(text)` 一度等价于：

```js
const raw = String(text || '').trim();
return Boolean(raw);
```

也就是：

- 只要用户发了文本
- 就先被当作“像 NAPM 问题”

这会导致：

- `天气` 这种问法可能因为命中了黑名单词而被拦住
- `节日`、`玫瑰` 这种没进黑名单的问法则会漏过去

所以原先的判断模式，本质上不是“只放行边界内”，而是“默认全放行，再靠黑名单补洞”。

### 2. 第二层根因：追问豁免放得过宽

后续为了支持多轮会话，入口增加了“NAPM 跟进态豁免”。

原意是允许这类追问继续放行：

- `那前三个呢`
- `第一个`
- `继续`
- `这个为什么`

但如果豁免条件只看“当前会话曾问过 NAPM”，就会把下面这类完全无关的新问题也放过去：

- 先问：`现在网络整体情况怎么样？`
- 再问：`什么是玫瑰`

这说明“会话中出现过 NAPM”不能直接等价于“后一句也属于 NAPM 追问”。

### 3. 第三层根因：边界修复后又出现运行时异常

在继续收紧入口边界时，远端日志出现了明确报错：

```text
ReferenceError: pruneNapmClarificationStates is not defined
```

这说明：

- 新版边界逻辑已经开始执行
- 但在判断 follow-up / clarification 状态时，调用了一个未定义函数
- thinking 消息先发出去了
- 真正的边界回复还没来得及发出，流程就中断

这也是用户看到“卡住”的直接原因。

---

## 三、本次实际修改

### 1. 将企业微信入口改为“白名单放行”思路

核心原则调整为：

```text
先判断是不是 NAPM 域内问题
  -> 否：直接拒绝并引导
  -> 是：再判断是否命中硬边界
       -> 是：拒绝
       -> 否：进入 OpenClaw 主链
```

也就是说：

- 主判定不再依赖“黑名单补洞”
- 主判定只看 NAPM 领域特征
- 其余默认拒绝

### 2. `looksLikeNapmQuery(...)` 收紧为 NAPM 语义白名单

当前白名单覆盖的核心类型包括：

- 网络/流量/吞吐/带宽
- 时延/RTT/响应时间/丢包/重传
- 应用/Web 应用/业务组/客户端/IP
- 排行/趋势/概览/TopN
- 指标码：`TPIO` / `PKIO` / `TRTI` / `RTTI` / `CSTI` / `RFCI` 等

### 3. 硬边界词继续保留，但不再承担主判定职责

`detectWeComHardBoundary(...)` 仍保留，用于补充拦截：

- 天气
- 节日
- 黄历
- 新闻
- 金价/股价/汇率
- 重启/部署/改配置
- 查密码/token

它的职责变成：

- 拦系统越权问题
- 拦明显泛问答问题
- 但不再作为“主边界”的唯一手段

### 4. 跟进态豁免收紧为“只允许像追问的话”

新增思路：

- 当前会话虽然处于 NAPM 跟进态
- 也必须同时满足“这句话本身像简短追问”
- 才允许借上下文继续放行

允许的典型形式包括：

- `那前三个呢`
- `第一个`
- `继续`
- `展开说说`
- `这个为什么`
- `再看一下这个`

而这类不再允许借上下文通过：

- `什么是玫瑰`
- `今天吃什么`
- `唐朝是什么`
- `金价多少`

### 5. 补齐缺失函数 `pruneNapmClarificationStates()`

为解决“thinking 后卡住”的问题，本次补上了：

- `pruneNapmClarificationStates()`

其职责很简单：

- 清理过期的 `napmClarificationStates`
- 避免入口在检查 follow-up / clarification 状态时抛 `ReferenceError`

- `今天是什么节日`
- `什么是玫瑰`

## 六、本次结论

本次修复的核心，不是简单加几个“天气/节日”关键词，而是把企业微信入口真正收口为：

**以 NAPM 白名单为主、以硬边界为辅、以受控追问豁免为补充**。

同时，本次还修复了一个隐藏运行时问题：

- `pruneNapmClarificationStates is not defined`

这保证了入口边界不仅“逻辑正确”，也能“真正稳定执行完并回消息”。
