# 数据包预览四数据集解析与答复修复

## 问题表现

NetInside `packetsPreview` 返回 HTTP 200 且有业务组流量时，答复显示“预览记录数：4 条”；单 IP 无数据时，答复只显示底层错误。普通预览还输出了带脱敏占位符的 API URL，用户无法直接使用，也挤占了真正的分析结果。

## 根因

标准 `packetsPreview` 响应是 4 个可视化数据集组成的外层数组：

1. `TA/TB/Data/MIFG`：通信记录；
2. `TN/Data/IPConv/MIFG`：端点汇总；
3. `edges/nodes`：拓扑；
4. `xValues/yValues`：时间序列。

旧解析器把外层数组直接当成预览行，因此把 4 个组件误报成 4 条记录，并遗漏通信、端点和流量字段。空预览又在确定性答复构造前提前返回底层错误，导致时间和目标丢失。

## 修复结果

- 以 `columnIds` 识别通信数据集和端点数据集，`overview.rowCount` 使用通信数据集的真实行数。
- 新增 `overview.trafficSummary`，包含 `conversationCount`、`endpointCount`、`trafficBytes`、`directions`、`topGroupMembers` 和 `topConversations`。
- 方向只依据已解析的 `criteria.ips/ipRanges` 判定：目标到外部为发出、外部到目标为进入、目标到目标为内部互访。
- `Data` 聚合值命名为“预览流量”，不作为包数或 pcap 预计下载大小。
- 最终答复展示精确时间、目标或实际业务组成员、通信数、端点数、流向、活跃成员和主要通信。
- `preview_only` 明确尚未下载 pcap，也未执行协议、TCP 或 HTTP 层分析。
- 空预览保留时间和目标，并明确未下载、未分析。
- 普通预览和分析不展示 URL；只有 `build_url_only` 链接请求展示脱敏 URL。

## 证据边界

预览数据只能证明指定时间和目标范围内的通信关系及聚合流量。未下载并解析 pcap 时，不得输出协议分布、TCP 重传、RTT、HTTP 状态、扫描特征、拥塞或健康结论。

## 回归覆盖

- 四数据集 fixture 必须解析为内部通信行数，而不是外层组件数。
- 业务组答复必须显示结构化流量证据并隐藏普通预览 URL。
- 单 IP 空结果必须保留时间、目标和未下载/未分析状态。
