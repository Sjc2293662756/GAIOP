# 巡检报告固定模板落地说明

日期：2026-06-17

## 目标

本次改动把巡检报告从“在 JS 里临时拼章节、拼表格”调整为“固定模板规格驱动渲染”。

目标是满足后续专业巡检报告的产出方式：

- 报告章节顺序固定。
- 表格表头和格式固定。
- 图表位置固定。
- 数据每次由巡检查询 skill 更新。
- 叙述由规则和查询数据生成，不由报告 skill 随意发挥。

职责边界保持不变：

```text
openclaw-napm-inspection
  -> 查询 NAPM 巡检数据
  -> 生成 trafficAnalysis / businessPerformance / findings / evidence
  -> 输出 inspection reportData

openclaw-napm-report
  -> 读取固定模板
  -> 渲染表格、图表槽位和规则叙述
  -> 生成 docx 和 audit JSON
```

`openclaw-napm-report` 不调用 NAPM 接口，也不重新判断业务是否异常。

## 模板规格

主模板：

```text
napm_traffic_health_inspection_v1.json
```

包含固定章节：

```text
封面
目录
1 文档说明
  1.1 流量分析系统检查项说明
2 基本信息
3 巡检信息汇总
  3.1 性能状况
  3.2 数据信息
  3.3 配置信息
  3.4 数据包存储信息
  3.5 流量分析状况
  3.6 业务性能状况
4 巡检总结
```

模板 section 类型：

| 类型 | 作用 |
|---|---|
| `cover` | 封面标题 |
| `toc` | 固定目录页 |
| `paragraphs` | 固定说明文字、检查要求、点击路径 |
| `staticTable` | 固定检查项说明表 |
| `keyValueTable` | 基础信息键值表 |
| `heading` | 固定章节标题 |
| `table` | 固定表格 |
| `dataParagraphs` | 将 findings/recommendations 渲染为“检查结果/建议”段落 |
| `narrative` | 规则叙述段落 |
| `chartSlot` | 固定图表槽位 |

表格通过 `rowBuilder` 绑定到固定数据构造器，例如：

| rowBuilder | 数据来源 |
|---|---|
| `devices` | `inspection.devices` |
| `basicDevices` | `inspection.devices`，按原模板基本信息表字段渲染 |
| `sectionItems` | `inspection.performance/items` 等 |
| `findings` | 各 section 的 findings |
| `trafficStats` | `inspection.trafficAnalysis` |
| `trafficSamples` | 流量趋势样本 |
| `businessSlow` | `inspection.businessPerformance.slowAccess` |
| `businessErrors` | `inspection.businessPerformance.httpErrors` |
| `summaryDevices` | `inspection.summary.devices` |
| `abnormalItems` | `inspection.summary.abnormalItems` |

## 页眉页脚配置

页眉页脚直接写在主模板：

```json
{
  "page": {
    "margin": {
      "top": 1000,
      "right": 900,
      "bottom": 1000,
      "left": 900,
      "header": 450,
      "footer": 450
    },
    "header": {
      "leftImage": {
        "path": "templates/inspection/company-logo.png",
        "width": 110,
        "height": 32,
        "alt": "网深科技流量分析系统"
      },
      "left": "网深科技流量分析系统",
      "right": "{{inspection.customerName}}{{inspection.projectName}}巡检报告"
    },
    "footer": {
      "center": "第 {{pageNumber}} 页 / 共 {{totalPages}} 页",
      "right": "{{inspection.reportDate}}"
    }
  }
}
```

支持两类占位：

| 占位 | 说明 |
|---|---|
| `{{inspection.customerName}}` | 普通数据路径，从 `reportData/inspection` 中读取 |
| `{{pageNumber}}` | 当前页码，由 Word 字段生成 |
| `{{totalPages}}` | 总页数，由 Word 字段生成 |

`header` 和 `footer` 支持 `left`、`center`、`right` 三个位置。后续如果某个客户模板需要品牌名、密级、报告日期、项目名，只改 JSON 即可。

页眉 logo 放置位置：

```text
skills/openclaw-napm-report/templates/inspection/company-logo.png
```

模板中的 `leftImage.path` 使用相对路径：

```json
{
  "leftImage": {
    "path": "templates/inspection/company-logo.png",
    "width": 110,
    "height": 32,
    "alt": "网深科技流量分析系统"
  }
}
```

如果 logo 文件存在，页眉左侧渲染图片；如果文件不存在，自动退回渲染 `header.left` 文本，避免报告生成失败。

示例：

```json
{
  "header": {
    "left": "网深科技",
    "center": "{{title}}",
    "right": "{{inspection.reportDate}}"
  },
  "footer": {
    "center": "第 {{pageNumber}} 页 / 共 {{totalPages}} 页"
  }
}
```

## 规则叙述

叙述规则文件：

```text
narrative-rules.v1.json
```

当前支持三组规则：

| ruleGroup | 用途 |
|---|---|
| `traffic.summary` | 3.5 流量分析状况 |
| `business.summary` | 3.6 业务性能状况 |
| `summary.conclusion` | 4 巡检总结 |

规则只读取 `inspection` 已有数据，例如：

```json
{
  "when": "inspection.trafficAnalysis.recentHour.dataset.stats.spikeCount > 0",
  "text": "最近1小时总流量趋势存在 {{inspection.trafficAnalysis.recentHour.dataset.stats.spikeCount}} 个疑似尖峰，建议关注对应时间点的业务突增或异常流量。"
}
```

目前支持的判断表达式：

- `path exists`
- `path empty`
- `path == value`
- `path != value`
- `path > number`
- `path >= number`
- `path < number`
- `path <= number`
- `default`

## 图表槽位

图表规格文件：

```text
chart-specs.v1.json
```

当前固定 4 个图表槽位：

| chartId | 用途 |
|---|---|
| `traffic.recentHour.total` | 最近1小时总流量趋势图 |
| `traffic.recentDay.total` | 最近1天总流量趋势图 |
| `business.slowAccess.top` | 慢访问业务 Top 图 |
| `business.httpErrors.top` | HTTP 400/500 业务 Top 图 |

第一阶段先在 Word 中渲染“图表槽位表”，明确图表类型、数据绑定、指标和数据点数量。

后续接入 ECharts 或图片生成后，只需要让巡检/图表链路产出 PNG/SVG artifact，再由报告模板把 `chartSlot` 替换为真实图片嵌入。模板章节结构不用再改。

## 3.5 与 3.6 的数据原则

### 3.5 流量分析状况

数据必须来自巡检查询 skill 的：

```text
inspection.trafficAnalysis.recentHour.dataset
inspection.trafficAnalysis.recentDay.dataset
inspection.trafficAnalysis.findings
```

报告 skill 只渲染：

- 流量趋势叙述。
- 图表槽位。
- 检查结果段落。

### 3.6 业务性能状况

数据必须来自巡检查询 skill 的：

```text
inspection.businessPerformance.slowAccess
inspection.businessPerformance.httpErrors
inspection.businessPerformance.findings
inspection.businessPerformance.queryEvidence
```

报告 skill 只渲染：

- 业务性能叙述。
- 图表槽位。
- 检查结果段落。
- 建议段落。

如果没有真实查询数据，报告不能编造业务异常。

## 目录真实页码机制补充

巡检报告目录不再使用模板 JSON 中写死的 `items[].page` 页码。

当前 `templates/inspection/napm_traffic_health_inspection_v1.json` 中的 `toc` 只声明目录配置：

```json
{
  "id": "toc",
  "type": "toc",
  "title": "目录",
  "alias": "Inspection Report TOC",
  "headingStyleRange": "1-2",
  "hyperlink": true,
  "updateMode": "wordField"
}
```

`InspectionFixedTemplateService.renderToc()` 会生成 Word 原生 `TOC` 字段，字段范围为 `Heading 1` 到 `Heading 2`。文档同时写入 `features.updateFields = true`，并将 TOC 字段标记为 `dirty`，因此 Word 打开文档时会根据真实分页刷新目录页码。

注意事项：
- 正文一级、二级标题必须继续使用 `Heading 1` / `Heading 2`，不要用普通加粗段落伪装标题。
- 如果某些客户端没有自动刷新字段，手动执行 `Ctrl+A` 后按 `F9` 更新字段即可刷新目录与页脚总页数。
- TOC1/TOC2/TOC3 样式已在生成器中设置为黑色、`Microsoft YaHei`，保持与正文的字体要求一致。
