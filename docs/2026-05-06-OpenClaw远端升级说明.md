## 4. 升级过程

### 4.1 安装新版本

远端执行全局安装：

```bash
npm install -g openclaw@2026.5.4
```

安装完成后确认：

- 全局包版本：`2026.5.4`
- CLI 版本：`OpenClaw 2026.5.4`

### 4.2 先做临时端口冒烟

在不影响正式服务端口 `18789` 的前提下，使用临时端口 `19999` 启动新版本做冒烟验证。

首次冒烟时，OpenClaw 本体可正常启动，但发现两个插件兼容问题：

1. `napm-openclaw-plugin`

- 新版加载器要求插件在 manifest 中显式声明 `contracts.tools`
- 旧插件虽然注册了 agent tools，但没有补齐 manifest 契约声明

2. `wecom-openclaw-plugin`

- `openclaw.plugin.json` 中配置的插件 id 是 `wecom-openclaw-plugin`
- 运行时代码导出的 `plugin.id` 却是 `wecom`
- 新版加载器会直接报 `plugin id mismatch`

此外还发现一个非阻断问题：

- `wecom-openclaw-plugin` 依赖的 `readJsonFileWithFallback` / `writeJsonFileAtomically` / `withFileLock` 不再从当前 `openclaw/plugin-sdk` 根出口稳定提供
- 表现为 `reqid-store warmup error`

## 5. 兼容修复

### 5.1 修复 napm-openclaw-plugin 的工具契约声明

在远端文件：

- `/home/netinside/.openclaw/extensions/napm-openclaw-plugin/openclaw.plugin.json`

新增：

```json
"contracts": {
  "tools": [
    "napm-skill-query",
    "napm-topn",
    "napm-average",
    "napm-timeseries"
  ]
}
```

修复目的：

- 让新版 OpenClaw 加载器承认该插件注册的 agent tools 属于 manifest 声明范围

### 5.2 修复 wecom-openclaw-plugin 的插件 id 不一致

修改远端文件：

- `/home/netinside/.openclaw/extensions/wecom-openclaw-plugin/dist/index.esm.js`
- `/home/netinside/.openclaw/extensions/wecom-openclaw-plugin/dist/index.cjs.js`

将运行时代码中的：

```js
id: "wecom"
```

改为：

```js
id: "wecom-openclaw-plugin"
```

修复目的：

- 与 `openclaw.plugin.json` 中的 id 保持一致
- 避免新版插件加载器初始化失败

### 5.3 修复 wecom reqId 持久化预热兼容问题

仍然在以下两个编译产物中修复：

- `/home/netinside/.openclaw/extensions/wecom-openclaw-plugin/dist/index.esm.js`
- `/home/netinside/.openclaw/extensions/wecom-openclaw-plugin/dist/index.cjs.js`

处理方式：

1. 保留当前插件主逻辑不变
2. 给 `readJsonFileWithFallback`、`writeJsonFileAtomically`、`withFileLock` 增加本地 fallback 实现
3. 优先使用 SDK 现有实现；若 SDK 根出口不可用，则退回到插件内兜底实现

修复目的：

- 消除 `reqid-store warmup error`
- 保持企微 `reqId` 缓存持久化能力
- 降低后续 OpenClaw 小版本升级时被 SDK 出口变动影响的概率

## 7. 当前遗留项

当前仍存在一个非阻断告警：

```text
OPENCLAW_PLUGIN_SDK_COMPAT_DEPRECATED
openclaw/plugin-sdk/compat is deprecated for new plugins
```

说明：

- 这是插件 SDK 兼容层的弃用提示
- 不影响当前服务启动、企微收发、NAPM 查询和 reqId 预热
- 但说明远端自定义插件后续仍值得做一次“按 2026.5.x SDK 子模块标准化整理”

建议后续择机处理：

1. 把 `wecom-openclaw-plugin` 的 import/require 调整到稳定子路径
2. 检查 `napm-openclaw-plugin` 是否还存在旧版插件写法
3. 尽量避免长期直接修改 `dist/` 编译产物，后续最好回到插件源码层统一构建

本次远端升级已经完成，结果如下：

- OpenClaw 已由 `2026.3.7` 升级到 `2026.5.4`

- OpenClaw `2026.5.x` 对插件 manifest 契约和插件 id 一致性要求更严格

- 线上升级时应坚持“先备份、先临时端口验证、后正式切换”的流程
