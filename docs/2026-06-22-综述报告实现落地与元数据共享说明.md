## 2. 数据流

```
用户请求
  → openclaw-napm-summary / SummaryService.run()
    ├── plan(scope, timeRange) → 查询计划（6种 scope × 2种模式）
    ├── validatePlan(plan) → SummaryMetadataService 校验指标×维度可用性
    ├── execute(plan) → 并行调用 NAPM API（Promise.allSettled）
    └── aggregate(rawData, scope) → 标准 summary 数据块
  → SummaryReportDataService.buildReportData()
  → openclaw-napm-report 消费
    → ReportInputContractService.normalizeReportInput()
    → ReportTemplateService.renderDocx() → SummaryFixedTemplateService
      ├── filterSectionsByScope（模板 scopes 声明控制章节显隐）
      ├── preRenderCharts（ECharts SSR，NAP 色系）
      └── Packer.toBuffer() → .docx
  → ReportStorageService（scope 驱动文件名）→ 落盘
```

## 3. 元数据共享架构

### 3.1 问题

不同 NAPM skill 需要知道：
- 某个维度（groupType）有哪些指标可用
- 维度树/下钻路径
- 时间粒度

之前各 skill 各自硬编码指标列表，导致查询到不支持的指标（如 WebApplication 不支持 TPIO）返回空数据。

### 3.2 方案

`openclaw-napm-query` 已有 `NapmMetadataService`（封装 `type=metricsForGroup`、`type=groups`、`type=drilldownCatalog` 等 API），其它 skill 通过相对路径 require 即可。

### 3.3 共享方式

```js
// 任意 NAPM skill 中
const meta = require('../../openclaw-napm-query/services/NapmMetadataService');

// 查某维度有哪些指标
const metrics = await meta.getMetricsForGroupPath([{ type: 'WebApplication' }]);
// → [{ id: 'PGSLPCT', label: '慢访问占比', unit: '%' }, ...]

// 查维度树（下钻路径）
const tree = await meta.getGroupTree();
// → TotalTraffic → { IPAddress, Application, WebApplication, BusinessGroup, ... }

// 查下钻目录
const catalog = await meta.getDrilldownCatalog('WebApplication');
// → WebApplication → { PageFamily, ClientIPs → IPAddress, ... }
```

### 3.4 缓存封装

`SummaryMetadataService` 在 `openclaw-napm-summary/services/` 中，提供：

- `getAvailableMetrics(groupType)` — 带缓存，首次调用后内存缓存
- `checkMetrics(groupType, metricIds)` — 返回 `{ available, missing }`
- `validatePlan(plan)` — 校验 query plan 中标注了 `groupType`+`metrics` 的条目

### 3.5 使用示例

```js
const SummaryMetadataService = require('./SummaryMetadataService');

// 在 plan 中标注每个查询的 groupType 和 metrics
const plan = [
  { label: 'topApps', groupType: 'WebApplication', metrics: ['TPIO','TPI','TPO'],
    fn: () => client.getTopValues(start, end, 'TPIO,TPI,TPO', 'TPIO', 10, [{type:'WebApplication'}]) }
];

// 执行前校验
const warnings = await SummaryMetadataService.validatePlan(plan);
// → [{ label: 'topApps', groupType: 'WebApplication',
//      missingMetrics: ['TPIO','TPI','TPO'],
//      hint: 'WebApplication 不支持指标: TPIO, TPI, TPO，可用: PGSLPCT, PGNSLPGE, PGTME, ...' }]
```

## 4. 模板 scope 系统

一份模板 `napm_summary_overview_v1.json` 覆盖全部 scope，每个 section 通过 `scopes` 字段声明适用场景：

```json
{
  "id": "traffic_top_app_table",
  "type": "table",
  "scopes": ["global", "network", "application", "businessGroup"],
  "rowBuilder": "trafficTopApps"
}
```

- `scopes` 省略或 `["*"]` → 所有 scope 都渲染
- `scopes: ["global"]` → 仅全局
- `scopes: ["global", "network"]` → 全局 + 流量整体

## 6. NAPM API 响应格式适配

### 6.1 时间对齐

NAP API 要求 start/end 对齐到 60 秒。`SummaryClient._alignToMinute()` 自动处理。

### 6.2 topValues 嵌套格式

NAP API 返回 `metricValues[{metric:{id:"TPIO"},value:23.88}]`，仅第一项有 `metric.id`，后续项只保留 `value`（API 优化）。`flattenTopValuesItems()` 缓存第一项 id 顺序并应用到后续项。

### 6.3 timeValues 结构化格式

NAP API 返回 `{interval:{start,end}, metricValues:[{metric:{id:"TPIO"},values:[...]}]}`。`normalizeTimeSeries()` 解析并转为 `{points:[{time,TPIO,...}]}` 格式供图表渲染。

## 10. scope 强制修正（插件层）

`buildSummaryExecutorPayload` 根据用户 prompt 文本强制修正 scope。AI 即使传错也会被纠正：

| 用户 prompt 包含 | 强制修正为 |
|---|---|
| 业务（非"业务组"） | `webApplication` |
| 业务组/工作组 | `businessGroup` |
| 网络/流量 | `network` |
| 应用 | `application` |
| 告警 | `alert` |
| 全局/系统 | `global` |

## 12. 数据处理规范

| 数据类型 | 精度 | 函数 |
|---------|------|------|
| 流量数据 (TPIO/TPI/TPO) | 保留三位小数 | `formatNumber()` |
| 慢访问 ratio / avgPageDelayMs | 保留两位小数 | `toFixed(2)` / `Math.round` |
| 流量表表头 | 带单位 `(kb/s)` | 模板 column 直接写 |

## 15. 子章节编号

模板子章节标题已移除硬编码编号（如 "3.1"、"4.2"），避免 scope 过滤后出现编号跳跃。仅保留章标题编号（1-5）。

## 16. 文件名修复

`ReportStorageService.createReportId` 的 `hasTarget` 判断从 `!scope.target` 改为 `!scope.target || !scope.target.groupArgument`，避免空 target 导致"未知对象"文件名。

## 17. 设备信息字段映射

`_normalizeDeviceInfo` 适配 NAPM `applianceInfo` API 响应格式：`boxName`→systemName、`address`→ip、`uiVersion`→softwareVersion。
