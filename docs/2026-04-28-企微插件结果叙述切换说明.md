# 企微插件结果叙述切换说明

## 问题现象

用户在企业微信里提问：

- `系统中有哪些web应用`

虽然 Skill 已经返回了结构化结果，但最终仍被企微插件格式化成：

- `结论：Groups list completed`
- `已返回 119 条对象/维度`
- `对象列表：...`

说明最终生效的不是 OpenClaw 基于语义的自由叙述，而是插件里的固定兜底格式化逻辑。

## 根因

企微插件在 `tryHandleNapmQuery()` 中拿到 NAPM 查询结果后，直接调用：

- `formatNapmDirectReply(payload)`

这一分支会机械地按 `service=groups/metrics/topValues/...` 输出固定模板，没有优先消费：

- `narrationInput`
- `narrationStructure`
- `machine_narration_input`

## 本次处理

在企微插件侧新增“查询结果叙述走 OpenClaw”分支：

1. 当返回载荷中存在 `narrationInput` 且属于查询结果时，
2. 先把结构化结果压缩成适合表达层消费的语义载荷，
3. 再调用 OpenClaw 生成自然中文回复，
4. 只有失败时才回落到原来的 `formatNapmDirectReply()`。

## 当前收口原则

- Skill：负责理解、查数、返回结构化结果
- OpenClaw：负责根据语义自由组织最终回复
- 企微插件：优先走 OpenClaw 结果叙述，失败时再走固定兜底模板
