# 2026-05-27 业务下钻路径语义漂移修复说明

## 背景

用户询问“业务有哪些下钻路径？”时，线上出现两类异常：

- 首轮返回“当前问题必须经 NAPM skill 执行后才能回答”，说明插件保护层没有拿到有效 skill 结果。
- 追问“你的查询链路是什么？”后返回了 `BusinessGroup` 下钻路径，和普通“业务”应指向 `WebApplication` 的语义不一致。

## 根因

排查远端日志发现：

- `16:21` 首轮只有 `before_message_write`，没有 `before_tool_call`，也没有 `forced NAPM skill execution completed`。
- 本地复现显示 `NapmResolvedQueryResolverService.resolvePrompt("业务有哪些下钻路径？")` 能正确构造 `service=drilldownCatalog`、`groups=[{type:"WebApplication"}]`。
- 但插件侧 `isHierarchyCatalogPrompt("业务有哪些下钻路径？")` 返回 `false`，导致 `shouldForceSkillRecordForPrompt()` 不触发 hook 强制 skill 执行。
- `16:22` 追问时，模型自行调用 `napm-skill-query`，传入的 `resolvedQuery.groups[0].type` 已经是 `BusinessGroup`，插件 canonical 化没有用 resolver 结果覆盖该错误对象。

## 修改内容

### 1. 统一下钻语义识别

文件：

- `skills/openclaw-napm-query/services/PromptRoutingService.js`

新增真实中文 Unicode 识别规则：

- 普通“业务”且未出现“业务组/工作组/BusinessGroup”时，目标对象为 `WebApplication`。
- 明确出现“业务组/工作组/BusinessGroup”时，目标对象为 `BusinessGroup`。
- 下钻意图支持真实中文“下钻、路径、层级、结构、支持哪些”等表达。

### 2. 收紧 tool 调用 canonical 化

文件：

- `napm-openclaw-plugin.remote.js`

修改 `buildCanonicalSkillToolParams()`：

- 对当前 activePrompt 调用 `NapmResolvedQueryResolverService.resolvePrompt()`。
- 如果 resolver 能构造有效 `resolvedQuery`，以 resolver 的 `resolvedQuery` 覆盖模型传入的 `resolvedQuery`。
- 避免模型把“业务有哪些下钻路径？”错误传成 `BusinessGroup` 后被插件放行。

- 未再输出 skill-required 保护文案。
- 未再漂移到 `BusinessGroup`。

## 当前正确链路

```text
用户：业务有哪些下钻路径？
  -> OpenClaw plugin 识别为 NAPM 下钻元数据问题
  -> resolver 构造 resolvedQuery
     service=drilldownCatalog
     queryModeKey=metadata
     groups=[{type:"WebApplication"}]
  -> napm-skill-query 执行
  -> skill 返回 WebApplication 下钻路径 displayText
  -> plugin 输出 skill 结果
```

明确询问“业务组有哪些下钻路径？”时：

```text
groups=[{type:"BusinessGroup"}]
```
