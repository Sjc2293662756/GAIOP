# NAPM 告警查询确定性输出契约修复方案

## 1. 问题现象

用户查询“最近一小时系统有哪些告警”时，`napm-alert-query` 已成功返回结构化告警数据，但最终企业微信消息被模型重新归纳成自由格式。实际输出出现“按严重程度”“Top 对象”“主要触发指标”“典型告警事件”等非 Skill 契约段落，未按项目要求展示完整的七类告警和每组明细。

该问题不是告警数据查询错误，也不是告警聚合数据错误，而是 Tool 结果到最终消息之间存在二次叙述路径。

## 2. 项目要求

`skills/openclaw-napm-alert-query/SKILL.md` 规定：

- 使用 `narrationInput.displayText` 作为用户最终展示文本，原样输出；
- summary 查询固定展示全部七类告警，空类别显示“无告警记录”；
- 同类告警按“告警名称 + 严重级别”聚合；
- 每个聚合组展示对象、触发次数、持续时长和首次开始时间；
- 禁止模型总结、重排、翻译或自行生成表格。

因此，告警查询必须采用确定性展示链路，模型不能成为告警事实的第二个格式化器。

## 3. 根因

1. 插件内 `createAlertQueryToolDefinition().execute()` 的 summary 分支只返回 `finalAnswer` / `displayText`，没有按 OpenClaw 生产 Tool 的通用契约返回 `content[0].text`。
2. OpenClaw 在缺少标准文本内容时仍把结构化结果交还模型，模型自由重写了已生成的告警文本。
3. 插件存在两套告警展示逻辑：Skill 的 `AlertNarrationContractService.buildDisplayText()` 和插件的 `buildAlertQueryReply()`。这使展示规则可能分叉。
4. `message_sending` 与 `before_message_write` 在 `model_owned` 路由上提前放行，不能在当前轮存在成功告警结果时强制使用确定性文本。

## 4. 解决方案

### 4.1 统一格式源

以 Skill 生成的 `result.narrationInput.displayText` 为唯一用户展示文本。插件的 `buildAlertQueryReply()` 只作为兼容回退：当 Skill 没有 `displayText` 时才根据结构化结果生成文本；不能再创建第三套摘要格式。

### 4.2 修正告警 Tool 返回契约

`napm-alert-query` 的 summary、timeline、detail 等普通返回统一包含：

```js
{
  content: [{ type: 'text', text: renderedText }],
  details: result,
  isError: result.ok === false,
  metadata: {
    sourceTool: 'napm-alert-query',
    answerMode: 'deterministic'
  }
}
```

为兼容已有调用方，可以继续保留 `finalAnswer` 和 `displayText`，但生产交付不得只依赖这两个字段。

带 `packetInstruction` 的告警数据包复合流程仍保留中间指令结构，由 `napm-alert-packet-analysis` 负责后续流程，不将中间指令直接当作普通告警摘要发送。

### 4.3 强制当前轮告警最终交付

在 `message_sending` 和 `before_message_write` 中，只有以下条件全部满足才替换最终消息：

- 当前会话有效；
- 当前 `turnId` 有效且结果属于当前轮；
- 记录来源为 `napm-alert-query`；
- 结果成功且存在告警 Skill 结果。

满足条件时始终发送 canonical `displayText`，不采纳模型对告警数量、分类、对象或建议的改写。无当前轮成功结果时继续使用现有“必须经告警 Skill 执行”的边界回复，不能从历史结果推断本轮结果。

### 4.4 其他查询隔离

本修复不修改通用 `makeToolResult()`、`napm-skill-query`、`napm-summary`、`napm-fault-diagnosis`、`napm-report-export` 和普通 `napm-packet-analysis` 的返回或最终文本逻辑。告警数据包复合流程保持独立，仅复用其既有确定性交付机制。

## 5. 验收标准

1. 告警 Tool 返回包含 `content[0].text`，文本与 Skill 的 `narrationInput.displayText` 一致。
2. 模拟模型自由输出时，当前轮最终消息仍与 canonical 告警文本一致。
3. 最终消息不出现模型自造的“Top 对象”“主要触发指标”“典型告警事件”等段落。
4. summary 仍展示 Skill 规定的七类告警、空类别和聚合明细。
5. 非告警查询的既有定向测试和全量测试不回归。

## 6. 验证与发布

先运行告警定向 Jest 和 Hook 生命周期测试，再运行全量 Jest、lint、Node 语法检查和 `git diff --check`。运行时代码变更完成后，按版本管理与统一部署指南构建新的 rc 制品并部署测试服务器；本次文档和代码均不写入账号密码、token 或未脱敏认证信息。
