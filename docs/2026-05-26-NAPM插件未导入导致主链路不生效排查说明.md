# NAPM 插件未导入导致主链路不生效排查说明

## 现象

用户多次询问：

```text
系统中有哪些业务？
```

线上仍回答：

```text
业务相关共 14 个
Web业务应用 Type=3
自定义业务应用 Type=2
直接调用后端 API
exec/curl/python 过滤
未经过 napm-skill-query
```

这说明生产请求没有被已实现的 NAPM 边界逻辑拦住。

## 关键证据

远端执行：

```bash
openclaw plugins inspect napm-openclaw-plugin --json
```

结果显示：

```json
{
  "status": "loaded",
  "imported": false,
  "hookCount": 0,
  "tools": [],
  "commands": [],
  "capabilityCount": 0,
  "shape": "non-capability"
}
```

这说明：

- `openclaw.plugin.json` 被发现了。
- 插件元数据是 loaded。
- 但运行时代码没有 import。
- `register(api)` 没有执行。
- `napm-skill-query` 工具没有注册。
- `message_received` / `before_tool_call` / `message_sending` / `before_message_write` hooks 没有注册。

因此之前修改的所有边界逻辑都没有进入生产请求链路。

## 为什么清缓存无效

这不是会话缓存问题。

即使清理会话，只要插件没有 imported，OpenClaw 主链路仍会直接由默认 agent 回答，NAPM 插件无法：

- 注入 NAPM routing system context。
- 阻止 exec/curl/python。
- 要求上游 resolvedQuery。
- 拦截错误业务清单首答。
- 重写错误查询过程说明。

## 根因

当前 `openclaw.plugin.json` 只有：

```json
{
  "activation": {
    "onCapabilities": ["tool", "hook"]
  }
}
```

但当前 OpenClaw 版本在 descriptor 阶段没有从该插件静态识别出工具/Hook capability：

```json
{
  "toolNames": [],
  "hookNames": [],
  "capabilityCount": 0
}
```

结果是 activation 计划没有真正 import runtime，插件停留在 metadata loaded 状态。

## 修改

在 `openclaw.plugin.json` 中增加 Gateway 启动强制导入：

```json
{
  "activation": {
    "onStartup": true,
    "onCapabilities": ["tool", "hook"]
  }
}
```

`onStartup:true` 是当前 OpenClaw manifest 类型中明确支持的启动激活字段，含义是：

```text
Explicit Gateway startup activation. Set true when the plugin must be imported during Gateway startup.
```

## 验收标准

重启远端后必须再次执行：

```bash
openclaw plugins inspect napm-openclaw-plugin --json
```

期望至少看到：

```json
{
  "imported": true,
  "hookCount": "> 0",
  "tools": ["napm-skill-query"]
}
```

同时日志中应出现：

```text
[napm-openclaw-plugin] stored guard state
[napm-openclaw-plugin] before_tool_call
[napm-openclaw-plugin] before_message_write
```

只有这一步通过，之前所有 resolvedQuery-first、对象本体、执行内核、输出边界修改才真正进入生产链路。
