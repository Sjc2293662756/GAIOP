# NAPM Syslog 告警推送 — 设计与实现文档

> 最后更新：2026-06-25
> 部署服务器：101.254.114.237

## 1. 设计目标

NAPM 通过 Syslog 实时推送告警 → 远端服务器接收 → 自动推送到企业微信群，支持一键查询详情。

## 2. 整体架构

```
NAPM (101.254.114.238)
  │  Syslog UDP 514 (GBK 编码)
  ▼
┌──────────────────────────────────────────────┐
│ 接收服务器 101.254.114.237                     │
│                                              │
│  rsyslog (UDP 514)                           │
│    └─ /var/log/netinside/syslog.log          │
│                                              │
│  napm-syslog-watcher (systemd, Node.js v22)  │
│    ├─ tail -F syslog.log                     │
│    ├─ SyslogParserService   → 解析 Syslog 行  │
│    ├─ AlertEnrichmentService → NAPM API 查详情 │
│    │    └─ 复用 AlertApiService (alert-query) │
│    └─ WeComPushService      → 企业微信推送    │
└──────────────────────────────────────────────┘
  │  HTTPS Webhook
  ▼
┌──────────────────────────────────────────────┐
│ 企业微信群 → Markdown 告警卡片                 │
│  支持 @机器人 二次查询详情                      │
└──────────────────────────────────────────────┘
```

## 4. 服务设计

### 4.1 SyslogParserService — Syslog 行解析

**输入**：rsyslog 写入的原始 Syslog 行

```
2026-06-25T14:44:22.307280+08:00 from=101.254.114.238 host=... facility=local0
severity=notice tag=一般: userAlerts severity=重大 name=SNMP测试1 alertid=113
elogid=694302 starttime=1782369840 endtime=0 canongrouppath=101.254.114.238
condition="如果 流量 > 1.0 则为 Critical..."
metric1=流量（流入和流出） value1=0.5772 units1=兆字节
```

**输出**：结构化告警对象

```json
{
  "timestamp": "2026-06-25T14:44:22.307280+08:00",
  "fromHost": "101.254.114.238",
  "facility": "local0",
  "severity": "notice",
  "tag": "一般",
  "category": "userAlerts",
  "alertSeverity": "重大",
  "alertName": "SNMP测试1",
  "alertId": 113,
  "metrics": [{"name": "流量（流入和流出）", "value": "0.5772", "unit": "兆字节"}],
  "extra": {
    "elogid": "694302",
    "starttime": "1782369840",
    "endtime": "0",
    "canongrouppath": "101.254.114.238",
    "condition": "如果 流量 > 1.0 则为 Critical..."
  }
}
```

**关键设计决策**：

| 决策 | 说明 |
|---|---|
| 时间戳正则支持微秒 | NAPM 实际输出 `14:44:22.307280+08:00`，正则增加 `(?:\\.\\d+)?` |
| 解析全部 key=value | 通过 `/(\w+)=(?:"([^"]*)"|(\S+))/g` 提取，放入 `extra` 字段 |
| 引号值处理 | `condition="含空格的值"` 正确处理为单个字段 |

### 4.2 AlertEnrichmentService — NAPM API 详情补充

**设计原则**：不重复造轮子，直接复用现有 `openclaw-napm-alert-query` 技能中成熟的 `AlertApiService`。

```
AlertEnrichmentService (~100 行薄封装)
  └─ require('../../openclaw-napm-alert-query/services/AlertApiService')
       └─ .getDetail({ eventIds: [elogid], start, end })
```

**查询逻辑**：

1. **ID 选择**：优先使用 `elogid`（事件唯一 ID），fallback 用 `alertid`（规则 ID）
   - 原因：一个 alertid 对应多台主机的多个 elogid，查详情必须用 elogid
2. **时间窗口**：
   - 优先使用 Syslog 中的 `starttime` / `endtime`（精确窗口 ±30 分钟）
   - `endtime=0` 时（告警持续中），用 `starttime ±1 小时`
   - 兜底：用 syslog 时间戳 ±1 天
   - 最终兜底：最近 7 天
3. **时间戳对齐**：NAPM API 要求时间戳能被 60 整除（分钟对齐），`Math.floor(ts / 60) * 60`

**API 调用格式**：

```
GET /webservice/NetInside?UserName=xxx&Password=xxx&type=alertsDetail&eventids=694302&start=...&end=...&json=true
```

### 4.3 WeComPushService — 企业微信推送

**消息类型**：`markdown_v2`（企业微信群机器人 Webhook）

> **为什么用 `markdown_v2` 而非 `markdown`**：
> `markdown_v2` 的代码块（\`\`\`）带**一键复制按钮**，`markdown` 只有灰色背景。
> 
> **注意**：`markdown_v2` 不支持 `mentioned_list` / `mentioned_mobile_list` 字段，
> 传了会导致静默回退到旧渲染，复制按钮消失。

**严重级别显示**：

| NAPM 级别 | 卡片显示 | 说明 |
|---|---|---|
| 紧急 | 🔴 紧急 | 红圈，企业微信支持 |
| 重大 | 🟠 重大 | 橙圈，企业微信支持 |
| 轻微 | 轻微 | 无图标，🟡 在企业微信中乱码 |

**卡片结构**：

```
## ⚠️ NAPM 告警通知

> **告警名称**：SNMP测试1
> **严重级别**：🟠 重大
> **告警类别**：用户体验告警      ← 中文映射
> **告警时间**：2026-06-25T14:44:22+08:00
> **触发条件**：如果 流量 > 1.0 ...  ← 来自 syslog condition
> **监控对象**：101.254.114.238     ← 来自 syslog canongrouppath
> **指标**：
> - 流量（流入和流出）: 0.5772 兆字节

> Alert ID: **113** | Event ID: **694302**
> ⏱ 告警窗口/告警开始              ← 端时间有效时显示窗口，endtime=0 时显示"持续中"

> 💬 查详情: `告警详情 694302 1782369540 1782373140`  ← 可直接复制 @机器人

> 📅 接收时间：2026/6/25 14:44:22
```

**关键设计决策**：

| 决策 | 说明 |
|---|---|
| 告警类别中文化 | `userAlerts` → `用户体验告警`，便于阅读 |
| 触发条件从 syslog 取 | syslog 里的 `condition` 比 API 返回的完整且精确 |
| 监控对象用 `canongrouppath` | 比 API 的 `objectName` 更直观（如 `101.254.114.238` 而非内部路径） |
| 快捷查询指令 | 卡片内嵌 `告警详情 elogid start end`，复制即用 |
| 时间戳截断微秒 | 显示时去掉 `.307280`，保持卡片简洁 |
| 移除 NAPM 控制台链接 | 按用户要求不显示 |

**endtime=0 处理**：

NAPM 对持续中的告警（未恢复）发送 `endtime=0`。处理方式：

| 卡片显示 | 查详情窗口 |
|---|---|
| `⏱ 告警窗口: 14:44 ~ 14:46`（endtime 有效） | start-30min ~ end+30min |
| `⏱ 告警开始: 14:44（持续中）`（endtime=0） | start-1h ~ start+1h |

### 4.4 SyslogWatcherService — 主守护进程

**职责**：编排 tail 监听 → 解析 → 去重 → 补充详情 → 推送

**流程**：

```
tail -F -n 0 /var/log/netinside/syslog.log
  ↓ 逐行
编码自适应解码（UTF-8 → 含 � 则回退 GBK）
  ↓
SyslogParserService.parse(line)
  ↓ 非告警行则跳过
去重检查（windowSeconds=0 时跳过）
  ↓
AlertEnrichmentService.getAlertDetail({ elogid, starttime, endtime })
  ↓ 失败不影响推送
WeComPushService.pushAlert(alert)
  ↓
企业微信群收到卡片
```

**关键设计决策**：

| 决策 | 说明 |
|---|---|
| 编码自适应 | `iconv-lite` 先 UTF-8 解码，含 `�` 则回退 GBK |
| 去重可配置 | `dedup.windowSeconds=0` 关闭去重，每条都推送 |
| API 失败不阻塞 | 详情补充失败仍推送基础卡片 |
| 优雅退出 | SIGTERM 时输出统计：总行/解析/推送/去重/失败 |
| tail -F（非 -f） | 日志 rotate 后自动重新打开 |

## 5. 关键问题与修复记录

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | systemd 服务无法启动 | `ProtectHome=yes` 阻止 /home 访问 | 改为 `ProtectHome=read-only` |
| 2 | Webhook 返回 invalid url | 用户提供的是智能机器人凭证，非群机器人 | 换用群机器人 Webhook URL |
| 3 | NAPM API 返回 403 | AlertEnrichment 用 POST JSON，NAPM API 是 GET + query string | 改用 `?UserName=xxx&Password=xxx&type=...` |
| 4 | NAPM API 返回 400 | 时间戳未对齐分钟 | `Math.floor(ts/60)*60` |
| 5 | 真实 Syslog 解析不到 | NAPM 时间戳含微秒 `14:44:22.307280`，正则只匹配秒级 | 正则增加 `(?:\\.\\d+)?` |
| 6 | 中文乱码 | NAPM Syslog 输出 GBK 编码，Node.js 按 UTF-8 解码 | `iconv-lite` 自适应：UTF-8 含 `�` 回退 GBK |
| 7 | 严重级别显示 `notice` | 代码先取了 syslog 协议层 severity | 改为 `alert.alertSeverity \|\| alert.severity` |
| 8 | 去重配置 `windowSeconds: 0` 不生效 | JS `0 \|\| 300` = `300` | 改为 `??` (nullish coalescing) |
| 9 | 轻微告警黄色图标乱码 | 🟡 企业微信 Markdown 不支持 | 轻微告警不加 emoji |
| 10 | NAPM API 查详情返回空 | 用了 `alertid`（规则ID）而非 `elogid`（事件ID） | 优先用 `elogid` 查询 |
| 11 | 卡片底部时间显示 `1970/1/1` | NAPM 发 `endtime=0`（告警持续中） | 检测 `endtime ≤ 0`，显示"持续中"，不参与查询 |
| 12 | AlertEnrichment 重复造轮子 | 自建 API 客户端 | 复用 `AlertApiService`（alert-query 技能） |
| 13 | 代码块无复制按钮 | 用了 `markdown`（v1），不支持复制按钮 | 换用 `markdown_v2`，移除不兼容的 `mentioned_list` 字段 |
| 14 | 触发条件含英文级别词（Critical/Major/Minor/None） | NAPM 原始 syslog 输出英文 | 正则替换：`Critical→紧急`、`Major→重大`、`Minor→轻微`、`None→无` |
| 15 | 已恢复告警仍推送 | 指标值 `N/D` 表示告警已恢复/结束 | 所有指标均为 `N/D` 时跳过不推送 |

## 6. 配置设计

配置文件：`config/watcher.config.json`（远端路径 `/home/netinside/.openclaw/workspace/skills/openclaw-napm-syslog-watcher/config/watcher.config.json`）

修改配置后执行 `sudo systemctl restart napm-syslog-watcher` 即可生效，无需重新部署。

```json
{
  "syslog": {
    "path": "/var/log/netinside/syslog.log"
  },
  "napm": {
    "host": "https://101.254.114.238/webservice/NetInside",
    "username": "GAIOP",
    "password": "GAIOP123",
    "tlsInsecure": true,
    "requestTimeoutMs": 15000
  },
  "wecom": {
    "webhookUrl": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx",
    "secret": "",
    "mentionedList": [],
    "mentionedMobileList": [],
    "routing": {}
  },
  "dedup": {
    "windowSeconds": 0,
    "maxCacheSize": 500
  },
  "watcher": {
    "maxRetries": 3,
    "retryDelayMs": 5000
  }
}
```

### 配置项速查

| 想做什么 | 改哪个字段 |
|---|---|
| 推送到另一个群 | `wecom.webhookUrl` |
| 告警太多，想去重 | `dedup.windowSeconds` 设为 `300` |
| 紧急告警 @ 人 | `wecom.mentionedMobileList` |
| 不同级别推不同群 | `wecom.routing` |
| 换 NAPM 地址/密码 | `napm.host` / `napm.username` / `napm.password` |

## 7. 与现有系统的关系

### 7.1 复用 `openclaw-napm-alert-query`

`AlertEnrichmentService` 直接 `require('../../openclaw-napm-alert-query/services/AlertApiService')`，共享同一套 API 客户端。保证：

- URL 构建逻辑一致
- 认证方式一致
- TLS 处理一致
- 与 @机器人 查告警走同一 API、同一参数格式

### 7.2 与 OpenClaw WeCom 机器人的关系

syslog-watcher 和 WeCom 机器人是**独立的两条路径**：

| 路径 | 方向 | 触发方式 |
|---|---|---|
| syslog-watcher → 推送卡片 | 服务器 → 企业微信 | NAPM 发 Syslog 自动触发 |
| @机器人 → 查告警详情 | 企业微信 → 服务器 | 用户主动发消息 |

卡片中 `💬 查详情` 行提供带时间窗口的查询指令，用户复制发给 @机器人即可获取 AI 分析后的完整详情。

### 7.3 不依赖 OpenClaw 网关

syslog-watcher 是独立的 systemd 服务，不依赖 OpenClaw gateway 进程。两者各自运行、互不影响。

```bash
sudo systemctl status napm-syslog-watcher       # 状态
sudo systemctl restart napm-syslog-watcher      # 重启

sudo journalctl -u napm-syslog-watcher -f       # 实时日志

sudo tcpdump -ni any host 101.254.114.238 and udp port 514 -A
sudo tail -f /var/log/netinside/syslog.log
```
