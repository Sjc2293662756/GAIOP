## 2. 推送前检查

先确认工作区变更范围：

```powershell
git status --short --branch
git diff --stat
```

如果只想推送指定文件，必须单独 `git add` 指定文件，不要直接 `git add -A`。

示例：

```powershell
git add README.md
git commit -m "docs: add project readme"
git push origin main
```

## 3. 敏感信息检查

推送前至少检查以下内容：

- `.env`、`.env.*` 不能提交，`.env.example` 可以提交但必须只放占位符。
- 不提交 API Key、数据库密码、企业微信密钥、token、证书、私钥。
- 不提交生产服务器 IP、真实账号、真实密码、真实部署路径。
- 不提交 `logs/`、`node_modules/`、`.codex-temp/`、`.claude/`、远端临时产物。

常用扫描命令：

```powershell
rg -n --hidden --glob '!node_modules/**' --glob '!.git/**' --glob '!logs/**' --glob '!.codex-temp/**' --glob '!.claude/**' -i "api[_-]?key|secret|token|password|passwd|corpsecret|private key|begin certificate|database_url|redis_url"

git status --short --branch
git diff --cached --stat
```

如果发现敏感信息已经进入提交，不能只靠删除文件解决；需要轮换对应密钥，并视情况重写 Git 历史后强制更新远端。

## 4. 首次绑定远端

如果本地还没有远端：

```powershell
git remote add origin https://github.com/haiwanxue/GAIOP.git
git branch -M main
git push -u origin main
```

如果远端已经存在：

```powershell
git remote set-url origin https://github.com/haiwanxue/GAIOP.git
git push origin main
```

如果还需要保留旧仓库作为备用远端：

```powershell
git remote add napm-backup https://github.com/Sjc2293662756/napm.git
```

## 5. 常规更新流程

推荐每次按这个顺序：

```powershell
git status --short --branch
git diff --stat
git add <需要推送的文件或目录>
git diff --cached --stat
git commit -m "<type>: <summary>"
git push origin main
git status --short --branch
```

提交信息示例：

```text
docs: update deployment notes
fix: correct metric routing guard
test: add overview regression case
chore: sync project state
```

## 6. 只保留部分修改的做法

如果工作区里有很多临时修改，但只想推送某一个文件：

```powershell
git status --short --branch
git add README.md
git diff --cached --stat
git commit -m "docs: add project readme"
git push origin main
```

未暂存的修改不会被这次提交推送。

如果需要撤回未提交的本地修改，只保留某个新文件，先确认目标文件未被删除，然后恢复已跟踪文件：

```powershell
git restore .
git status --short --branch
```

注意：`git restore .` 会撤销所有已跟踪文件的未提交改动，执行前必须确认这些改动不需要保留。
