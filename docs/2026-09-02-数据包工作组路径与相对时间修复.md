# 数据包工作组路径与相对时间修复

## 问题

数据包 Skill 原来只接受 IP、IP 段、事件 ID 或业务页面条件。用户以业务组/工作组名称发起数据包预览或下载时，没有成员 IP 发现路径；只提供“最近 5 分钟”等相对时间时，也会因为缺少根级 `start/end` 直接失败。

## 处理结果

### 工作组路径

`napm-packet-analysis` 接受 `groupType=BusinessGroup` 配合 `groupArgument`、`businessGroupName` 或 `businessGroup`。运行时请求 `businessGroups?csv=true`，在 CSV 中按 `Name` 精确匹配工作组，再读取 `IpMembers`：

1. 不含 `-` 的成员放入重复 `ips` 参数；
2. 含 `-` 的成员放入重复 `ipRanges` 参数；
3. 空白成员忽略，重复值去重，非法值记录到 `invalidMembers`。

解析结果写入 `businessGroupResolution`，再复用普通的 `packetsPreview -> packetsDown` 门禁和文件流下载流程。名称不存在或没有有效成员时立即停止，不调用预览或下载接口。

### 时间参数

调用方传入用户原始 `prompt`，或传入具体的 `criteria.timeRange.key`，例如 `last5minutes`、`last1hour`。Skill 复用共享 `ResolvedQueryTimeRangeService`，用运行时服务器时钟计算窗口并将 `start/end` 对齐到分钟边界。

显式根级 `start/end` 优先；`timeRange.start/end` 仍只是声明性元数据，不能替代根级执行时间。模型不得自行计算 Unix 时间戳，也不得通过 shell/date/curl 获取时间。

插件的 `before_tool_call` 会将当前用户原文注入 `napm-packet-analysis`，因此即使模型漏传 `prompt`，相对时间仍能在执行入口解析。

## 验证

- `test/napm-packet-workgroup-time.test.js`：9 个测试通过。
- packet runtime 语法检查通过；关联 plugin 测试中可运行的路由与业务页面守卫通过。
- 更大范围的运行时契约检查受工作树未安装 `js-yaml`、`axios`、`docx`、`node-cache` 等依赖影响。
