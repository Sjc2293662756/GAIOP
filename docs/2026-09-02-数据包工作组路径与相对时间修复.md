# 数据包工作组路径与相对时间修复

## 问题

数据包 Skill 原来只接受 IP、IP 段、事件 ID 或业务页面条件。用户以业务组/工作组名称发起数据包预览或下载时，没有成员 IP 发现路径；只提供“最近 5 分钟”等相对时间时，也会因为缺少根级 `start/end` 直接失败。

## 处理结果

### 工作组路径

`napm-packet-analysis` 现在接受 `groupType=BusinessGroup` 配合 `groupArgument`、`businessGroupName` 或 `businessGroup`。运行时按以下顺序发现可下载的成员 IP：

1. `BusinessGroup -> MemberIPs -> IPAddress`
2. 第一条路径为空或失败时，回退 `BusinessGroup -> ConnectedIPs -> IPAddress`

发现结果会提取并去重 IPv4 地址，写入 `businessGroupResolution`，再复用普通的 `packetsPreview -> packetsDown` 门禁和文件流下载流程。没有可用成员 IP 时停止，不调用预览或下载接口。

### 时间参数

调用方传入用户原始 `prompt`，或传入具体的 `criteria.timeRange.key`，例如 `last5minutes`、`last1hour`。Skill 复用共享 `ResolvedQueryTimeRangeService`，用运行时服务器时钟计算窗口并将 `start/end` 对齐到分钟边界。

显式根级 `start/end` 优先；`timeRange.start/end` 仍只是声明性元数据，不能替代根级执行时间。模型不得自行计算 Unix 时间戳，也不得通过 shell/date/curl 获取时间。

插件的 `before_tool_call` 会将当前用户原文注入 `napm-packet-analysis`，因此即使模型漏传 `prompt`，相对时间仍能在执行入口解析。

## 验证

- `test/napm-packet-workgroup-time.test.js`：8 个测试通过。
- 关联 packet/plugin 套件：29 个测试通过。
- 运行时契约全量检查受工作树未安装 `js-yaml`、`axios`、`docx` 等依赖影响；packet runtime 本身加载通过。
