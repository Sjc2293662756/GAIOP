# 告警间接数据包发现方案

> 状态：设计阶段 | 日期：2026-06-29

---

## 1. 背景

### 1.1 当前行为

`openclaw-napm-alert-query` skill 中，`buildEventPacketHandoff()` 提供告警→数据包的转交链路，仅支持两条路径：

| 条件 | 路径 | 适用场景 |
|------|------|---------|
| `linkType === 2` | 按事件 ID 关联数据包 | 告警直接绑定数据包事件 |
| `linkType === 1` 且 `group` 是 IP | 按 IP 关联数据包 | 告警对象是一个 IP 地址 |
| `linkType === 1` 但 `group` 不是 IP | **返回 null，断掉** | 业务/应用/工作组告警 |

### 1.2 问题

业务告警（WebApplication）、应用告警（DefinedApp/Application）、工作组告警（BusinessGroup）的 `group` 是业务名/应用名/组名，不是 IP 地址。`looksLikeIp()` 校验失败 → `buildEventPacketHandoff()` 返回 `null` → 用户无法从这类告警直接获取数据包。

但实际上，这些告警背后一定有一些 IP 会话触发了指标异常。只要找到这些 IP，就能下载数据包。

---

## 2. 目标

为 `linkType === 1` 且 `group` 不是 IP 的告警，自动发现告警时段内该业务/应用/工作组下最可疑的 IP 会话，并构造对应的数据包下载链接。

**一句话：查告警 → 自动找到嫌疑 IP → 直接给出数据包下载链接，用户一步到位。**

---

## 3. 方案概览

```
业务/应用/工作组告警 (group ≠ IP)
  │
  ├─ Step 1: 检测告警类型
  │     categoryType 属于 {14, 25, 63, 68}
  │     → 识别为"间接数据包"场景
  │
  ├─ Step 2: 自动执行 Discovery 查询
  │     用告警的 categoryType + group + metrics
  │     → 构造 topValues 查询
  │     → 获取 TopN 嫌疑 IP/会话
  │
  └─ Step 3: 构造 indirectPacketCandidates
        每个候选 IP/会话 ±120s 数据包下载链接
        → 交给 openclaw-napm-packet-analysis
```

---

## 4. Discovery 查询构造规则

### 4.1 映射表

| 告警 categoryType | groupType1 | groupType2 | groupType3 | 默认 topMetric | 结果 key 格式 |
|---|---|---|---|---|---|
| 68 (WebApplication) | `WebApplication` | `ClientIPs` | `IPAddress` | `PGNPGE` | 单个 IP |
| 25 (Application) | `DefinedApp` | `IPConversations` | `IPConversation` | `TPIO` | `IP\|IP` |
| 14 (BusinessGroup) | `BusinessGroup` | `IPConversations` | `IPConversation` | `TPIO` | `IP\|IP` |
| 63 (PageFamily) | `PageFamily` | `ClientIPs` | `IPAddress` | `PGNPGE` | 单个 IP |

### 4.2 参数取值策略

| 参数 | 来源 |
|------|------|
| `start` / `end` | 告警的 `start` / `end`（直接用告警触发时间窗口） |
| `metrics` | 告警的 `metrics[0]`，若无则用默认 topMetric |
| `topMetric` | 业务类→`PGNPGE`，应用/工作组→`TPIO` |
| `topCount` | 默认 10（可配置 `options.discoveryTopCount`） |
| `groupArgument1` | 告警的 `group` 字段 |
| `json` | `true` |

## 6. 数据包时间窗口

```
packetStart = 告警 start - bufferSeconds  (默认 120s)
packetEnd   = 告警 end   + bufferSeconds  (默认 120s)
```

`bufferSeconds` 可配置，默认 120 秒（前后各 2 分钟）。

## 8. 新增模块设计

### 8.1 AlertIndirectPacketDiscoveryService

```
services/AlertIndirectPacketDiscoveryService.js
```

**职责：**

1. 判断告警是否需要间接数据包发现
2. 根据 `categoryType` 构造 discovery 查询参数
3. 调用 `AlertApiService.getJsonByParams('topValues', params)`
4. 解析 topValues 返回结果（IP 或 IP|IP）
5. 去重并排序，生成 `indirectPacketCandidates`

**核心方法：**

```js
// 判断是否触发间接发现
shouldDiscover(event): boolean

// 构造 discovery 查询参数
buildDiscoveryParams(event, options): object

// 执行 discovery 查询
async discover(api, event, options): DiscoveryResult

// 解析 topValues 返回结果 → IP 列表
parseTopValuesResult(rawData, categoryType): IPCandidate[]

// 批量执行（多个 event 时去重）
async discoverForEvents(api, events, options): IndirectPacketResult
```

### 8.2 判断条件

```js
function shouldDiscover(event) {
  // linkType=2 走直接路径，不需要发现
  if (Number(event.linkType) === 2) return false;
  // linkType=1 且 group 是 IP，走直接路径
  if (Number(event.linkType) === 1 && looksLikeIp(event.group)) return false;
  // group 为空，无法发现
  if (!event.group) return false;
  // categoryType 必须在支持映射表中
  if (!DISCOVERY_GROUP_CHAIN_MAP[event.categoryType]) return false;
  return true;
}
```

## 9. 错误处理

| 场景 | 处理策略 |
|------|---------|
| discovery 查询返回空结果 | `packetHandoff.available = false`，reason = `ALERT_INDIRECT_DISCOVERY_EMPTY` |
| discovery 查询网络失败 | 记录 warning，packetHandoff 为 null，不阻断告警主流程 |
| 返回的 IP 数量超过 topCount | 只取前 topCount 个 |
| IPConversation 解析失败（非 `\|` 格式） | 跳过该条，记录 warning |
| 告警没有 metrics 也没有默认 topMetric | 使用默认 topMetric（业务→PGNPGE，应用/工作组→TPIO） |
| 同一 IP 出现在多个 rank | 去重，保留最高 rank |

## 10. 执行流程

```
executeAlertQuery()
  │
  ├─ summary / analysis 模式 → 获取告警事件列表
  │
  ├─ 现有逻辑: result.packetHandoff = buildPacketHandoff(events, criteria)
  │     │
  │     └─ buildPacketHandoff()
  │           │
  │           └─ buildEventPacketHandoff(event, criteria)
  │                 │
  │                 ├─ linkType=2          → 直接: 按事件 ID    [现有]
  │                 ├─ linkType=1 + IP     → 直接: 按 IP        [现有]
  │                 └─ 业务/应用/工作组     → 间接: Discovery   [新增]
  │                       │
  │                       ├─ shouldDiscover(event) → true
  │                       ├─ buildDiscoveryParams(event, options)
  │                       ├─ api.getJsonByParams('topValues', params)
  │                       ├─ parseTopValuesResult(rawData, categoryType)
  │                       └─ 生成 indirectPacketCandidates
  │
  └─ 返回 result（含 packetHandoff）
        → OpenClaw 渲染时展示: "发现 3 个嫌疑 IP，可下载对应数据包"
```

## 11. 配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `options.packetHandoff` | `true` | 总开关，false 时跳过所有数据包转交 |
| `options.discoveryTopCount` | `10` | discovery 查询返回的 TopN 数量 |
| `options.packetBufferSeconds` | `120` | 数据包下载的前后扩展秒数 |
| `options.discoveryEnabled` | `true` | 间接发现子开关（默认开） |

## 13. 限制与后续扩展

- **v1 范围**：仅支持 categoryType 68/25/14/63，按固定 group chain 查询
- **v1 不包含**：多级 drill-down 后进一步筛选、跨多个 group chain 的联合发现
- **后续可扩展**：支持自定义 group chain、支持并发 discovery 查询加速、支持按多个指标加权排序
