# 项目整体背景信息（新线程版）

## 1. 项目定位

本项目是 `NAPM_Semantic_Gateway`，当前主要作为 OpenClaw 本地 NAPM 查询运行时与公共基础仓库使用。

核心定位：

- Skill 是“语义解析 + API 拼装 + 查询执行 + 机器载荷封装”主链
- OpenClaw 是“意图承接 / 对话编排 / 结果叙述”主入口

---

## 2. 现阶段总体架构

当前采用 `Skill 自主解析 + 直接查询 NAPM` 主链路：

- OpenClaw / 企微插件侧：
  - 透传用户问句
  - 调用本地 skill 执行器
- Skill 运行时侧：
  - 解析对象、指标、时间、服务模式
  - 做必要的指标归一与参数修正
  - 直接调用 NAPM API
  - 返回 `summary / rows / structuredRows / narrationInput`

已明确不再保留为当前主链的旧思路：

- 本地 gateway 路由承接查询请求
- 旧 `/api/gateway` 查询入口
- 以网关为中心的 parse/postProcess 主链

---

## 3. 关键职责边界（当前约定）

## 3.1 OpenClaw 侧职责

- 判定：是否可执行、执行什么动作
- 语义：对象类型、指标、时间、服务模式
- 打分：置信度、策略选择
- 叙述：把 skill 返回的结构化结果转自然语言

## 3.2 Skill 运行时职责

- 接受自然语言 `prompt` 或结构化 `resolvedQuery`
- 本地完成对象识别、指标映射、时间解析、参数构造
- 做执行安全归一（例如非法指标不下发）
- 返回统一机器载荷（`rows/structuredRows/summary/narrationInput`）

---

## 4. 当前主链路流程（从用户问句到上游 API）

1. 用户在 OpenClaw 提问  
2. OpenClaw / 插件调用 `skills/openclaw-napm-query/scripts/run_napm_query.js`  
3. Skill 执行器调用内部服务链完成语义解析  
4. Skill 构建并调用 NAPM API  
5. Skill 返回结构化结果：
   - `summary`
   - `rows / structuredRows`
   - `requestParamsJson`
   - `narrationInput`
6. OpenClaw 根据 `narrationInput` 叙述给最终用户

---

## 5. 元数据查询口径（当前生效）

这部分是本项目当前最关键的执行口径：

- 查“应用清单”：`type=applications`
- 查“WebApplication 维度下可选对象”：`type=groupArguments&argumentType=4`
- 查“业务组清单”：`type=businessGroups`
- 查“一级分组树”：`type=groups`
- 查“指标列表”：`type=metrics`

---

## 6. 业务语义口径（项目约定）

- `业务组 / 业务分组 / 工作组` -> `BusinessGroup`
- `业务 / 业务系统 / Web应用 / 网站 / 站点` -> `WebApplication`

说明：

- 该口径应由 OpenClaw 主判稳定输出
- skill 侧应避免长期堆叠“词语补丁式”语义改写

---

## 7. 近期关键修复概览（影响主链路）

## 7.1 指标归一与执行保护

- 修复了别名透传问题（如 `connectionFailureCount`、`http500Count`）
- 统一归一到标准码（如 `RFCI`、`PGHTTP500`）
- 对执行型请求增加“无合法指标码不下发”保护

## 7.2 Web 应用类对象查询口径修正

- WebApplication 列表改为 `groupArguments(argumentType=4)` 口径
- Debug API 展示与真实执行参数对齐

## 7.3 机器叙述载荷兼容增强

- 补齐 `rows/structuredRows/summary.rowCount/summary.empty`
- 降低 OpenClaw 侧因字段读取差异导致的“误判空结果”风险

---

## 8. 当前配置重点（以远端运行环境为准）

常见关键开关：

- `SKILL_FORWARD_DISPLAY_TEXT=false`
- `SKILL_ENABLE_GATEWAY_SKILL_BRIDGE=false`

解释：

- `SKILL_FORWARD_DISPLAY_TEXT=false` 表示优先走机器载荷叙述
- `SKILL_ENABLE_GATEWAY_SKILL_BRIDGE=false` 表示默认不走旧网关桥接

---

## 9. 关键入口文件

- 本地运行入口：`src/app.js`（仅保留 `health/static`）
- 执行服务：`skills/openclaw-napm-query/services/RequirementParserService.js`
- 元数据服务：`skills/openclaw-napm-query/services/NapmMetadataService.js`
- 指标映射服务：`skills/openclaw-napm-query/services/MetricMappingService.js`
- Skill 执行器：`skills/openclaw-napm-query/scripts/run_napm_query.js`
- OpenClaw skill agent 提示：`skills/openclaw-napm-query/agents/openai.yaml`

---

## 10. 当前已知风险

1. 上游主判稳定性风险  
同一语义问法可能漂移到不同对象类型，直接影响查询对象。

2. 叙述侧字段消费差异风险  
若 OpenClaw 未统一消费 `narrationInput.result`，可能出现“有数据但说无数据”。

3. 临时补丁膨胀风险  
若继续沿用旧网关时代的语义补洞方式，会削弱当前 skill 直查边界并引入冲突。

---

## 11. 新线程建议起手动作

1. 先固定“职责边界”不再争论：OpenClaw 承接对话，skill 负责直查执行。  
2. 用 10~20 条核心问句做回归矩阵（业务、业务组、应用、Web、指标支持、总流量、TopN）。  
3. 每条用例同时记录：
   - 上游 `resolvedQuerySeed`
   - skill `requestParamsJson`
   - NAPM 原始返回行数
   - OpenClaw 最终叙述
4. 所有修复优先放在 skill 解析链与上游提示模板，其次才是执行保护。
