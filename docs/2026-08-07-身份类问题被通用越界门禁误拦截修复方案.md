# 身份类问题被通用越界门禁误拦截修复方案

日期：2026-08-07  
适用范围：OpenClaw 企业微信通道、NAPM OpenClaw 插件、观枢AI 身份与能力自述

## 1. 问题现象

用户在企业微信中询问：

```text
你是谁？
```

系统没有按照 `IDENTITY.md` 和 `SOUL.md` 介绍观枢AI，而是返回通用域外文案：

```text
我当前只处理系统监控、性能分析、NAPM 查询和结果解读相关问题。
像天气、闲聊、泛问答这类内容不在当前技能范围内。
如果你是想看系统情况，可以直接问我：239web最近异常吗、某系统今天比昨天差吗、这个监控结果怎么理解。
```

同类风险还包括：

- 你叫什么名字？
- 你的身份是什么？
- 你是做什么的？
- 你能做什么？
- 你有哪些能力？
- 你运行在哪里？
- 你基于什么平台？
- 请介绍一下你自己。

因此身份上下文存在且内容正确；最终答案是被插件输出钩子覆盖的。

## 3. 根因分析

### 3.1 将“非 NAPM”错误等同于“通用越界”

会话状态当前使用以下判定：

```js
generalOutOfScopeRequested: Boolean(prompt) && !domainRelated
```

“你是谁？”不包含系统、网络、应用、告警、性能等 NAPM 领域关键词，因此：

```text
domainRelated=false
napmRelated=false
generalOutOfScopeRequested=true
```

这里缺少“平台身份与能力自述”这一独立消息类型。

### 3.2 prompt-build 阶段再次执行相同误判

即使 `message_received` 的状态被修正，`before_prompt_build` / `before_agent_start` 仍会根据 `!effectiveDomainRelated` 重新生成 `generalOutOfScopeRequested`。

因此只修改一个状态构造点不能解决完整链路问题。

### 3.3 两个输出钩子强制覆盖模型答案

以下钩子都会读取 `generalOutOfScopeRequested`：

1. `message_sending`
2. `before_message_write`

任一状态命中后，插件都会使用 `buildGeneralOutOfScopeReply()` 覆盖已有回答。即使模型已经依据身份卡生成正确答案，最终用户仍只能看到域外文案。

### 3.4 路由上下文没有声明身份问答例外

插件注入的通用边界规则目前只写明“仅处理监控/NAPM，天气/闲聊应重定向”，没有告诉模型身份与能力自述属于允许的平台交互。

即使取消输出覆盖，模型仍可能根据过宽的边界说明自行拒答。

### 3.5 测试覆盖缺口

现有域外守卫测试覆盖了天气问题，但没有覆盖：

- 身份问题不应被改写；
- 能力自述不应被改写；
- 身份问题不需要调用 `napm-skill-query`；
- 身份问答后，下一条天气问题仍应被拦截。

## 4. 正确的消息分类模型

插件边界至少需要区分四类消息：

| 分类 | 示例 | 是否调用 NAPM skill | 是否使用通用域外文案 |
| --- | --- | --- | --- |
| NAPM 业务请求 | 现在系统情况怎么样？ | 是 | 否 |
| 平台身份/能力请求 | 你是谁？你能做什么？ | 否 | 否 |
| OpenClaw 原生命令 | `/new`、`/status` | 否，由 OpenClaw 处理 | 否 |
| 真正的通用域外请求 | 今天天气怎么样？ | 否 | 是 |

身份问题不能通过设置 `napmRelated=true` 来绕开门禁，因为这会引入错误的 NAPM 工具强制要求。

## 5. 修复设计

### 5.1 新增平台身份分类器

新增：

```js
isPlatformIdentityPrompt(prompt)
```

分类器只识别明确指向当前助手的身份、能力、定位和运行平台问题，不把普通业务查询或泛问答放行。

### 5.2 扩展会话状态

在会话状态和 guard 状态中保存：

```js
platformIdentityPrompt: true | false
```

通用域外判定调整为：

```js
generalOutOfScopeRequested = Boolean(prompt)
  && !domainRelated
  && !platformIdentityPrompt;
```

该逻辑必须同时应用于：

- `buildConversationScopedGuardState()`；
- `before_prompt_build` / `before_agent_start` 的 guard 重建逻辑。

### 5.3 明确身份问答路由契约

当 `platformIdentityPrompt=true` 时，注入明确规则：

```text
这是允许的平台身份/能力问题。
直接依据 IDENTITY.md 和 SOUL.md 回答。
不得调用 NAPM skill，不得返回天气/闲聊域外文案。
```

身份事实继续由 OpenClaw workspace 的身份文件维护，插件不重复硬编码完整身份卡，避免双份配置漂移。

### 5.4 保持既有边界

本次修复不修改以下行为：

- 天气、娱乐、泛闲聊继续返回统一域外文案；
- NAPM 查询继续要求正确的 skill 结果；
- `/new`、`/reset` 等 OpenClaw 原生命令继续走既有旁路；
- 身份问题不继承上一轮 NAPM 工具要求；
- 身份问题也不会让下一轮天气问题获得放行。

## 6. 回归测试

1. “你是谁？”在 `message_sending` 中不被改写。

5. 身份类问题不要求 `napm-skill-query`，也不触发 NAPM 工具兜底。
6. 路由上下文明确要求依据身份文件直接回答。
7. 天气问题仍在两个输出钩子中被改写。
8. 身份问题之后的新天气轮次仍被正确拦截。
9. OpenClaw 原生命令专项测试继续通过。
