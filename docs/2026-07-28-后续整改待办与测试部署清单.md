## 暂缓项：T08 报告 MEDIA 交付

### 简单说明

现在系统可以生成 Word 文件，但尚未确认 OpenClaw 工具结果和企业微信通道到底要求哪个“附件字段”。因此当前只能返回报告的文字说明和文件信息，不能保证用户会在企业微信里收到可下载的附件。

在未确认实际契约前，不能猜测字段名后上线；否则系统可能显示“报告已生成”，而用户实际收不到文件。

### 已确认根因

- 报告工具没有返回已验证可被 OpenClaw/企业微信消费的 MEDIA 附件结构。
- 报告默认写到源码目录，运行数据与部署代码混放。
- 下载地址只是相对路径，缺少鉴权、签名和有效期。
- 缺少“文件生成 -> 附件投递 -> 通道确认/失败 -> 重试”的状态追踪。

### 下次开始前的只读确认

1. 在测试服务器确认当前 OpenClaw 版本的工具结果媒体契约。
2. 确认企业微信通道支持的文件附件字段、上传方式、大小限制和发送回执。
3. 选定独立报告运行目录、受控下载服务或对象存储，以及访问授权和保留期策略。
4. 基于真实契约实现投递适配器和按会话隔离的发送状态机。
5. 做一次企业微信端到端验收：用户收到可打开的 Word，发送失败可追踪和重试，未授权用户不能长期访问文件。

## 本次测试建议

1. 先验证普通查询、告警、综述、故障诊断和报告生成仍可正常调用。
2. 用两个独立会话交错执行查询、告警和报告跟进，确认无串会话。
3. 通过受控方式制造 API 失败或空数据，确认不会得到“健康”或“报告已就绪”的错误结论。
4. 验证普通查询和数据包报告能生成 Word；本轮只验证生成，不把“企业微信收到附件”作为通过条件。
