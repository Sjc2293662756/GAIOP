# 告警间接数据包发现 — 完整技术方案

> 日期：2026-06-30 | 状态：已验收通过

---

## 1. 概述

当 NAPM 告警的对象是业务/应用/工作组（而非 IP 地址）时，无法直接下载数据包。本方案通过**间接发现**——自动查询告警时段内该业务/应用下最可疑的 IP 会话——生成数据包下载候选，再调用 packet-analysis 完成抓包分析。

---

## 4. 核心数据流

### 4.1 categoryType 映射

```
alertsDetail API 返回 categoryType
         │
         ▼
CATEGORY_TYPE_TO_GROUP_TYPE (AlertConstants.js)
  ├─ 14 → 'BusinessGroup'
  ├─ 25 → 'DefinedApp'
  ├─ 51 → 'DefinedApp'     ← 原 'OtherApp'，修正为 NAPM API 实际名称
  ├─ 56 → 'OtherApp'
  ├─ 63 → 'PageFamily'
  └─ 68 → 'WebApplication'
         │
         ▼
DISCOVERY_GROUP_CHAIN_MAP (AlertIndirectPacketDiscoveryService.js)
  ├─ 14: groupType2='IPConversations', groupType3='IPConversation', topMetric='TPIO'
  ├─ 25: groupType2='IPConversations', groupType3='IPConversation', topMetric='TPIO'
  ├─ 51: groupType2='IPConversations', groupType3='IPConversation', topMetric='TPIO'
  ├─ 63: groupType2='ClientIPs',       groupType3='IPAddress',      topMetric='PGNPGE'
  └─ 68: groupType2='ClientIPs',       groupType3='IPAddress',      topMetric='PGNPGE'
         │
         ▼
buildDiscoveryParams():
  groupType1 = event.groupType || CATEGORY_TYPE_TO_GROUP_TYPE[categoryType]  ← 不写死
  groupArgument1 = event.group  ← 告警对象名
```

### 4.2 发现查询

```
topValues API:
  ?type=topValues
  &numGroups=3
  &groupType1=DefinedApp          ← 从映射表动态获取
  &groupArgument1=SSH             ← 告警的 group
  &groupType2=IPConversations     ← DISCOVERY_GROUP_CHAIN_MAP
  &groupType3=IPConversation      ← DISCOVERY_GROUP_CHAIN_MAP
  &metrics=TPIO                   ← 告警 metrics[0] 或 defaultTopMetric
  &topMetric=TPIO
  &topCount=5                     ← discoveryTopCount
  &start/end=<用户提供的时间范围>
```

### 4.3 时间窗口策略

| 用途 | 时间来源 | 说明 |
|------|---------|------|
| **alertsDetail 查询** | 用户提供的 start/end | 宽窗口确保查到告警 |
| **discovery topValues** | 用户提供的 start/end | NAPM API 需要足够的窗口 |
| **packet download** | 告警自身 start/end ± 120s | 精确抓取异常时刻 |
| **endtime=0 兜底** | start + period 或 start + 300s | `resolveAlertTimeWindow` |

### 4.4 parseTopValuesResult 三种格式

```js
// 格式 1: { topValues: [{ key, metricValues }] }  — 标准 topValues
// 格式 2: { "10.1.1.5": 156, ... }                — 简化键值对
// 格式 3: [{ group: { argument, key }, groupPath }] — 树形 drill-down
```

### 4.5 packetInstruction 动作

| action | callPacketAnalysis | 触发场景 |
|--------|-------------------|---------|
| `USE_CANDIDATES` | true | 间接发现成功，有候选 IP |
| `STOP_NO_PACKET` | false | 无 packetHandoff |
| `STOP_DISCOVERY_EMPTY` | false | 发现结果为空 |
| `STOP_DISCOVERY_FAILED` | false | 发现执行出错 |
| `STOP_DISCOVERY_OBJECT_NOT_FOUND` | false | 告警对象在 NAPM 不存在（含 fallback） |
| `USE_DIRECT_QUERY` | true | 直接路径（linkType=2 或 IP） |

## 6. 错误处理

| 场景 | 行为 |
|------|------|
| categoryType 不在映射表 | `shouldDiscover` false → packetHandoff null |
| 告警 metrics 为空 | 使用 defaultTopMetric |
| endtime=0 | `resolveAlertTimeWindow` 用 period 或默认 300s |
| topValues 返回空 | `ALERT_INDIRECT_DISCOVERY_EMPTY` |
| topValues 返回 400 | fallback 去掉 groupArgument1 重试 → `ALERT_INDIRECT_DISCOVERY_OBJECT_NOT_FOUND` |
| API 返回树形格式(3) | `parseTopValuesResult` 自动识别 |
| API 网络错误 | `ALERT_INDIRECT_DISCOVERY_FAILED`，不阻断主流程 |
