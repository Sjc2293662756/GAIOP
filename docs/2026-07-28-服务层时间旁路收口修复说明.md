# 服务层时间旁路收口修复说明

## 问题

综述和故障诊断服务此前可在未收到完整时间范围时，自行按当前时间生成默认窗口。该路径会绕过统一的分钟对齐规则，导致真实 API 请求出现非整分钟的 `start/end`。

## 修复

- 执行入口统一通过时间解析器生成执行时间范围。
- 执行时间范围被冻结，`start/end` 必须是 Unix 秒且为 60 的整数倍。
- 综述和故障诊断服务只接受该执行时间范围；缺失或直接传普通时间对象会在调用 API 前失败。
- 故障诊断的基线窗口必须同时提供 `start/end`，并按同一规则向下对齐到整分钟。

## 结果

服务层不再自行取当前时间，也不再自行决定默认时间窗口。所有进入 API 的时间参数由同一个规则生成，满足后端对整分钟的要求。

## 验证

已通过定向回归：5 个测试套件、30 项测试。覆盖相对时间、显式时间、综述、故障诊断、基线窗口和服务层拒绝旁路输入。

已部署至测试环境并完成重启后验证。运行中的网关状态正常，插件侧和服务侧的离线时间检查均通过，未发起业务数据请求。
