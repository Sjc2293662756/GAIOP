# 查询工作流第二阶段对象本体收口说明

## 背景

第一阶段已经引入 `WorkflowClassifierService`，先判断用户问题属于 `object_inventory`、`metric_inventory`、`drilldown_catalog` 等 workflow。

第二阶段继续收口对象语义：同一个对象不能在 plugin、resolver、metadata service、输出层各自维护别名、provider 和应用类型过滤规则。否则会出现：

- “业务”一层理解为 WebApplication，另一层改成 BusinessGroup。
- “自动识别应用”一层理解为 CompositeApplication，另一层改成 DefinedApp。
- WebApplication 和 DefinedApp 都走 applications，但 Type 过滤混用。

## 新增对象本体配置

新增：

```text
config/object-ontology.v1.json
```

该配置统一定义：

- `objectType`
- `inventoryProvider`
- `apiType`
- `executionGroupType`
- `applicationTypeFilter`
- `applicationCatalogRole`
- `cnAliases`
- `enAliases`
- `description`

当前已收口对象：

```text
BusinessGroup -> businessGroups
WebApplication -> applications Type=3
DefinedApp -> applications Type=2
CompositeApplication -> applications Type=4
BuiltinApplication -> applications Type=1
OtherApp -> groupArguments
PageFamily -> groupArguments
User -> groupArguments
ClientBusinessGroup -> groupArguments
```

## 新增 ObjectOntologyService

新增：

```text
skills/openclaw-napm-query/services/ObjectOntologyService.js
```

职责：

- 加载 `object-ontology.v1.json`。
- 按对象类型返回 provider 绑定。
- 按对象类型返回别名。
- 根据文本识别对象类型。
- 提供 plain application 歧义候选集。

## 接入点

### ObjectMetadataRegistry

`ObjectMetadataRegistry` 不再手写 WebApplication、DefinedApp、CompositeApplication、BuiltinApplication、BusinessGroup 的 provider 绑定，而是从 `ObjectOntologyService.resolveObjectInstanceProvider()` 读取。

保留 `Application -> DefinedApp` 的兼容映射。

### ApplicationCatalogSemanticRules

应用对象分类规则不再手写每个对象正则，而是从对象本体读取别名生成匹配规则。

plain “应用”仍保持歧义，不强行默认到某一类：

```text
WebApplication
DefinedApp
BuiltinApplication
CompositeApplication
OtherApp
```

### WorkflowClassifierService

workflow 分类后的 `targetObjectType` 由 `ObjectOntologyService.classifyObjectText()` 识别，避免 workflow 层重复维护对象别名。

## 设计边界

本阶段不改变南向 API 调用方式，只改变对象语义和 provider 绑定的真相源。

`NapmMetadataService` 仍负责实际 provider 执行：

- `applications`
- `businessGroups`
- `groupArguments`

后续第三阶段再拆 `MetadataExecutionKernel` 和 `MetricExecutionKernel`。

## 回归测试

新增：

```text
test/object-ontology-service.test.js
```

验证点：

- BusinessGroup provider 必须是 `businessGroups`。
- WebApplication 必须是 `applications Type=3`。
- DefinedApp 必须是 `applications Type=2`。
- CompositeApplication 必须是 `applications Type=4`。
- BuiltinApplication 必须是 `applications Type=1`。
- ObjectMetadataRegistry 的 provider 绑定来自对象本体。
- “系统都有哪些工作组”识别为 BusinessGroup。
- “系统中有哪些自动识别的应用”识别为 CompositeApplication。
- plain “系统中有哪些应用”保持歧义候选，不直接默认。

## 价值

完成后，对象口径形成一条统一链路：

```text
object-ontology.v1.json
  -> ObjectOntologyService
  -> WorkflowClassifierService
  -> NapmResolvedQueryResolverService
  -> ObjectMetadataRegistry
  -> NapmMetadataService
```

这能减少对象语义漂移和 provider 选择漂移，为第三阶段执行内核分层打基础。
