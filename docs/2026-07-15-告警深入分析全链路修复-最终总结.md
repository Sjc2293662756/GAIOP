## 2. 全部修复明细

### 修复① — filterEvents 空 metrics 误杀
**文件**: `skills/openclaw-napm-alert-query/services/AlertNormalizerService.js`
**问题**: NAPM `alertsDetail` API 返回 `metrics: []`。AI 将指标名作为 `criteria.metrics` 过滤条件，`[].some()` 返回 false 误杀事件。
**修改**: `event.metrics.length > 0` 前置保护。

### 修复② — 深入分析格式缺触发指标值
**文件**: `skills/openclaw-napm-syslog-watcher/services/WeComPushService.js`
**问题**: 旧格式只有指标名，AI 将其解析为过滤条件。缺失实际值/级别/条件。
**修改**: 新增"触发指标值"、"告警级别"、"触发条件"上下文行。

### 修复③ — buildFocusAnalysis 不支持外部注入
**文件**: `skills/openclaw-napm-alert-query/services/AlertIndirectPacketDiscoveryService.js`
**问题**: 仅从 `event.metrics` 提取，API 返回空时输出 `hasTriggerMetrics: false`。
**修改**: 新增 `buildFocusFromExternalMetrics()`，`buildFocusAnalysis(event, options)` 支持 `options.alertTriggerMetrics` 外部注入。

### 修复④ — normalizeAnalysisOptions 丢弃告警上下文
**文件**: `skills/openclaw-napm-packet-analysis/scripts/run_packet_analysis.js`
**问题**: 只提取 5 个开关字段，丢弃 metrics/instruction/values。
**修改**: `buildAlertAnalysisContext()` 保留 → `analyzePacketFile` 嵌入 → `buildNarrationInput` 生成 `alertRenderHint`。

### 修复⑤ — 远端 .env 缺 TLS 配置
**文件**: `/home/netinside/.openclaw/workspace/.env`
**问题**: `AlertApiService` 用 `NETINSIDE_TLS_INSECURE`，`packet-analysis` 用 `NETINSIDE_TLS_REJECT_UNAUTHORIZED`。后者未配置。
**修改**: 新增 `NETINSIDE_TLS_REJECT_UNAUTHORIZED=false`。

### 修复⑥ — packet-analysis .env 加载路径不健壮
**文件**: `skills/openclaw-napm-packet-analysis/scripts/run_packet_analysis.js`
**问题**: 仅从 `process.cwd()/.env` 加载，gateway 以非 workspace cwd 启动时失败。
**修改**: 新增 `loadDotEnvCandidates`，多路径依次尝试。

### 修复⑦ — exec/curl 绕过 skill
**文件**: `napm-openclaw-plugin.remote.js`
**问题**: AI 绕过 `napm-packet-analysis`，用 `bash`+`curl`+硬编码错误密码发 NAPM 请求。
**修改**: `activePacketPrompt` + `isDangerousSystemTool` + NAPM URL 检测 → 拦截。

### 修复⑧ — napm-skill-query auto-repair 在 packet 场景误修
**文件**: `napm-openclaw-plugin.remote.js`
**问题**: AI 用 `napm-skill-query` 查 IP 会话，被 auto-repair 修成错误 metric 查询。
**修改**: `napm-skill-query` auto-repair 入口增加 `&& !activePacketPrompt`。

### 修复⑨ — USE_CANDIDATES 响应格式太弱
**文件**: `napm-openclaw-plugin.remote.js`
**问题**: AI 看到 `USE_CANDIDATES` 响应后不调 `napm-packet-analysis`，误以为查询已完成。
**修改**: 重写为顶部 `🚨🚨🚨 下一步操作（必须执行）🚨🚨🚨` + 禁止/必须清单。

### 修复⑩ — "用户体验时间" 触发 fault-diagnosis
**文件**: `napm-openclaw-plugin.remote.js`
**问题**: `isFaultDiagnosisPrompt` 正则含 `用户体验时间`，所有深入分析 prompt 都被导向故障诊断。
**修改**: `isFaultDiagnosisPrompt` 增加"告警数据包"例外；fault guard 增加 `&& !activeAlertPacketPrompt`。

### 修复⑪ — key=value 格式防 AI 漏参
**文件**: `skills/openclaw-napm-syslog-watcher/services/WeComPushService.js`
**问题**: 位置参数 `分析这个告警数据包 <id> <start> <end>` AI 频繁漏传 start/end。
**修改**: 改为 `分析告警数据包 eventId=<id> start=<start> end=<end>`。

### 修复⑫ — time override 不兼容扁平参数
**文件**: `napm-openclaw-plugin.remote.js`
**问题**: AI 传扁平格式 `{ eventIds, mode }` 无 `alertQuery` 包装，time override 跳过。
**修改**: 兼容三种格式：嵌套 `alertQuery.criteria`、`criteria` 扁平、完全扁平。

### 修复⑬ — AI 误读 Password=*** 为占位符
**文件**: `napm-openclaw-plugin.remote.js`
**问题**: `publicPacketUrl` 返回 `Password=***`，AI 误以为需自己填密码，猜错导致 403。
**修改**: `buildPacketAnalysisReply` 追加安全提示，明确告知认证已内部处理。

### 修复⑭ — displayText 格式对齐期望模板
**文件**: `skills/openclaw-napm-alert-query/services/AlertNarrationContractService.js`
**问题**: `buildDisplayText` 只展示有数据的类别和 3 条 overviewEvents，不分组。
**修改**: 重写 `buildDisplayText`——全 7 类别、name+severity 分组聚合（次数/时长/开始时间）、空类别显式标注、组间 `---` 分隔、`🟢` 轻微。

### 修复⑮ — SKILL.md 模板同步
**文件**: `skills/openclaw-napm-alert-query/SKILL.md`
**修改**: 更新 `displayText` 格式示例与修复⑭的实际输出一致，补充格式规则说明。

## 8. 已知限制：displayText 模板无法强制 AI 原样输出

### 问题

Skill 已生成完整格式化的 `displayText`（含全 7 类别、分组聚合、空类别标注），但 AI（deepseek-chat）始终用自己的话重新组织输出（markdown 表格、列表等），不遵守模板。

### 尝试过的方案

| 方案 | 结果 |
|---|---|
| `{ finalAnswer: renderedText }` | AI 忽略，自述输出 |
| `{ displayText: renderedText }`（OpenClaw SDK） | AI 忽略 |
| System prompt "Prefer displayText directly" | AI 忽略 |
| SKILL.md 明确标注"直接返回，一字不改" | AI 忽略 |

### 根因

OpenClaw 平台 + deepseek-chat 模型架构下，AI 拥有**最终叙述权**。Skill/Plugin 返回的任何文本（`finalAnswer`、`displayText`、`text`）都只是建议，AI 可以自由改写。OpenClaw SDK 的 `withDisplayText()` 是为 Teams/WeCom 交互卡片设计的，不作为通用工具响应的强制输出机制。

### 唯一可靠绕过方案

**直接通过企微 Webhook 发送**——类似 syslog-watcher 推送告警卡片的方式。即 Plugin 在工具执行后，不通过 AI 返回结果，而是直接调企微 API 将格式化文本作为独立消息发送到群聊。这需要架构级改动，当前未实施。
