# 2026-04-29 Skill服务迁移收口说明

## 本次调整

为配合“Skill 自主解析 + 直接查询 NAPM，上层不再依赖网关参与请求”的方案，本次继续完成了下面几件事：

1. 将仍然承担查询语义解析职责的运行时服务保留在：
   - `skills/openclaw-napm-query/services/`

2. 让 `skills/openclaw-napm-query/scripts/run_napm_query.js` 以 Skill 自身为主入口：
   - 优先接受外部直接传入的 `resolvedQuery`
   - 若只给自然语言 `prompt`，则直接调用 Skill 内部解析链 `mapNaturalLanguageWithMetadata`
   - 解析完成后直接执行 NAPM 查询
   - 查询结果直接封装为 OpenClaw 叙述契约返回

3. 修复迁移过程中损坏的关键文件：
   - `skills/openclaw-napm-query/services/CandidateSpecBuilder.js`
   - `skills/openclaw-napm-query/services/ClarificationGateService.js`
   - `skills/openclaw-napm-query/services/OpenClawNarrationContractService.js`
   - `skills/openclaw-napm-query/scripts/run_napm_query.js`

4. 修复对应测试文件编码损坏问题：
   - `test/openclaw-narration-contract.test.js`

## 当前结构理解

现在项目里已经不再保留以旧服务目录为主的运行时查询链。

当前语义查询核心链路主要分成两块：

- `skills/openclaw-napm-query/services/`
  - Skill 内部的对象识别、指标识别、时间识别、参数修正、元数据约束、直查执行辅助

- `src/utils/` / `src/constants/`
  - 仍然作为公共基础工具层被 Skill 复用

也就是说，`src` 现在更像“公共底座”，而不是“查询网关主链”。

## 结果

本次收口后，方向已经更一致：

- 不再依赖本地 gateway parse/postProcess 主链
- Skill 可以自己根据自然语言做解析
- Skill 可以自己执行查询
- Skill 可以直接返回给 OpenClaw 做叙述

后续如果继续清理，可以优先处理两类内容：

1. 文档里仍然引用旧服务目录的历史说明
2. 旧网关思路相关的历史入口说明
