# 2026-05-19 OpenClaw 路径预判器接入说明

最后更新：2026-05-19

## 1. 问题背景

当前问题不是 OpenClaw 听不懂问题，而是：

- OpenClaw 已经能较稳定识别对象和意图
- 但在第一次形成可执行查询时，没有同时拿到足够强的“可达路径知识”
- 结果就是它会在后续推理里反复试探对象下钻路径
- 表现出来就是：
  - 明明理解了“要查谁”
  - 但不能第一时间给出最优 `groups/path`
  - 进而导致回复变慢、续钻不稳、容易出现重复推理

本次落地的是此前确认的方案 A：

- 给 OpenClaw 主链到 Skill 之间补一层轻量“路径预判器”
- 让 OpenClaw 在第一次调用 Skill 前，就先拿到候选路径和首选路径
- 但不把插件重新做成完整语义理解层

## 3. 做了什么

### 3.1 插件侧动态接入 `GroupPathPlannerService`

插件现在会根据 `NAPM_SKILL_EXECUTOR` 动态推导 skill 工作区，并尝试加载：

- `skills/openclaw-napm-query/services/GroupPathPlannerService.js`

这样可以同时兼容：

- 本地仓库测试
- 本地镜像 `.codex-temp`
- 远端 `~/.openclaw/extensions/napm-openclaw-plugin/index.js`

同时补了 `.env` 自动加载，避免插件直接调用路径规划器时拿不到 `NETINSIDE_*` 环境。

### 3.2 在 `prepareSkillExecutionArgs()` 前置路径预判

新增逻辑会在下面场景尝试预判路径：

- 上游已经给了对象锚点 `resolvedQuery.groups`
- 或者这是一个续钻型 prompt，且 `sessionState.last_groups` 可用

插件会调用 `GroupPathPlannerService.planPath(...)`，如果命中：

- 补写 `resolvedQuery.groups`
- 补写 `resolvedQuery.pathPlanning`
- 补写 `semanticConstraints.targetObjectType`
- 补写 `resolutionHints.group.type`

新增字段来源标记：

- `pathPlanning.preflightSource = 'napm_openclaw_plugin'`
- `resolutionHints.group.source = 'plugin_path_preflight'`

### 3.3 保持边界，不扩散职责

本次明确没有做这些事：

- 没有修改企业微信插件
- 没有把插件变成新的业务语义理解层
- 没有让插件从裸 prompt 自行发明对象和业务意图
- 没有移除 Skill 原有的 session continuation / static path planning / fallback

也就是说，本次只做：

- “已有对象锚点时，尽早把路径知识补上”

而不是：

- “插件完全代替 OpenClaw 进行对象理解”

## 4. 为什么这次能改善当前问题

本次改动针对的正是当前主因：

- OpenClaw 已经知道“查哪个对象”
- 但第一次下发时没拿到足够强的路径候选

现在变成：

1. OpenClaw 先给出对象锚点或续钻意图
2. 插件在进入 Skill 前先跑一次静态路径预判
3. Skill 第一次收到的 `resolvedQuery` 就更接近最终可执行路径
4. 从而减少后续反复试探和慢推理

这能明显改善：

- `BusinessGroup -> Applications -> DefinedApp`
- `WebApplication -> PageFamilies -> PageFamily`
- 其他已被静态 groups tree 描述过的标准下钻链路

## 5. 当前仍然不是万能修复

这次方案主要解决“路径选不准”的问题。

它不能单独解决：

- 指标选错
- 排序指标选错
- overview scene 选错
- 复合分析策略选错
- 上游根本没有产出对象锚点的情况

所以这次属于：

- 对当前主痛点的有效修复
- 但不是对所有 NAPM 语义问题的一次性总修

## 9. 结论

本次方案 A 已经以最小侵入方式落地：

- 不改企业微信插件
- 不推翻现有 Skill 主执行链
- 只把“路径知识”前置到 OpenClaw 调 Skill 之前

对于当前“理解没问题，但第一时间找不到正确路径，导致反复试探和变慢”的问题，这次改动是有效且对症的。
