## 页面访问详情查询能力实施

- 在 `codex/napm-turn-decision-phase1` 实现共享 `NapmPageViewsContract` 和 Query Skill 专用 `PageViewsExecutionKernel`，新增 `pageViews/detail` resolution、校验、执行、结果归一化、叙述和错误分类。
- `QueryTurnCoordinator` 保存最小 `PageFamily` 排行投影并按新轮次冻结来源结果集；`resultReference` 按 conversation scope、对象类型、序号和 30 分钟 TTL 校验，显式 `resultSetId` 也不能绕过冻结来源。
- Hook 和直接 Tool execute 都在时间物化与 Skill 执行前解析页面结果引用；非法引用、非法时间、`PageFamilyDetail` group、缺失 ID 或非法 limit 均保证零 Query Skill、零 `NapmClient`、零南向调用。
- Coordinator 通过插件从 `OPENCLAW_SKILLS_ROOT` 注入页面族 ID 解析器，保持独立 extension 目录不携带 partial Skill tree 的安装契约。
- Packet Analysis 改用共享请求和详情归一化，不再发送 `maxLimit=undefined`；Fault Diagnosis 生产入口统一默认 limit，并按规范化 `httpStatus/http400S/http500S` 判断 4xx/5xx。
- 当前本地缺省 `maxLimit=20`，保护上限 200；200 不是已确认的上游正式限制，分页和正式最大值仍待权威接口证据。
- 最终本地门禁：`npm test -- --runInBand` 共 108 个 test suites、955 项测试全部通过；`npm run lint`、`npm run verify:runtime-contract`、`git diff --check` 和 Query Skill UTF-8 结构校验全部通过。
