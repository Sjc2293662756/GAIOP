# 2026-07-01

## 综述报告整体综述追问问题修复

- 问题现象：用户提出“应用整体的综述报告”“业务整体的综述报告”时，观枢AI 没有直接走 `napm-summary` 的 overview 模式，而是继续追问具体对象名称。
- 根因：`skills/openclaw-napm-summary/SKILL.md` 仍沿用旧契约，写成 `webApplication` / `application` / `businessGroup` / `network` 必须带 `target`，与当前插件路由和 `SummaryService` 实际支持的“无 target 整体综述”不一致。
- 真实实现现状：`SummaryService.plan()` 已按 `scope.target` 是否存在自动切换 overview 模式和 target 模式；插件系统上下文也已明确“未指定 target 时省略 `scope.target`，生成整体维度综述”。
- 已修复：
  - 更新 `skills/openclaw-napm-summary/SKILL.md`
  - 明确 `scope.target` 为可选
  - 补充“业务整体综述 / 应用整体综述 / 网络整体综述 / 业务组整体综述”说明
  - 增加 overview 模式 CLI 示例
  - 新增 `docs/2026-07-01-综述报告整体综述追问问题修复说明.md`
- 维护结论：后续遇到“业务整体综述”“应用整体综述”这类请求，不应再追问 target，应直接走 `scope.type=webApplication|application` 且省略 `scope.target`。
