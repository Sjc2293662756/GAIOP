# 2026-08-30

## NAPM 查询轮次统一决策与澄清机制

- 根因：`napm-skill-query` 适配器把缺少具体应用名的正常澄清记录为 `ok=false/error`，`before_tool_call` 又提前阻断 Tool；输出 Hook 因没有可验证 Skill 结果，把模型的正确追问覆盖成 generic guard。
- 新增 `QueryDecisionPolicy`：统一输出 `ASK_CLARIFYING_QUESTION`、`EXECUTE_QUERY`、`REJECT_QUERY`，复用 Resolution Spec 参数策略。
- 新增 `QueryTurnCoordinator`：以 `conversationKey + turnId` 保存 route、phase、action、outcome 和交付声明；Query Skill 保持无状态。
- `napm-skill-query` Tool 现接受 `queryDraft`，迁移期兼容 `resolvedQuery`。澄清返回 `ok=true`、`isError=false`、无 `error`，且不调用 Query Skill 或南向接口。
- “应用流量趋势”不得降级为 `TotalTraffic`；缺应用名时追问具体应用。明确总流量问题仍使用 `TotalTraffic`。
- `before_message_write` 与 `message_sending` 读取同一 Query Turn 终态，避免 generic guard 覆盖并保证同轮只交付一次。
- 用户在下一轮补充应用名（例如 `HTTP`）时，由 OpenClaw 构造新的完整 Query Draft，再进入正常执行；Skill 不恢复会话。
