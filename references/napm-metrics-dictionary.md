# NetInside NAPM 当前系统指标字典

本文档定义当前系统 107 个指标的名称、代码、单位、分类和主要业务含义，并说明各类指标的角色、方向和使用边界。对于未明确公开精确算法的指标，只解释其业务用途和分析方向，不额外假设底层计算公式。

## 1. 指标解释基础

### 1.1 客户端与服务器

NAPM 的应用性能指标基于 TCP 交互计算。

- **客户端**：在一次 TCP 交互中发送数据请求的 IP。系统名称中带“客户端”的指标，也可理解为“发送请求方”指标。
- **服务器**：在一次 TCP 交互中接收并处理数据请求、随后返回响应数据的 IP。系统名称中带“服务器”的指标，也可理解为“接收并处理请求方”指标。
- 同一个 IP 或业务组在不同连接中可以同时承担客户端和服务器角色。例如 Web 服务器接收浏览器请求时是服务器，访问数据库时又是客户端。

在这套指标命名中，`I`、`O` 常用于区分接收/发送或服务器/客户端口径，但不能脱离指标名称单独判断。解释指标时应以系统中文名称为主，再结合所查询对象、分组方向和内部地址列表判断角色。

### 1.2 TCP 客户端与 TCP 服务器

TCP 角色由三次握手确定：

- **TCP 客户端**：发送第一个 SYN、主动发起连接的一方。
- **TCP 服务器**：接收 SYN，并通常在监听端口上响应连接请求的一方。

TCP 客户端/服务器是连接层角色；应用客户端/服务器是请求—响应交互中的角色。两者多数情况下相同，但不能简单视为完全等价。

### 1.3 TCP 连接与 TCP 交互

- **TCP 连接**：从三次握手开始，到连接关闭为止的一条 TCP 会话。一个连接中可以包含多个应用请求—响应交互。
- **TCP 交互**：一个完整的数据请求—响应周期。请求是客户端发往服务器的非零载荷数据，响应是服务器返回给客户端的非零载荷数据。
- 纯 ACK、SYN、FIN 等零载荷控制报文通常不用于判定交互边界，但在部分连接或网络指标计算中仍会参与统计。
- NAPM 根据 TCP 载荷及请求—响应方向识别交互。一个连接可以包含多个交互，纯控制报文不应被当作完整业务交互。

### 1.4 流入与流出

“流入/流出”在不同类别中有两种含义。

**流量、吞吐量、包量和利用率指标：**

- 流入：被查询分组是流量目的地，即流量发送到该分组。
- 流出：被查询分组是流量源，即流量从该分组发出。

**RTT、丢包、重传时延等网络性能指标：**

- 流入：被关注分组与采集设备之间的网络段。
- 流出：采集设备与连接分组之间的网络段。

因此，网络性能指标中的流入/流出不一定等于客户端到服务器/服务器到客户端，也不一定等于物理接口的收包/发包方向。

### 1.5 内部地址列表对方向和角色的影响

应用、总流量、VLAN、监控接口组等对象可能依赖内部地址列表识别服务器角色和流量方向。内部地址列表应包含所有应用服务器 IP。服务器 IP 未被正确纳入时，可能导致：

- 客户端和服务器角色颠倒；
- 流入和流出方向颠倒；
- 服务器侧指标被计入客户端侧，或客户端侧指标被计入服务器侧。

### 1.6 时间指标组成

**服务器响应时间**测量服务器处理请求并开始响应的速度：

- 开始：客户端初始请求的最后一个报文；
- 结束：服务器初始响应的第一个报文。

**用户体验时间**评估客户端从请求数据到完整收到所请求载荷的平均耗时，其组成关系为：

```text
用户体验时间 = 连接建立时间 + 服务器响应时间 + 载荷传输时间 + 重传时延
```

各组成项先按时间窗口计算平均值，再相加得到该时间窗口内的用户体验时间。

### 1.7 单位说明

- 时间类指标在接口中可能以通用时间单位返回。页面延时、连接时长、传输时间和用户体验时间通常按秒级展示；连接建立、服务器响应、首字节、RTT 和重传时延通常按毫秒级展示。实际使用时以接口返回的单位字段或系统界面单位为准。
- 数据量类指标在接口中可能以通用数据单位返回，系统可按 B、KB、MB 等形式展示。不要仅凭代码固定换算单位。
- `千比特/秒（kbps）`：吞吐、有效吞吐、重传数据速率。
- `个`：连接、交互、页面、响应、数据包等数量。
- `个/秒`、`个/分钟`：单位时间内的事件或对象数量。
- `%`：比例或百分比。

### 1.8 时间聚合

系统以 1 分钟为基础粒度保存指标，并可逐级聚合为 5 分钟、1 小时和 1 天。时间类指标通常表示该时间窗口内相关连接或交互的平均值；数量类指标表示该窗口内统计到的数量或聚合数量。长连接跨越多个时间窗口时，连接时长、数据传输、载荷等指标会按连接和交互持续计算，重传时延会按每分钟窗口记录。

## 4. 指标之间的关键关系

### 4.1 页面访问数与 HTTP 响应数

- `PGNPGE` 表示页面访问次数。
- `PGNOBJE` 表示 HTTP 响应对象数量。
- 一个页面通常包含 HTML、JavaScript、CSS、图片和接口等多个对象，因此 `PGNOBJE` 通常大于 `PGNPGE`。

### 4.2 数量、速率和百分比

- 数量指标表示一个时间范围内发生了多少次，例如 `CONI`、`PGHTTP500`、`TRNI`。
- 速率指标表示单位时间发生多少次，例如 `FILI`、`PGSLRT`、`TRRI`。
- 百分比指标表示某类事件在总体中的占比，例如 `PGHTTP500PCT`、`PGSLPCT`、`PLI`。

### 4.3 流量、吞吐量和有效吞吐

- `BYTI/BYTO/BYTIO`：累计传输了多少数据。
- `TPI/TPO/TPIO`：单位时间内传输了多快。
- `GPI/GPO`：系统认定的有效数据吞吐速率，用于与总吞吐量对比。
- `RTXI/RTXO`：单位时间内有多少带宽被重传数据占用。

### 4.4 连接请求、连接和连接失败

- `CONI/CONO`：连接请求总数，主要基于 SYN。
- `FILI/FILO`：连接请求每秒速率。
- `CCNI/CCNO`：统计到的 TCP 连接数。
- `CRTI/CRTO`：TCP 连接活动速率，用于观察单位时间内连接形成或统计规模。
- `RFCI/RFCO`：连接失败总数。
- `RFRI/RFRO`：连接失败每秒速率。

### 4.5 响应时间与用户体验时间

- `TRTI/TRTO`：服务器处理请求并开始返回响应的时间。
- `PTTI/PTTO`：响应有效载荷完成传输的时间。
- `RDTI/RDTO`：重传造成的附加等待时间。
- `UEII/UEIO`：上述过程与连接建立时间共同构成的综合体验时间。

### 4.6 RTT、丢包和重传

- RTT 高：网络基础时延较高。
- 丢包高：链路中存在较明显的数据包缺失。
- 重传高：TCP 为恢复丢失或未确认数据进行了重复发送。
- 重传时延高：重传已经明显拉长业务交互时间。

这四类指标需要联合判断。只有重传较高而业务时延没有升高时，影响可能有限；重传、丢包和重传时延同时升高时，通常说明网络质量已经影响业务体验。
